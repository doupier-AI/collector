# #122 研究学习文档解析基准原型

> **PROTOTYPE — 一次性证据资产，不合入 `master`，不代表正式解析能力。**

## 这个原型回答什么

哪一套最小但有代表性的公开或可控样本文档与人工金标准，足以让用户比较解析候选对论文、教材和技术报告的真实阅读、导航与引用价值，而不是只比较“有没有导出 Markdown”？

当前答案仍是 **7 份文件**，但正向样本不再是短小演示稿：3 份核心研究材料和 1 份 DOCX 办公回归都包含足以暴露顺序、结构、定位与诚实降级问题的长距离对象；另外 3 份只测试稳定失败。

## 直接体验

双击打开：

- `document-parsing-gold-set-122.prototype.html`

页面完全离线、无服务、无联网、无持久化。它包含：

- 7 份样本的本地打开入口；
- “整份文档研究价值”与“对象级诊断锚点”两层人工评分；
- 通过 / 部分 / 失败的逐项选择和两层独立得分；
- 四个引导场景：完整成功、文本提取基线、漂亮 Markdown 丢锚点、混合扫描页伪造；
- 总分、核心材料下限、核心研究价值下限和致命违规四道透明门槛；
- 每次操作后的完整内存状态。

每个关键风险仍只有一个主要承载样本。TXT、Markdown 和更多普通办公文档会重复已经成熟的纯文本路径，因此不加入这套最小基准。

## 双层人工金标准

完整机器可读定义位于 `gold/gold-set.json`，schema 版本为 2。

### 第一层：整份文档研究价值

每份样本固定检查 4 件事：

1. **内容完整性**：关键论证、结论、限制和来源没有静默丢失；
2. **可导航阅读**：标题、章节、页序和栏序足以连续阅读；
3. **引用可复核**：从解析结果可以稳定返回原页、原区域或原文档对象；
4. **诚实降级**：不支持的结构、扫描页或失败类型被明确说明，不伪装成完整成功。

### 第二层：对象级诊断锚点

金标准为每份文件记录可逐个核对的对象，包括：

- 精确正文短语、标题层级和阅读顺序；
- 页码、左/右栏、上/中/下区域或 DOCX 块定位；
- 表格尺寸、表头、合并关系、续表关系和指定单元格；
- 公式的可读表达与编号；
- 图片资源、图注、交叉引用和替代文字；
- 真脚注、页眉、页码字段与扫描页是否有文本层；
- 负例允许的稳定失败分类、实际文件大小和零伪造约束。

7 份样本的锚点数依次为 `8 / 8 / 9 / 8 / 4 / 4 / 4`；每个机器 Gold 锚点都使用与交互页相同的 `*-aN` ID、顺序和复核语义。三份负例依次检查正文、结构、定位和错误（超限负例第一项为前置限制）；正例的多对象检查则把标题—正文、图—图注、公式—变量、表—行列、来源—修改声明等关系写入 `structureExpectation`，避免页面评分与机器金标错位。

两层候选组合权重为：**整份文档 60% + 对象锚点 40%**。这个比例只是为了让原型可操作，仍等待用户裁决，不是产品基线。

混合报告的两张纯图扫描页带有独立的待裁决依赖：**准确 OCR 且标明 OCR 来源与不确定性可以通过；只有页图和“无原生文字层”声明、但没有 OCR 时，不能自动记通过，究竟记部分还是失败仍由用户裁决。** 两页分别提供只用于 OCR 核验的 `ocrReferenceText`，生成器会先确认参考短语真实存在于对应 NIST 来源页；它不会冒充输出 PDF 的原生 `exactText`。`gold-set.json` 将该样本标为 `decision-dependent`，不预判无 OCR 是部分还是失败。

NIST 锚点同时记录 `sourcePdfPage` 与 `sourcePrintedPage`：前者是从 1 开始的 PDF 物理页序，用于程序回源；后者是页面内印刷页码，用于人工复核。两者不能混用。

## 裁决门槛

样本组权重保持：核心研究材料 70%，DOCX 回归 10%，负例 20%。

- **成功**：全部检查完成；总分 ≥ 85；三份核心材料组合分各 ≥ 75；三份核心材料的整篇研究价值各 ≥ 80；零致命违规。
- **部分成功**：总分 50–84，或任一核心门槛未过，但没有致命违规且降级明确。
- **失败**：总分 < 50，或发生任一致命违规。

致命违规包括：伪造文字、声称精确但无法回读的定位、把负例报告为干净成功、静默丢内容。它们不能被其他高分平均掉。

## 公开来源与许可

来源清单位于 `sources/manifest.json`，固定落地页、直接下载地址、许可依据、署名、下载日期、页数、字节数和 SHA-256。

- **英文论文**：Ali Tivay、Xin Jin、Alex Kai-Yuan Lo、Christopher G. Scully、Jin-Oh Hahn，*Practical Use of Regularization in Individualizing a Mathematical Model of Cardiovascular Hemodynamics Using Scarce Data*，Frontiers in Physiology 11:452 (2020)，DOI `10.3389/fphys.2020.00452`。文章页与 PDF 均声明 [CC BY 4.0](https://www.frontiersin.org/journals/physiology/articles/10.3389/fphys.2020.00452/full)。输出保留原文署名、期刊、DOI 和许可声明。
- **技术报告底稿**：Elham Tabassi，*Artificial Intelligence Risk Management Framework (AI RMF 1.0)*，NIST AI 100-1 (2023)，DOI `10.6028/NIST.AI.100-1`。[NIST Technical Series 复用说明](https://www.nist.gov/open/copyright-fair-use-and-licensing-statements-srd-data-software-and-technical-series-publications)授予全球再版与衍生权，并要求推荐引用后紧跟 `Republished courtesy of the National Institute of Standards and Technology.`；衍生稿按此顺序保留署名和致谢，同时写明 `2026-08-24` 修改日期、选页重排/扫描化/新增四页原创框架的修改性质，以及无背书声明。

“能免费下载”不等于“能进入仓库或制作衍生品”。例如带 `ND` 条款的中文开放图书没有纳入本原型。

## 重新生成

先从 Codex workspace dependency loader 取得 bundled Python 路径，再在本目录运行：

```powershell
& '<workspace-python>' download-sources.py
& '<workspace-python>' generate-fixtures.py
```

`download-sources.py` 只下载缺失或指纹不一致的两个公开来源；下载过程中以清单里的精确字节数为上限，完成后再验证页数、字节数和 SHA-256。来源缓存位于 `sources/cache/`，不提交。仓库保存 6 个非填充样本与人工金标准；第 7 个超长负例由生成器按需产生。

生成器同时检查：

- 中文教材、英文论文和混合技术报告的固定页数，以及中文每页最低文字密度和内容唯一性；
- 混合报告第 6、12 页没有原生文字层，其他 14 页仍有文字层；来源页映射、NIST 缓存哈希与 gold 一致，选中页面不含 `OECD`、`adapted from` 或 `copyright` 标记；
- gold 中所有正例精确文字锚点真实存在于指定 PDF 页或 DOCX XML；
- DOCX 的真实标题层级、两级编号、精确表格网格、合并单元格、重复表头、32 条独立记录、图片、替代文字、脚注和页码字段；
- 加密 PDF 是确定性 AES-256-R5 负例，并可用审阅密码解密；
- 超长负例恰好是 20 MiB + 1 字节；
- 7 个样本角色、权重、路径和两层检查均写入 `gold/gold-set.json`。

在本项目支持的 Windows 生成环境中，连续两次生成的 7 个样本和 gold SHA-256 完全一致。中文与 DOCX 会调用系统字体，因此这里不宣称任意操作系统之间都能逐字节相同。

`negative-oversized.pdf` 由 `.gitignore` 排除，因为它只是固定填充物；交互页会如实显示“运行生成器产生”，不会提供不存在的远程文件链接。

## 现行能力与原型边界

当前 Collector 已支持 TXT / Markdown / DOCX / 文本型 PDF 导入，并为 PDF 保留页码锚点、为 DOCX 保留段落/标题/块类型锚点；当前不支持扫描 PDF / OCR / 图片提取，也不复原 PDF 版式。

因此：

- 双栏区域、单元格、公式、图片资源、OCR、真脚注和 Word 合并关系是**比较解析候选的金标准**，不是当前产品承诺；
- 原型不修改生产解析器、共享契约、数据库、HTTP 接口或 WebUI；
- 原型不决定未来解析供应商、实现方式、性能预算或文件大小上限；
- 扫描页没有 OCR 时应算部分成功还是直接失败，仍等待用户看过新样本后裁决。

## 用户需要确认的三件事

1. 这 3 份核心材料现在是否足够像真实会阅读和引用的教材、论文与技术报告？
2. “整份文档 60% + 对象锚点 40%”是否符合研究优先级，还是对象证据应该更重？
3. 对混合报告的无文本层扫描页，明确显示“无法 OCR”能否算部分成功，还是必须直接失败？
