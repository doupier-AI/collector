# #122 研究学习文档解析基准原型

> **PROTOTYPE — 一次性证据资产，不合入 `master`，不代表正式解析能力。**

## 这个原型回答什么

哪一套最小但有代表性的匿名/公开样本文档和人工金标准，足以让用户真实比较解析候选对论文、教材与技术报告的阅读和引用价值，而不是只比较“有没有导出 Markdown”？

本原型把答案收敛为 **7 份文件**：3 份核心研究材料、1 份 DOCX 办公回归、3 份负例。每个关键风险只设一个主要承载样本，避免为“数量好看”重复堆材料。

## 直接体验

双击打开：

- `document-parsing-gold-set-122.prototype.html`

页面完全离线、无服务、无联网、无持久化。它包含：

- 7 份样本的本地打开入口；
- 六维人工金标准；
- 通过 / 部分 / 失败的逐项评分；
- 四个引导场景：完整成功、文本提取基线、只有 Markdown、伪造式 OCR；
- 总分、核心材料下限和致命违规三道裁决门槛；
- 每次操作后的完整内存状态。

## 最小样本矩阵

| 样本 | 角色 | 主要覆盖 | 不重复承担什么 |
| --- | --- | --- | --- |
| 中文单栏教材式 PDF | 核心研究 | 中文可复制正文、标题层级、表格、公式、脚注、图片、参考文献、页区定位 | 不承担双栏顺序与 OCR |
| 英文双栏论文式 PDF | 核心研究 | 英文、双栏阅读顺序、表格、公式、脚注、图片、参考文献、左右栏区域 | 不承担中文与扫描 |
| 扫描实验记录 PDF | 核心研究 | 纯图片页、OCR、页区锚点、原始页图、图像内网格 | 不重复测试文本层 |
| DOCX 办公回归 | 回归 | Heading 1/2、段落、4×3 表格、图片、分页、参考文献 | 不用于证明研究材料代表性 |
| 损坏 PDF | 负例 | 损坏分类、零伪造 | 不评分版式质量 |
| 加密 PDF | 负例 | `password_required` / `encrypted` 分类、零伪造 | 不测试密码管理产品流程 |
| 20 MiB + 1 B PDF（按需生成，不提交填充物） | 负例 | 解析前大小拒绝、实际大小与上限说明 | 不测试超大文件解析性能 |

完整人工金标准位于 `gold/gold-set.json`。它明确记录：

- 阅读顺序与标题层级；
- 页码和区域；
- 表格单元格矩阵；
- 公式可读表达；
- 图片资源、图注与所在页；
- 可读正文关键锚点；
- 负例允许的稳定失败分类。

## 评分与分类

每份样本都使用同一组六维检查点：

| 维度 | 权重 |
| --- | ---: |
| 可读正文 | 25 |
| 阅读顺序与标题层级 | 20 |
| 页码与区域定位 | 20 |
| 表格与公式结构 | 15 |
| 图片资源与图注 | 10 |
| 失败分类与诚实降级 | 10 |

样本组权重：核心研究材料 70%，DOCX 回归 10%，负例 20%。

- **成功**：总分 ≥ 85；三份核心研究材料各自 ≥ 75；零致命违规。
- **部分成功**：总分 50–84，或存在非致命结构缺失但降级明确。
- **失败**：总分 < 50，或发生任一致命违规。

致命违规包括：伪造文字、声称精确但实际不可回读的定位、把负例报告为干净成功、静默丢内容。它们不能被其他高分平均掉。

## 重新生成样本

生成器只使用匿名合成内容，不读取仓库外的用户文件，也不联网。它通过 Codex 文档/PDF 工作区运行时生成 PDF 与 DOCX：

```powershell
& '<workspace-python>' generate-fixtures.py
```

`<workspace-python>` 由 Codex 的 workspace dependency loader 返回。生成器会同时执行结构自检：

- 中文与英文 PDF 均为 3 页；
- 扫描 PDF 为 2 页且没有文本层；
- 加密 PDF 可用审阅密码 `collector-122` 解密；
- 超长负例恰好为 20 MiB + 1 字节；
- 7 份样本与 `gold/gold-set.json` 的路径全部存在。

生成器产生的 `negative-oversized.pdf` 恰好为 20 MiB + 1 字节，但 `.gitignore` 不提交这段无阅读价值的固定填充；远程分支保留生成器、金标准路径和精确字节断言。交互报告也把它标记为“运行生成器产生”，不提供一个必然不存在的远程下载链接。

## 已知现行能力与原型边界

当前 Collector 已支持 TXT / Markdown / DOCX / 文本型 PDF 导入，并为 PDF 保留页码锚点、为 DOCX 保留段落/标题/块类型锚点；当前不支持扫描 PDF / OCR / 图片提取，也不复原 PDF 版式。因此：

- 原型中的“双栏区域、表格单元格、公式、图片资源、OCR”是**用于比较候选的金标准**，不是当前产品承诺；
- 原型不修改生产解析器、共享契约、数据库、HTTP 接口或 WebUI；
- 原型不决定未来解析供应商、实现方式、性能预算或文件大小上限；
- 评分权重与扫描页的“部分成功还是直接失败”仍等待用户查看样本后裁决。

## 用户需要确认的三件事

1. 这三份核心材料是否像你真实会读的论文、教材与技术报告？
2. 六维检查点和 70/10/20 权重是否符合你对“研究价值”的优先级？
3. 扫描页没有 OCR 时，明确显示“无文本层”的部分成功是否可接受，还是必须直接失败？
