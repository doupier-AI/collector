# 实现一次可恢复的近期整理最小路径

Status: ready-for-agent
Category: enhancement
Type: HITL
Resolution: open

## Parent

[`../PRD.md`](../PRD.md)

## What to build

在“近期收集”提供一个最小但真实的“立即整理”路径：用户触发后，系统冻结当前有效材料集合，创建持久化工作流，完成本地去重，并发布一个暂时把剩余材料列为“未归类”的近期快照。该版本不调用云模型，但完整贯通 SQLite、执行器、API/IPC 和用户可见状态。

应用在步骤间退出后必须能从最后一个已完成步骤恢复。该切片用真实用户动作证明工作流基础，而不是单独交付一套没有产品路径的任务框架。模型调用表和 Fake Provider 可以作为后续扩展测试接口，但本次用户结果不伪造 AI 分组。

## PRD acceptance path

- 场景 B：步骤 1、3，触发批量整理并安全保留尚未归类的材料。
- 场景 E：步骤 2，工作流失败不影响原始材料和上一成功快照。

## Acceptance criteria

- [ ] `WorkflowRun`、`WorkflowStep` 和 `ModelCall` 使用 SQLite 正式表及 migration 持久化。
- [ ] 用户可从近期收集页面触发“立即整理”，并看到排队、处理中、完成或失败状态。
- [ ] 工作流冻结当前有效材料，完成本地精确去重后发布 `RecentClusterSnapshot`。
- [ ] 首个快照允许没有 AI 分组，非重复材料明确进入未归类集合。
- [ ] 相同类型、幂等键和输入版本不会创建两个有效运行。
- [ ] 执行器通过原子状态转换和租约领取任务，两个实例不能同时执行同一步骤。
- [ ] 每一步输出与状态推进在同一事务中提交。
- [ ] 应用在某一步完成后退出，重启可继续后续步骤而不重复发布输出。
- [ ] 失败不会删除材料或覆盖上一成功快照，用户可以重新触发。
- [ ] 受保护 API/IPC 可读取当前运行和快照，普通界面不暴露内部 step 名称。
- [ ] 测试覆盖成功、恢复、幂等、租约到期、取消和失败隔离。
- [ ] 现有采集与 GUI smoke 继续通过。
