# 人类拟真验收

本流程验证普通用户能否自然完成目标，与组件、集成和 Playwright 自动化分工。它是低频体验验收，不因单个开发任务、Issue 关闭或普通“运行测试”自动触发。

## 触发

只有用户主动使用下列意图时执行：

- “进行一次人类拟真测试”：覆盖当前版本变化及一条最短稳定路径；
- “进行一次人类拟真测试：某模块或功能”：只覆盖指定范围与必要前置；
- “进行一次全量人类拟真测试”：覆盖全部现役产品模块。

没有触发时，按 `docs/ENGINEERING.md` 执行自动化验证即可。

## 准备

1. 固定受测提交、工作树、启动方式、数据目录和端口。
2. 读取涉及的产品模块契约，并从代码、测试和实际界面确认现有入口；不使用历史步骤推断当前功能。
3. 明确纳入、排除、预制数据、预计时长、保存内容和清理方式。
4. 使用确定性演示轨道检查交互与恢复；只有范围涉及真实回答质量、模型恢复或真实联网时才使用真实模型轨道。
5. 真实模型配置来自本机安全存储；凭证不进入截图、日志、报告或对话。

## 执行

- 以第一次使用 Collector 的用户视角从界面发现入口，不机械复刻自动化脚本。
- 每一步只做一个主要动作，并记录肉眼可判断的预期和实际结果。
- 覆盖范围需要的宽屏、窄屏、键盘、焦点、读屏、减少动态效果、刷新和重启恢复。
- 全程观察控制台错误、失败请求、重复请求、页面卡顿、状态不明和数据丢失。
- 分别评价美观、舒适和完整性；主观建议与产品缺陷分开。
- 使用预制或隔离数据。私人内容只保留判断所需的最小截图并遮盖敏感信息。
- 不绕过登录、付费墙、反爬或访问限制。

以下情况立即停止当前路径并保留现场：出现未说明的密钥或验证码要求、删除或公开真实数据的风险、产品契约不足以判断、应用连续失败，或下一步安全条件不明确。

## 复核与报告

原始问题在进入修复前由独立上下文按相同提交和步骤复跑，归为：确认成立、预期行为、无法复现、待用户定夺。只有确认成立且有产品或实现依据的条目进入实施任务。

报告只包含：受测提交与范围、运行轨道、确认问题与证据、美观/舒适/完整评价、被筛除条目、控制台与网络异常、未覆盖范围和清理结果。不维护跨版本人工进度基线；历史报告由任务记录或 Git 保存。
