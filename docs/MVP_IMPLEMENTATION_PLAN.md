最后更新：2026-07-30

本文件是核心闭环的当前实施计划，按完成的切片同步更新。产品定义与验收标准以 `PRODUCT.md` 为准；已经发生的阶段事实、验证证据和遗留限制记录于 `PROJECT_DEVELOPMENT_RECORD.md`，本文件只保留计划与状态。

## 目标

连通下划线处的核心闭环，全部连通并通过四场景端到端验收后，才记录"核心流程 MVP 可体验"：

```text
阅读当前内容 → 手动选区 → 选区质量提示 → 选区智能窗口
→ 深入研究 / 稍后再学 → 保留来源关系 → 返回原内容和原选区
```

核心流程 MVP 可体验已于 2026-07-21 生效。当前并行推进两个方向：阶段 E（可信研究能力，代码已完成待真实验收）和阶段 F（联网搜索策略改进，已完成）。阶段 H（统一研究节点树与弱标记生长）已于 2026-07-30 启动：H1（节点数据模型归并与迁移）、H2（节点页统一与全屏树导航）已完成；H3a（术语检测与弱标记数据）、H4a（选区引用胶囊与双模发送）、H5a（父链上下文组装）于 2026-07-30 并行完成。

## 关键设计决策

1. **统一选区锚点（三层）**：契约包 `deriveMessageBlocks()` 是前后端唯一的段落切分实现；锚点统一两种内容来源——消息块 `{ messageId, blockOrdinal, startOffset, endOffset, exact, prefix?, suffix? }` 与快照块 `{ contentSnapshotId, blockId, ... }`。服务端校验 `exact` 与块文本切片一致，失败时用 prefix/suffix 自愈重定位，再失败转 stale：保留原文与粗粒度位置，不删除记录。
2. **选区分析 = 异步任务 + SSE**：镜像导入管线。创建同步返回（窗口立即有原文与操作区），分析异步执行，事件只有 snapshot / completed / failed；逐字段流式属可延后增强。
3. **AI 输出一次完整 JSON**：网关 `analyzeSelection()` 返回校验过的 insight；必需字段缺失即 `invalid_analysis` 可重试失败；可选字段 `relationToFocus` 缺失合法。不静默降级为假数据。
4. **深入研究第一轮材料范围**：来源内容与选区上下文始终进入研究提示；用户主动发起的 Chat / 研究会话 / 分支追问默认不请求联网，仅在用户打开输入框联网开关时请求供应商联网能力；其他 AI 生成场景（如文档生成、整理、节点命名等）由模型按任务类型自行判断是否需要联网。选区分析不联网；供应商失败、不支持或没有可核验来源时，以消息级状态说明降级，不呈现引用。
5. **节点呈现（H2 起）**：统一节点页 `/research/:sessionId/node/:nodeId`，顶部来源条；消息归属以 `nodeId` 为准，旧 `ResearchMessageRecord.branchId` 继续双写保留，旧会话/分支路由重定向到节点页并保留 `?sel=`。
6. **事件流客户端同构复制**：选区事件流复制任务 / 导入事件流的既有模式，不强行合并三条客户端，避免无关 diff。
7. **搜索由模型供应商能力提供，用户主动场景默认关闭（阶段 E）**：联网搜索不引入独立的适配层或搜索凭证，由当前 AI 模型供应商的能力（如 OpenAI `web_search`、Gemini grounding、Anthropic 后续能力）提供；Collector 在模型网关层按供应商协议解析响应，归一为统一的来源记录与行内引用结构。用户主动发起的对话、研究会话和分支追问在输入框提供联网开关，默认关闭；关闭时不请求供应商联网，开启时才请求。其他 AI 生成场景由任务类型决定是否需要联网。供应商切换与 AI 供应商切换一致；不同供应商的联网能力形式和引用格式各异，归一逻辑集中在网关。
8. **引用以供应商结构化输出为准，且只在用户开启联网开关后呈现（阶段 E）**：引用来源由模型供应商返回的结构化数据驱动，Collector 校验引用的完整性与来源一致性；用户主动场景未开启联网开关时，界面不呈现虚构来源；供应商未返回可核验来源时，界面如实说明本轮未获得可核验引用。
9. **零文本引用标记（阶段 E，E3 预留）**：界面引用标记渲染为 `textContent` 为空的 `<sup data-citation-marker>`，可见编号用 CSS `::after` 绘制，不扰动已验收的选区锚定偏移；选区无扰动由回归测试证明。
10. **搜索改进分三阶段推进（阶段 F）**：第一阶段（F1）不改架构，仅加日志和查询改写，低成本修复 Bing 中文分词偏差问题；第二阶段（F2）把搜索变为 Agent 可多轮调用的独立工具，对标 DeerFlow 的自主搜索体验，采用手写 ReAct 循环（零新增依赖）；第三阶段（F3）增加多后端支持（Bing / DDG / Tavily / SearXNG），通过统一适配器接口和单一规范后端列表管理。三个阶段均已完成，核心架构见 `docs/ARCHITECTURE.md` 联网搜索一节。

### 阶段 E：可信研究能力（已实现，真实供应商验收已停止）

当前规则（待调整）：Chat、深入研究第一轮和分支追问自动请求当前模型供应商的联网能力；选区分析始终不联网；v1 不提供联网开关或独立搜索凭证。OpenAI Responses `web_search`、Gemini Google Search grounding 与 Anthropic Messages server-side web search/web fetch 都由模型网关归一为 `ResearchGrounding*` 记录。

**产品决策调整（2026-07-30，已确认）**：联网搜索从"强制开启"改为"用户可控、默认关闭"。Chat / 研究会话 / 分支追问的输入框增加联网搜索开关；开关关闭时，这些用户主动发起的生成场景不请求供应商联网能力；其他 AI 生成场景（如文档生成、整理、节点命名等）由模型按任务类型自行判断是否需要联网。选区分析维持始终不联网。Mimo 等模型商自有联网服务需单独确认协议后接入，当前阶段 E 默认适配 OpenAI / Gemini / Anthropic 三家供应商联网能力。

**E1（已弃用，2026-07-22）**：历史方案为 SearXNG 兼容适配层与 v20 轨迹，已在 `39dffe5` 中完全清除；从未合入 `master` 或远端跟踪分支。

**E2（已实现，真实供应商验收已停止）**：共享契约声明供应商联网能力、统一完成状态和安全净化函数；模型网关支持 OpenAI、Gemini 与 Anthropic；当前代码仍把三类研究生成接入自动联网，并在 SQLite v21 保存运行、来源、引用和任务范围摘要。联网失败或供应商不支持时回退普通回答，保留诚实状态与可重试任务。用户可控开关改造作为后续增强，不阻塞当前阶段收尾。

**E3（已实现，真实浏览器验收已停止）**：完成消息按持久化块内偏移插入零文本引用标记，CSS 伪元素绘制稳定编号；主线与分支视图都恢复来源、引用和消息级联网状态；来源预览只使用净化后的外链并提供键盘可达的详情。

**阶段 E 收尾（已停止）**：由于当前已配置供应商均不支持原生联网，且用户决定停止阶段 E 真实供应商验收，阶段 E 不再执行真实环境验收。已完成的自动化测试与代码实现保持有效；用户可控联网开关作为后续增强另行安排。

### 阶段 F：联网搜索策略改进（已完成）

自建搜索（Bing HTML 抓取）原存在三个核心问题：中文分词导致搜索失真、零可观测性、架构僵化。通过三个阶段逐步解决：

**F1（已完成，`68b39be`）**：搜索链路日志 + 查询改写。在 `web-search-agent.ts` 关键节点加日志输出；用当前模型做轻量 query reformulation。

**F2（已完成，`9952a02`）**：web_search/web_fetch 工具拆分 + Agent 多轮工具调用循环。手写 ReAct 循环（零新增依赖），模型可自主搜→看结果→决定抓哪些→信息不够→换词再搜。

**已确认决策：**

1. **节点同构**：`ResearchSessionRecord` 与 `ResearchBranchRecord` 归并为单一节点表（`parentNodeId` 自引用）；根节点来源为一次对话或一篇导入文档；每个节点功能完整（多轮追问、就地追问、生长子节点、稍后再学）。`DeepResearchMode` 二选一退役。数据迁移作为独立提交，四级验证。
2. **双生长**：AI 弱标记点击 / 手动选区 + query 创建子节点；引用选区在当前节点内追问不产生新结构（就地追问）。
3. **弱标记生成一次到位**：不用廉价模型生成与正式内容不一致的预览。悬停约 400ms 判定意图后，开始生成子节点第一轮（模板 query + 术语 + 父链上下文），弹窗流式预览；点击即以该生成作为子节点首条消息；缓存键 = 术语 + 节点，不重复生成；鼠标移开后任务继续跑完。页面切换动画掩盖首字延迟，动画速度可调、以不烦为上限。
4. **内容收敛**：提示词携带节点深度与父链上下文引导深层回答收敛；深度或内容长度超过阈值时，以确定性规则停止打标，不依赖模型自觉。
5. **上下文编排**：沿 `parentNodeId` 向上组装有界的父链上下文（背景主题 + 引用文本），是深层节点回答质量的核心工程，Collector 目前没有这一层。
6. **导航**：MVP 为快捷键唤出的全屏树视图——键盘可达、面包屑路径、兄弟节点并列可跳跃（横向生长由"每个回答多个弱标记出口"自然产生，不需要额外机制）。HUD 沉浸式导航（Pointer Lock + 位移速度模型 + 径向焦点渐变 + 悬停节点放大）为后续实验层，与数据层解耦，手感不对可整体退回。
7. **AI 节点命名**：由按用途路由的便宜模型生成节点名，服务导航显示。
8. **选区窗口简化**：退役 difficulty / quickReadMinutes / deepStudyMinutes 等装饰字段；窗口动作收敛为就地追问、开枝散叶、稍后再学。
9. **不变**：选区锚点与自愈、任务 / SSE / 幂等 / 重启恢复、联网双路径与引用、模型配置与按用途路由、稍后再学、本地优先安全边界。

**切片划分（H1、H2、H3a、H4a、H5a 已完成；其余待实施）**：H1 节点数据模型归并与迁移；H2 节点页统一与全屏树导航；H3 弱标记标记—悬停—子节点闭环（H3a 数据层已完成，H3b 悬停预览与点击生长、渲染层待实施）；H4 就地追问与选区窗口简化（H4a 引用胶囊与双模发送已完成，H4b 用户标记与笔记待实施）；H5 父链上下文编排与内容收敛（H5a 上下文组装已完成，H5b 提示词注入、H5c 内容收敛待实施）；H6 节点命名。HUD 导航另立实验切片。

## 阶段完成标准

### 核心流程 MVP 可体验

满足以下条件后，才使用"核心流程 MVP 可体验"：

- 第 4 节不可缩减闭环全部真实可操作；
- Chat 与文档两个入口至少各通过一条完整的选择—决策—来源返回路径；
- 深入研究和稍后再学都不是占位入口；
- 至少一种真实模型完成回答、选区分析和研究生成验收；
- 真实数据、刷新恢复、失败重试和来源关系一致；
- 自动化测试与实际浏览器验收覆盖第 8 节场景；
- 当前实现状态同步到项目开发记录和相关产品文档，不把待实现增强能力写成已实现。

### 完整 MVP 可对外验收

在核心流程可体验基础上，还需要：

- 按需联网搜索进入真实研究流程；
- AI 的关键事实陈述具有可验证的行内引用和来源返回；
- 稍后再学具备最低可用、可解释的弱重现；
- 本地模型、搜索和错误轨迹可查看或导出；
- 双击启动、关闭、异常恢复和本地安全边界通过实际运行验收；
- 产品共识中其余标记为当前 MVP 的能力，已经实现或经过明确的范围变更确认。

## 主要风险

1. **锚点失效**：AI 消息重试重写内容后旧选区进入 stale，由自愈与粗粒度降级兜底，e2e 覆盖该路径；
2. **块派生前后端漂移**：单实现放契约包，前端禁止另写切分逻辑；
3. **jsdom 选区 API 薄弱**：偏移计算做成 Range-like 纯函数单测，真实选区行为只由 Playwright 断言；
4. **模型无结构化输出**：分析解析失败即任务失败可重试，不静默降级；
5. **branchId 侵入会话视图**：若 C1 复杂度失控，降级预案为两种模式都建带 origin 的独立会话（产品语义变弱，仅作预案）。

## 待确认事项

- 选区智能窗口字段的最终顺序、默认展开层级和首屏信息密度；
- 稍后再学基础闭环需要提供哪些即时用户控制；
- 自动弱重现进入完整 MVP 时的最低触发规则和每日展示上限；
- **课题级 Deep Research（待确认）**：从自由课题发起、多轮生成研究报告的产品入口，需要单独设计报告形态、轮次控制、与现有“深入研究”分支的关系，以及它与 G2c 任务模型分配的组合方式（例如研究任务固定使用强模型配置）。
