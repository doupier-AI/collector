# Collector 技术架构

状态：2026-08-10 本地 WebUI 当前架构。统一研究节点页、选区与显式引用、节点生长、标记与笔记、文件导入与连续阅读、会话内研究地图、三类关系边、正文唯一事实源与派生语义卡片、相似性弱提示、确认式融合（F2/#31）、默认关闭的自动融合（F3/#32）、融合依据回跳、AI 弱标记预览、逐次联网开关、模型设置、运行记录与脱敏导出均已实现。研究地图全局模式、跨会话搜索与新专注查询仍处于产品设计阶段，当前事实与目标差距见 `docs/PROJECT.md` 和 ADR-0022。

## 架构目标

Collector 是单用户、本机运行的 Web 应用。用户通过普通启动器打开 Collector，全部产品界面运行在默认浏览器中；本机服务负责数据、文件、解析、AI、联网搜索和后台任务。

架构优先保障：

- 普通用户双击即可启动；
- Chat、阅读、选区和研究分支在同一 WebUI 中连续使用；
- 页面刷新、浏览器关闭和服务异常后的状态可恢复；
- 私人文件和研究数据保存在本机；
- 产品事件、模型会话和搜索链路在本机形成完整观测轨迹；
- 外部模型与搜索只接收当前操作所需内容；
- 构建、测试、打包和长期维护的复杂度保持可控。

## 运行结构

```mermaid

  USER["用户双击 Collector"] --> LAUNCHER["本地启动器"]
  LAUNCHER --> SERVICE["Collector 本机服务<br/>127.0.0.1:动态端口"]
  LAUNCHER --> BROWSER["默认浏览器"]
  BROWSER --> WEBUI["Collector WebUI"]
  WEBUI <-->|"同源 HTTP / SSE"| SERVICE

  SERVICE --> DOMAIN["研究会话与内容服务"]
  SERVICE --> PARSER["文件解析与阅读快照"]
  SERVICE --> TASKS["AI 与后台任务执行器"]
  SERVICE --> CREDS["凭证边界"]
  WEBUI --> TRACE["本地产品观测与模型会话轨迹"]

  DOMAIN --> SQLITE["SQLite"]
  PARSER --> FILES["导入文件与内容快照"]
  TASKS --> MODELS["外部模型"]
  TASKS --> SEARCH["模型供应商联网能力"]
  TASKS --> TRACE
  TRACE --> SQLITE
```

WebUI 生产构建与 API 由同一个 loopback 地址提供。页面资源、数据请求和流式回答共享一个受控来源，减少端口、CORS 和部署复杂度。前端热更新服务器只用于开发，不属于正式运行依赖。

## 组件职责

### 本地启动器

启动器核心能力已在当前实现中提交并通过主要自动化与浏览器路径验证；运行版本替换、异常退出和无法安全关闭旧实例仍按真实运行状态单独验收。

- 启动或复用 Collector 本机服务；
- 选择可用端口并记录当前实例；
- 确认服务身份、运行版本和健康状态；
- 在默认浏览器打开当前工作区；
- 重复启动时只复用身份与当前构建一致的健康实例；
- 代码更新后，在既有实例支持受控关闭时安全替换为当前版本；
- 协助异常退出后的恢复和日志定位。

启动器使用独占启动锁串行化启动决策。实例文件记录进程、端口、实例 ID 和运行版本指纹；重复启动同时核对实例文件与 `/health` 返回的实例 ID、运行版本。兼容实例继续复用；版本不一致且既有实例支持受控关闭时，启动器通过专用本机控制凭据请求其优雅关闭，确认进程退出后再启动当前版本。更早、不支持受控关闭的服务需要用户先关闭后重试。现有进程仍存活但暂时无法验证或无法受控关闭时，启动器明确停止本次操作，不强行结束进程，也不并行创建第二个服务。

服务在打开业务 SQLite 和文件存储前，通过独立的 SQLite 排他事务取得数据目录生命周期所有权，并持有到优雅退出。直接运行服务、启动器并发或短暂健康检查失败都不能让两个服务同时使用同一份数据；进程异常退出时由操作系统释放事务锁，后续启动不依赖可能已经复用的 PID，也不需要竞态删除普通锁文件。`service.lock` 只保留当前所有者的可诊断信息，不承担互斥正确性。业务 SQLite 与用户文件在服务更换和陈旧实例记录清理时保持不变。

浏览器打开时，启动器用独立本机控制凭据申请一个短时、一次性回环入口。该入口通过 HttpOnly、SameSite=Strict Cookie 建立会话后立即关闭；URL 只包含随机本机端口，不含配对码或令牌。控制凭据保存在独立私有文件，不进入业务表、URL、浏览器存储、实例文件或日志。

启动器只承担运行生命周期，不承载产品界面。

### WebUI

- 最近研究会话、Chat、当前内容、模型设置和运行记录；
- 浏览器文件选择与拖放上传；
- AI 回答和导入文档的连续阅读；
- 选区上方浮动胶囊：显式【引用】后在此追问或深入研究生长节点，或直接【标记】并添加笔记；
- 统一节点页、来源条与来源返回；「研究地图」按钮或快捷键 `t`（专注）/ `g`（关联）打开统一覆盖层，专注模式呈现当前节点的祖先 / 直接子 / 同级脉络与弱化关联区，关联模式呈现桌面网状画布或窄屏关系列表，两种模式共用服务端图投影；
- AI 弱标记的内联渲染、流式预览和点击生长；标记失败不阻塞正文和手动选区；
- 逐次联网开关、行内引用和诚实的未请求 / 不支持 / 失败状态；
- 标记列表、运行记录查看和当前筛选范围的脱敏导出；
- 加载、空状态、恢复状态和错误状态；
- 键盘、焦点、响应式布局、屏幕阅读器语义和减少动态效果。

WebUI 使用 HTTP API 和流式连接，不直接访问 SQLite、文件系统或模型凭证。

### 本机 API 与领域服务

- 研究节点（`research_sessions` / `research_branches` 已于 H1 归并）、类型化边、语义切片、选区和用户标记与笔记；
- 单一图投影：父子边由节点血统确定性派生，语义相关和融合来源边从 `research_edges` 读取；WebUI 的树、画布和关系列表不维护另一份关系数据；
- 正式切片与临时切片：新生成内容使用正式切片，旧消息在需要时按既有消息块边界惰性派生临时切片；
- 切片上下文：当前问题保留为用户消息，历史助手内容按相关性、当前节点、来源选区和父链距离在独立预算内整片装入；
- 文件上传、内容快照、解析状态和来源锚点；
- 模型配置、凭证状态、按任务分配、AI 调用和按需搜索；
- 任务创建、幂等、取消、重试和恢复；
- 本地运行轨迹、筛选读取和脱敏导出；
- 本地会话认证、来源校验和输入边界；
- 数据清理和受控关闭本地服务。

### SQLite 与文件存储

SQLite 保存结构化业务数据、任务状态、配置状态、来源关系、产品事件和模型及搜索轨迹。导入原文件与稳定内容快照使用受控文件目录保存。

数据库与文件记录通过稳定 ID 关联。迁移使用事务和备份；清理操作同步处理数据库、文件、凭证状态和 WebUI 状态。

### 模型与后台任务

后台任务保存实际输入与输出、提供商、模型、提示版本、调用参数、流式片段、工具调用、状态、用量、费用、延迟、重试、取消和错误。用户提交、节点、来源选区和任务在模型调用前持久化。

Chat 和研究生成通过 SSE、流式 `fetch` 或等价连接渐进交付。流连接中断后，WebUI 根据任务 ID 查询当前状态并继续展示已经保存的输出。

当前研究生成自由输出连续正文，完成后由确定性规则派生节级语义卡片，再由小模型按需补充标题和概念元数据；正文版本与语义范围承担稳定定位，卡片不保存正文副本。生成的有界修复只处理断流、截断、空节和其他契约失败，不做内容质量评分；页面始终呈现连续正文，卡片边界不进入可读文本或选区。

语义标记属于内容增强层，不是正文、选区、引用或来源关系的前置依赖。主对话与长文正文已由同一次模型流返回正文和四类提及控制标记；控制串同时携带只在当前回答有效的隐藏对象身份，同一对象可跨不同文字共享身份，同名异义对象使用不同身份。服务端在控制短语闭合后保存干净正文与独立范围，格式或身份错误时丢标记保正文；深度 2–3 确定性减少标记，深度 4 停止。深入研究、联网回答与融合正文尚未统一接入这套提示，旧开发数据保留确定性词法回退。实体预览只在同一节点内复用：跨消息同名提及先以双方各不超过 600 字的局部语境核验，不同节点始终重新生成。导入文档弱标记不在当前阶段。服务端校验标记身份、文本、偏移、数量和安全边界；模型不可用、任务失败或结果不可信时只隐藏弱标记，不阻塞正文、手动选区、引用、来源返回或节点生长。

F1 当前扫描相似节点候选并核验关系类型；“保留关系”建立语义相关边（实现标识 `semantic-related`），拒绝后进入确定性冷却。F2 在用户确认后创建独立新增的融合节点，F3 在用户预先开启自动融合后复用同一契约；二者都不覆盖或改写来源节点、原始内容和既有父子或语义关系，融合来源通过类型化融合来源边及来源片段引用保存。自动融合默认关闭。跨会话候选、多来源提议和独立融合会话属于 ADR-0022 的未实现目标；ADR-0023 又将目标关联路径收缩为临时提示，不再写入永久 `semantic-related` 边。停止写入、已有边处理与界面迁移尚未实施。

ADR-0024 进一步确定未实现目标：AI 自主发现达到质量门槛后自动创建研究地图 B 面临时融合节点，以候选来源连接引用 A 面正式来源；B 面与 A 面共享画布坐标但隔离交互，确认后同一节点及核验通过的连接原位提升为 A 面正式融合节点与融合来源。当前契约没有临时节点状态、候选来源连接、A/B 层投影、原位提升或 B 面导航快照，现有“自动融合”会直接创建永久节点，不能作为目标行为。

## #35–#44 已完成架构基线

正文与语义派生层的 expand–contract 迁移已经完成：

- 连续正文是唯一可读事实源；语义卡片只保存骨架和派生元数据，不保存正文副本。
- `research_body_versions` 与 `research_semantic_fragments` 提供稳定正文版本、语义范围、上下文选择和来源定位；检索与融合运行时从正文版本回读内容。
- 当前研究地图仍按会话投影，专注与关联呈现共享同一节点、三类边、筛选和导航状态；全局查询目标见 ADR-0022。
- 融合提议、融合来源条和正文引用可以返回来源语义范围；版本或范围失效时明确降级，不伪造精确定位。
- 节点页、研究地图和语义卡片共享视觉令牌，并覆盖响应式、键盘、屏幕阅读器语义、减少动态效果和像素回归基线。

## 本地产品观测与模型会话轨迹

Collector 在 WebUI 事件入口、领域任务、模型网关和 Agent 搜索边界生成统一轨迹。一次用户操作使用稳定关联 ID 串联：

- 界面操作、页面状态和用户可见结果；
- 研究会话、当前内容、选区和研究分支；
- 后台任务、步骤、重试与恢复；
- 模型提示、上下文、参数、流式回复、工具调用和最终输出；
- 可披露的联网查询、净化后的来源、引用选择、固定统计摘要和失败分类；不记录供应商原始响应、认证头、Cookie、会话令牌或带敏感参数的 URL；
- 首字延迟、总耗时、token、费用、取消和错误。

轨迹采用接近 OpenTelemetry 与 OpenInference 的层级结构，并保留本地查询与导出接口。当前实现直接写入 Collector SQLite，保持单机安装体验；后续可以增加到 Langfuse、Helicone、Arize Phoenix 或其他兼容系统的可选导出器。

原始模型会话内容保存在本地轨迹存储中。API Key、本地会话令牌和认证头在进入轨迹前清除。普通运行日志保存定位运行故障所需的结构化信息，完整会话内容通过轨迹查看与导出。

## 联网搜索

联网能力通过两条路径提供：

1. **供应商原生联网**（阶段 E2/E3）：OpenAI Responses `web_search`、Gemini Google Search grounding 与 Anthropic Messages server-side web search/web fetch 由模型网关归一为统一的来源记录与行内引用结构。
2. **Agent 自主搜索循环**（阶段 F1-F3）：Collector 自建搜索链路，支持 Bing（默认，零配置）、DuckDuckGo（免费回退）、Tavily（AI 专用搜索 API，需 Key）和 SearXNG（自托管聚合引擎）四个后端。后端通过统一 `SearchBackend` 接口适配，支持运行时配置切换和故障回退链。

用户主动发起的 Chat、研究节点和阅读页提问默认不请求联网，输入框提供逐次联网开关；关闭时不执行供应商原生联网或 Agent 搜索，开启时才允许当前配置支持的路径运行。选区分析始终不联网。其他 AI 生成任务按产品契约决定是否联网，不继承其他提交的开关状态。搜索后端凭证和供应商凭证分别遵守各自的本机凭证边界。

每次联网运行及引用都进入本地 SQLite v21 轨迹。供应商未返回来源时，界面如实说明本轮未获得可核验引用，不呈现虚构来源。

## 本地服务安全

- 服务只监听 `127.0.0.1`；
- WebUI 和 API 使用同源交付；
- 数据路由使用本地会话令牌；
- 校验 `Host`、`Origin` 和请求来源；
- CORS 使用精确允许来源；
- 状态修改请求具备 CSRF 防护或等价同源保护；
- 请求体、文件、响应、重定向、解析工作量和网络时间均有上限；
- 外部 URL 在请求前和重定向后校验公网目标；
- API Key、会话令牌、认证头和系统敏感字段在日志与轨迹入口清除；
- 启动器专用控制凭据只能在本机认证请求头中使用，普通已配对客户端不能创建浏览器启动入口；
- 关闭本地服务使用当前会话授权，并展示明确确认结果。

本地监听表示部署位置，认证与来源校验承担访问控制。

## 模型凭证

模型密钥只进入本机服务的凭证边界。WebUI 提交新密钥后只接收“已配置”、供应商和模型等状态信息。

凭证存储方案需要满足：

- 原始密钥避开 WebUI 状态、浏览器存储、普通业务表、日志和导出；
- 服务重启后可以恢复；
- 配置清理与凭证清理保持一致；
- 存储能力不可用时展示明确恢复路径；
- 自动化测试使用隔离的假凭证存储。

当前实现：真实 API Key 与 ProviderProfile 分离存储在 SQLite 独立表 `provider_credentials`（migration v22），主键与 `provider_profiles(id)` 外键关联并级联删除；Profile 的 `record_json`、列表与激活响应只携带 `credentialConfigured` 布尔标志，HTTP 响应永不回传密钥。清空全部数据（`clearAllData`）保留 `provider_profiles` 与 `provider_credentials`，确保清理研究数据后 AI 配置仍可用。启动时若存在 `COLLECTOR_AI_*` 环境变量，强制覆盖并激活 `environment-<providerId>` 配置；否则读取持久化的激活配置与对应凭证重建模型网关。明文凭钥存储符合当前本机单用户威胁模型；未来接入系统级加密只需替换凭证 CRUD 层，无需改动表结构。

WebUI 回填：编辑配置时，客户端通过专用认证端点 `GET /v1/provider-profiles/:id/credential` 读取已保存的原始 Key，以 `password` 输入框暗文填入；输入框右侧提供眼睛按钮切换明文/暗文显示。Key 仅在组件内存中使用，不写入浏览器存储、URL、日志或错误上报；保存后输入框继续保留暗文 Key（不清空），服务重启后再次编辑仍可回填。

启用/停用：每套 ProviderProfile 有 `enabled` 字段。通过 `POST /v1/provider-profiles/:id/enabled` 切换；当前使用中的配置不能停用（服务端校验）。停用的配置在会话页快速切换和任务模型分配中不可见，但保留在持久化列表中，可随时重新启用。

模型发现：设置页的“获取模型”通过 `POST /v1/provider-models/discover` 调用供应商端点 `GET {baseUrl}/models` 拉取可调用模型列表（OpenAI 兼容 Bearer、Anthropic `x-api-key`、Gemini `x-goog-api-key` 三种认证；Gemini 响应解析 `models[].name` 并去掉 `models/` 前缀）。请求可复用已保存凭证，响应只含模型名与分类错误文案（认证失败 / 端点不支持 / 解析失败 / 超时），自定义 baseUrl 一律经过公网地址校验。获取成功后，WebUI 在同页面内以按家族分组的复选框列表展示模型；新建模式可勾选多个模型批量保存（共用同一 Key，一个 Key 配多模型），编辑模式同样可勾选批量补充模型。已保存的同厂商模型自动禁用，避免重复。

按任务类型路由：`model_purpose_routes` 表（migration v23）保存“任务类型 → ProviderProfile”分配，任务类型为 chat（对话）、selection（选区分析）、research（深入研究）、search（联网搜索）、document（文档生成）。未分配的用途跟随当前激活配置。服务层在配置、凭证、路由或激活变化后懒重建按用途的网关快照，生成调用按用途解析；失效分配（配置删除、Key 缺失、解析失败、已停用）静默回退激活配置。工作流的冻结路由恢复语义不经过任务分配。每次调用的真实供应商与模型以模型调用轨迹为准。

## 文件导入与内容快照

```text
浏览器选择或拖放文件
        ↓
受限上传接口
        ↓
保存原文件与校验信息
        ↓
确定性解析
        ↓
生成阅读视图、结构锚点和稳定内容快照
        ↓
（增强层）结合快照上下文异步生成语义标记
        ↓
WebUI 阅读、选区、研究与来源返回
```

MVP 文件范围为 TXT、Markdown、DOCX 和文本型 PDF，单文件上限为 20 MiB。研究会话导入使用独立的附件、持久任务、内容快照和事件模型；上传原文件以不透明对象名保存在本地，浏览器只接收稳定 ID、文件元数据、状态和结构锚点，不接收本地路径。SQLite migration v16 保存会话关联、任务、快照和可重放事件；服务重启后恢复排队任务，将处理中断标记为可重试，并清理数据库未引用的遗留对象。

上传幂等键按研究会话隔离，与创建会话键和消息键相互独立。TXT 使用行号锚点，Markdown 使用行号、标题和块类型，DOCX 使用段落序号、标题和块类型，PDF 使用页码；阅读入口由内容快照 ID 和块 ID 驱动。

## 会话与任务恢复

- 用户输入在任务启动前保存；
- 创建研究会话和提交消息分别使用稳定幂等请求 ID；浏览器在网络结果不确定时复用原请求 ID，服务端在 SQLite 事务中返回首次创建的记录；
- 每个长任务具有稳定任务 ID；
- 页面刷新后重新读取当前会话、阅读位置和任务状态；
- 浏览器页面关闭后，本机服务继续保存任务进度；
- 服务异常退出后，下一次启动恢复可继续任务并标记需要人工处理的状态；
- 重复启动复用当前构建对应的服务实例、动态端口和后台任务；
- 健康响应包含实例 ID 和运行版本指纹，启动器确认连接到身份与当前构建都一致的实例；
- 版本不一致且既有实例支持受控关闭时先安全关闭，再启动当前版本；更早版本或任何无法确认既有实例已经退出的情况都不创建第二个服务；
- 数据目录生命周期锁保证同一份 SQLite 和用户文件只能由一个服务持有。

## WebUI 布局

WebUI 统一以 `/research/:sessionId/node/:nodeId` 作为节点页：中央显示当前节点的连续正文，顶部来源条展示来路并可返回原内容原选区。`/research/:sessionId` 与 `/research/:sessionId/branch/:branchId` 只提供兼容重定向；导入文档阅读使用 `/research/:sessionId/reading/:contentSnapshotId`，`?sel=<selectionId>` 恢复来源高亮。

顶栏「研究地图」按钮或快捷键 `t`（专注）/ `g`（关联）打开统一覆盖层；专注模式呈现当前节点的面包屑祖先路径、祖先 / 直接子 / 同级脉络与可折叠「关联」区，关联模式桌面端使用网状画布、窄屏使用同源关系列表。两者消费同一服务端图投影和三类边，筛选状态模块级共享。选中文字后在选区上方显示浮动胶囊，用户明确【引用】后才进入输入框引用态，也可以直接【标记】并填写笔记；标记列表返回后只恢复高亮，不自动创建引用。

完整布局记录在本文件；产品交互原则与当前能力状态见 `docs/PROJECT.md`，领域术语见 `CONTEXT.md`。

## 当前代码实施边界

当前已实现 Node API、SQLite、共享契约、模型网关、统一研究节点与类型化边、单一图投影、正式/临时切片与切片上下文、文件导入、确定性 TXT/Markdown/DOCX/PDF 解析、任务与会话恢复、模型设置、运行记录，以及生产构建同源服务、动态端口启动器、重复启动复用和首次安全配对。正式服务从专用 WebUI 构建目录读取资源，浏览器页面路由回退到 SPA 入口；`/v1` 路由继续使用本地认证和来源校验。

运行版本兼容检查、旧版本安全更换和数据目录单服务独占已经实现并有自动化覆盖；真实旧服务替换、异常退出和无法安全关闭旧实例仍需实际运行验收，不计入 live verified 边界。

已配对浏览器扩展保留 `43110` 回环适配入口，并与动态 WebUI 端口共享同一认证和领域服务。该入口不提供 WebUI，未配对请求仍被拒绝。

WebUI 当前没有用户可见的关闭服务入口；启动与退出生命周期仍由启动器、受控本机端点和操作系统进程边界承担。文件导入后续仍需决定接近 20 MiB 的性能目标与 Markdown 列表结构渲染策略。

`apps/browser-extension` 提供浏览器来源采集基础。新的产品界面行为进入 WebUI 与 HTTP/SSE 路径。

## 当前技术选型

- WebUI 位于 `apps/web`，使用 React、TypeScript、Vite 和 React Router；
- 共享领域与接口契约位于 `packages/capture-contracts`，模型适配位于 `packages/model-gateway`；
- 浏览器端到端测试使用 Playwright，并为端口、数据目录、会话和模型供应商提供隔离配置；
- WebUI 构建产物由 `apps/api` 同源提供；
- 普通业务请求使用 HTTP，生成内容与后台任务通过统一客户端封装接收 SSE、流式 `fetch` 或等价的渐进事件；
- 供应商原生联网由模型网关归一搜索与引用格式；Collector Agent 搜索循环通过统一 `SearchBackend` 接口支持 Bing、DuckDuckGo、Tavily 和 SearXNG，并记录搜索与抓取轨迹；
- 产品事件、领域任务、模型调用和搜索调用共享关联 ID，并保存在本地轨迹存储中；
- 当前验证数字和证据边界只在 `docs/PROJECT.md` 四态能力表维护，本文件不复制测试计数。
