# Collector 人工验收说明标准

状态：2026-08-03 当前产品人工验收写作与判定标准。本标准定义如何描述和判断已选择功能区，不维护版本测试步骤或最后一次通过证据。Chrome DevTools MCP 人类拟真测试的触发、范围与运行纪律见 `docs/agents/browser-acceptance.md`；动态功能区步骤见 `docs/agents/browser-acceptance/areas/`；最后实际证据见 `docs/agents/browser-acceptance/BASELINE.md`。

## 适用对象

人工验收参与者以普通用户身份操作 Collector，通过界面直接判断操作结果。手册使用日常语言，并为每一步提供清楚的动作和预期结果。

人工验收回答：“执行这个动作后，界面是否出现了说明中的结果。”技术差异通过源码、日志和自动化证据进入调查。

## 每份验收手册的固定结构

### 1. 本次验证目标

用一至三句话说明用户场景和成功结果。例如：“验证导入一份 PDF 后，可以阅读正文、选中一句话，并在重启 Collector 后返回同一位置。”

### 2. 开始前准备

逐项写明：

- 需要打开的应用和页面；
- 账号或登录要求；
- 预先准备的测试内容；
- 预计用时；
- 本次可能保存或发送的内容；
- 正确起始页面的可见特征。

### 3. 隐私与数据说明

操作前说明保存的文字、文件、来源和上下文，数据保存位置，以及测试结束后的清理方式。

说明 Collector 会在本机保存产品操作、模型提示与回复、工具调用、联网搜索、来源选择、耗时和错误等关联轨迹。当前受测版本已经提供轨迹查看、导出或清理能力时，验收过程确认相应结果，并确认供应商凭证、认证头和本地会话令牌未进入记录；未实现的候选能力不得写成当前步骤。

测试过程使用预制样本。参与者自主选择使用私人材料时，结果记录采用最小披露方式：用例编号、步骤编号和现象描述优先；截图保留判断问题所需区域，并遮盖账号、姓名、标题和私人正文。

密码、验证码和 API Key 由参与者在对应产品的安全界面中自行处理，验收记录只保存配置结果状态。

### 4. 逐步操作

每一步只包含一个主要动作，并使用界面中真实可见的名称。例如：“点击‘导入文档’”“选中第二段中的‘多头注意力’”。

按钮位置通过文字位置描述或截图说明。参与者全程使用普通产品界面。

### 5. 每一步的预期结果

紧跟操作写出肉眼可判断的结果，包括可见文字、位置、加载状态和可用操作。

### 6. 结果记录

每个用例提供三个结果：

- 符合说明；
- 与说明不一致；
- 无法继续。

出现差异时，参与者记录当前页面、步骤编号和看到的文字，并按隐私说明保留必要截图。

### 7. 停止条件

以下情况触发当前用例停止：

- 页面要求输入准备说明中未提及的密码、验证码或密钥；
- 界面出现删除、覆盖或公开真实数据的提示；
- 实际界面与步骤说明存在明显差异；
- 应用失去响应或连续两次出现同一错误；
- 下一步操作的安全条件不明确。

停止后保留当前现场并记录为待调查项。

### 8. 测试结束清理

说明测试内容、研究节点、标记项目和截图的清理步骤，以及测试设置的恢复方式。

## 当前功能区入口

人工验收按以下六个功能区选择动态专项，不在本标准复制逐步脚本：

1. [启动器与模型配置](agents/browser-acceptance/areas/launcher-model.md)；
2. [Chat、联网搜索与来源引用](agents/browser-acceptance/areas/chat-search-sources.md)；
3. [选区、引用、标记与来源返回](agents/browser-acceptance/areas/selection-mark-return.md)；
4. [节点生长、上下文与导航](agents/browser-acceptance/areas/nodes-context-navigation.md)；
5. [文档导入与阅读](agents/browser-acceptance/areas/documents-reading.md)；
6. [设置、本地观测与数据安全](agents/browser-acceptance/areas/settings-observability-data.md)。

功能实现、自动化通过或 Issue 关闭都不能自动升级人工基线。只有用户主动触发、完成实际浏览器操作并经过独立第二轮复核后，才更新 `agents/browser-acceptance/BASELINE.md`。

## 长期可观察契约

动态专项可以随版本调整入口和样本，但以下产品行为必须始终能够由普通用户直接判断：

- 选中文字只显示浮动胶囊；只有明确点击【引用】才进入输入框引用态；
- 在此追问留在当前节点，深入研究生长带来源选区的子节点；
- 【标记】不依赖模型，从列表返回后只恢复原文高亮，不自动引用；
- `t` 父子树与 `g` 关系导航都有可发现入口、完整键盘路径和安全退出；
- 连续正文可稳定阅读和选择，后台片段边界不污染可读文字；
- 联网开关默认关闭，关闭时无外部搜索请求，开启才允许联网；无来源时不显示虚假引用；
- 刷新、重新打开和服务重启后，已确认保存的研究、来源关系、标记和任务按契约恢复；
- 模型设置与运行记录不暴露 API Key、认证头、Cookie、会话令牌或控制令牌。

## 选区引用验收要求

具体手册覆盖（以交互修订 issues #9–#11 后的当前实现为准；来源返回行为再按受测版本的现行规格选择）：

1. 选中文字后，浮动胶囊出现在选区附近并提供【引用】；
2. 点击【引用】后，引用态胶囊进入输入框区域并显示选区文本截取与移除按钮；
3. 随后聚焦输入框、输入文字或原生选区坍缩时，引用状态不丢失；
4. 「在此追问」携带引用在当前节点对话流发送成功；
5. 「深入研究这段」以选区为来源创建子节点并导航到新节点；
6. 移除引用后发送回到普通对话；
7. 键盘可以聚焦、确认和移除胶囊；
8. 来源返回与 `?sel=` 的高亮时长、浮动操作和降级行为以受测版本的现行规格为准，锚点失效时不得阻塞操作。

## 本地 WebUI 启动与恢复验收要求

具体手册覆盖：

1. 双击 Collector 启动器后，默认浏览器自动打开本地工作区；
2. 地址使用 `127.0.0.1` 和本次启动端口；
3. 首次打开由启动器自动完成本机配对，URL、浏览器存储和日志中不出现会话令牌；
4. 在代码未变化时重复启动，打开同一个本地服务，实例 ID、运行版本、进程和端口保持一致；
5. 在代码更新后再次启动：既有实例支持受控关闭时先自然关闭，再打开当前版本服务；更早版本提示先关闭旧服务后重试；浏览器不出现新界面连接旧接口的混合状态；
6. 同一数据目录不能同时启动第二个服务；旧服务暂时无响应或无法确认已退出时，本次启动给出明确提示且不创建并行服务；
7. 刷新页面后恢复已保存会话和阅读位置；
8. 关闭浏览器页面后，本地服务中的已提交任务保持可恢复状态；
9. 异常退出后的下一次启动恢复已经保存的数据；
10. 其他网页无法直接调用 Collector 的本地数据接口。

## 深入研究验收要求

具体专项至少覆盖：

1. `t` 打开父子树，能够理解当前路径、进入父节点 / 子节点 / 兄弟节点并安全返回；
2. `g` 打开关系导航，桌面端显示网状画布，窄屏显示同源关系列表；
3. 按受测版本的现行实现验证父子、`semantic-related` 旧实现边和融合来源三类边具有非颜色冗余编码，筛选只改变呈现；该步骤不把旧实现边解释为目标产品中的第三种永久关系；
4. 筛选后的键盘导航只遍历相关节点，全空筛选保留当前节点和明确空态；
5. 画布平移、缩放、逐层展开、打开父节点、返回当前页面和 Escape 焦点回归可用；
6. 从选区生长子节点（可选填写重点问题作为第一轮输入）；
7. 子节点页面顶部来源条展示内容名称、选区摘要和返回入口；
8. 生成恢复状态保留节点、方向和来源关系；
9. 返回来源后恢复原内容和选区位置；精确锚点失效时显示可理解降级；
10. 弱标记预览只生成一次，点击或键盘确认后复用内容生长节点；标记失败不影响手动路径。

## 用户标记与笔记验收要求

当前版本按以下要点验收（旧稍后再学验收要求随星级/AI 概括体验退役）：

1. 选区胶囊上点击【标记】立即保存标记；
2. 展开的笔记输入框 1 秒内不点击自动收起（纯标记）；
3. 点击输入框后固定于屏幕位置，滚动页面不移动，可输入笔记；
4. 点击屏幕其他位置保存并关闭（空笔记为纯标记；Escape 不关闭）；
5. 标记列表呈现原文截取、笔记、来源节点与时间；
6. 从标记返回原内容原选区并恢复高亮；
7. 返回后默认只显示恢复浮动胶囊，不自动创建引用；明确点击【引用】后才进入引用态；
8. 未配置模型时标记、列表与返回均可用。

## 内部文件阅读器首轮人工验收

首轮使用八组预制样本：

1. TXT：导入、阅读、选取一段文字；
2. Markdown：标题、列表、代码块和普通段落；
3. 简单 DOCX：标题、段落、列表和常用文字格式；
4. 结构型 DOCX：基础表格、图片、链接和表格单元选取；
5. 简单文本型 PDF：页面显示、文字选取和页内返回；
6. 较长或多栏文本型 PDF：阅读顺序、跨页阅读和来源返回；
7. 重启后返回：DOCX/PDF 保持导入时快照和正确位置；
8. 恢复状态：扫描、加密、损坏或解析质量较低的文件展示原因、原文件和手动粘贴入口。

每个样本附上关键文字、结构说明和参考截图。性能目标在接近 20 MiB 的真实样本原型后确定；首轮手册同时记录处理状态出现时间、可取消性和最终打开时间。

## 节点页视觉体验验收要求

#44 起（2026-08-07）以下视觉维度已由自动化像素基线覆盖（`z-visual-baseline.spec.ts`，7 张基线 png 入库），人类拟真测试尚未触发；人工验收手册生成时按以下要求编写：

1. 节点页视觉顺序稳定：正文内容 → 当前节点与主要任务 → 局部导航 → 辅助关系与工具；工具栏和图例不持续争夺注意力；
2. 语义卡片具备默认、悬停、焦点、定位（融合回溯强调）与来源状态，悬停/焦点只改变背景与阴影、不引起文字或布局位移；
3. 研究地图具备加载、空、错误与筛选关闭状态，均有可理解说明与安全出口；
4. 画布三类边通过线型、粗细、方向端点、标签与颜色组合编码，颜色不是唯一通道；当前节点是明确视觉锚点；
5. 键盘焦点环清楚可见；专注脉络当前行带 `aria-current`，屏幕阅读器可判定当前锚点；
6. 模式切换（专注/关联）保持正文与当前节点，动效有界且 reduced-motion 下即时；
7. 窄屏（320px）无横向溢出，主要操作可达。

## 人工验收开始前检查

发出手册前完整走一遍，并确认：

- 界面名称与当前版本一致；
- 所有截图完成隐私处理；
- 每一步只有一个主要动作；
- 每个预期结果都可以直接观察；
- 每个恢复分支都有停止和记录方式；
- 测试结束后的清理步骤完整。
