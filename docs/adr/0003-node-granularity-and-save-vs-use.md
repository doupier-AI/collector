# 节点粒度与"保存时少判断，使用时再判断"

2026-08-03 访谈确认三个粒度严格分离，并确立保存/使用不对称原则。

**决策：**
- 研究节点 = 多轮对话容器 = 用户地图中的稳定对象。多轮对话始终在同一节点：追问、翻译、改写、总结、普通问答都追加同节点，不得每轮拆节点。
- 只有用户明确的生长动作（深入研究、选区生长、弱标记生长）才创建子节点；融合创建独立融合节点。
- 语义范围 = 节点内容的派生定位，是上下文选择与融合引用的最小单位；用户不管理语义范围。
- 融合节点 = 基于多来源范围的增量综合，不是对原节点的清洗或重拼装；融合不负责清洗无关轮次。
- 保存时少判断，使用时再判断：消息产生时只保存并解析流内轻标记；检索时临时选范围；生长或融合触发时才做重解构。无关轮次允许存在，由检索时按需语义筛选排除。

**Why:** 每轮拆节点会增加判断负担并制造大量碎节点；话题守卫和意图分类器在保存时判断既不可靠又无必要，因为消费端（上下文选择、融合）可以在使用时做更准确的判断。

**Consequences:** 节点数量只随用户显式动作增长；同节点可混含多主题轮次，消费端自行筛选；融合前必须做来源核验而非信任保存时的分类。
