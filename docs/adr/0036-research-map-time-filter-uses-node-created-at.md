# 研究地图时间筛选使用节点创建时间

2026-08-20 用户确认。

## 决策

- 研究地图中的“时间”表示研究节点的创建时间，唯一事实源是 `ResearchNodeRecord.createdAt`。
- 用户在界面选择自然日时，客户端按用户本地时区把日期换算为 `[当天 00:00, 次日 00:00)` 的半开区间，再以 ISO 时间传给统一观察查询；服务端只验证并应用这个明确区间。
- 补充回答、重新生成、修改节点或会话标题、移动项目、归档/恢复等后续活动不会改变节点所属的创建时间范围。
- 时间筛选只改变当前观察结果，不改写节点、会话、关系或正文事实，也不产生第二份时间字段。
- 本决定不定义“最近活动”筛选。若未来需要按活跃程度观察，必须先单独定义哪些行为算活动、活动归属节点还是会话，以及活动如何持久化和排序。

## Why

节点创建时间已经是稳定、可验证的事实。相同筛选条件在刷新、返回现场和后续编辑后仍应得到相同范围；若直接复用节点或会话的更新时间，标题修改、对话追加等无关行为会使旧知识在日期范围间漂移，用户无法理解筛选结果为什么改变。

半开区间避免把结束日的午夜重复计入相邻范围，也让不同本地时区的自然日能够转换为无歧义的服务器时间。服务端不推测用户时区，客户端也不自行决定节点是否命中。

## 与既有 ADR 的关系

- 本 ADR 补充 ADR-0022 的全局观察范围，并保持 ADR-0026 的完整连通和范围外桥接语义。
- 项目、生命周期和永久关系仍与时间组合成同一份观察输入；筛选不得删除关系事实或截断已启用关系需要的桥接节点。
- 图谱现场恢复继续遵守现有 history entry 边界，不把筛选写入 URL、业务库或 `localStorage`。

## Consequences

现有预埋的 `updatedFrom` / `updatedTo` 不能继续作为正式产品契约；实现应改为名称和边界都明确的创建时间半开区间。`createdAt` 已存在，不需要 SQLite schema migration，也不为开发期旧研究数据增加兼容分支。共享契约、HTTP、客户端、统一观察派生、现场快照和自动化测试必须使用同一语义。
