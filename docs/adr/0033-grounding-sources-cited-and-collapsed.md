# 联网来源区域收口：底部列表只列正文实际引用并默认折叠

2026-08-17 确认（真实使用反馈驱动：底部「本轮可核验来源」区域占据大量阅读面积；Agent 搜索循环「搜到即来源」使列表混入大量与问题无关的搜索结果）：

1. **底部来源列表语义从「搜索痕迹」改为「正文实际依据」**。列表只展示本轮正文中实际出现引用标记（`[来源n]` / 行内引用胶囊）的来源；未被引用的搜索结果不再出现在界面列表中。来源序号与正文引用标记保持同一编号、不重排（列表可能只出现来源 2、5、7）。两条联网路径（供应商原生 / Agent 搜索循环）的来源展示语义由此统一为「实际引用」。

2. **列表默认折叠为一行摘要**。折叠态显示本轮实际引用数量（如「本轮引用了 5 个来源 ▸」），点击展开完整列表；正文内的行内引用胶囊行为不变，仍可直接点开单个来源并跳转原始网页。

3. **未被引用的搜索结果照常落库，仅默认不展示**。Agent 搜索循环「搜到即来源」的入库规则（model-gateway）不变，#49 证据状态（full / partial / none）管线不变；过滤发生在消息组装/读取层，不发生在入库层。本地观测与运行记录的审计能力不变，未来如需「搜索过程回顾」或恢复完整列表有数据基础。

**Why:** 现状下一轮 Agent 联网搜索最多约 50 条来源（5 次搜索 × 每次 ≤10 条）全部逐条渲染进阅读区；引用清洗（#49）只过滤正文引用标记，从不过滤底部列表，用户看到的是搜索过程痕迹而非回答依据。用户明确不希望该区域默认占据阅读面积，且列表中大量来源与问题无关。改为「实际引用 + 默认折叠」后，列表即本轮参考文献，通常只有几条且全部与回答直接相关，面积问题与相关性问题同时解决。过滤放在读取层而非入库层，保留完整审计与回溯能力，逆转成本低。

**Consequences:**

- 底部区域从「本轮可核验来源（全部搜索痕迹）」变为「本轮引用来源（正文实际依据）」；区域标题文案与 `GroundingScopeNote` 计数口径的对齐、折叠交互细节（键盘、读屏、窄屏）在实施票据中固定。
- `evidenceStatus=none` 的来源本就无法被正文引用（引用清洗丢弃），天然不再出现在列表；`full`/`partial` 但未被引用的来源继续落库但不展示。
- 普通（非联网）回答与导入文档不受影响；融合正文的 `[来源n]` 引用指向融合来源节点，不经过本区域。
- 本决策不改变 #49 证据管线、#46 抓取安全边界与联网逐次开关默认关闭的既定边界；不改变搜索循环的查询、抓取与重试行为。
- 与 ADR-0032（轮次卡片与双导航）无依赖关系，可独立出票实施。
