# 开发数据兼容基线

2026-08-03 访谈确认当前数据保留策略。

**决策：**
- 当前处于"开发数据期"：切换到新数据结构时可以清空研究数据（会话、节点、回答、切片、选区、标记、融合提议、运行记录）。
- 必须保留：模型供应商配置、API Key、任务分配、应用设置。
- 只有用户显式批准并在 `docs/PROJECT.md` 记录"数据兼容基线"之后，才承诺跨版本保留研究数据。

**Why:** 开发期结构迭代频繁，为旧研究数据做兼容迁移成本高且价值低；但模型配置与凭证是用户重新使用的必要前提，清空会造成真实损失。

**Consequences:** 迁移实现可以先清研究数据再建结构，无需为研究数据写迁移脚本；`clearAllData` 类操作必须继续保留 `provider_profiles` 与 `provider_credentials`；承诺数据兼容前需要一次显式产品决策。

**决策纪律：** 开发数据期的历史研究数据不得作为产品或功能设计的约束条件。设计新功能、划分内容边界、判定"是否需要兼容/兜底"时，不得因为"开发数据库里已存在某种旧数据"而增加兼容分支、降级兜底或改变目标形态；遇到"历史数据/旧数据怎么办"的疑问，一律回到本基线——可清空即不构成约束。历史数据只有在用户显式批准数据兼容基线后才需要纳入设计考量。
