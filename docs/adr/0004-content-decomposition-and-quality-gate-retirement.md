# 内容解构分层与运行时质量检查退役

2026-08-03 访谈确认：内容解构统一定义，分三层实施；运行时质量检查整体退役。

**决策：**
- 内容解构 = 不改写原始内容，把稳定内容解析成可定位、可检索、可关联、可回溯的派生语义结构；解构产物绑定稳定内容版本；解构失败不阻止阅读、复制、讨论和手动选择引用。
- 分层：①流式轻量提及标记（随生成同一次模型流产生）；②长文/跨节点按需语义范围索引（检索时临时判断）；③融合触发时的深度解构与关系核验。
- 生成时输出完整语义切片降为待验证技术方案，需对照实验后再定，不作为必经环节。
- 运行时质量检查整体退役：正文无条件流式展示与保存；用户输入和粘贴内容不受任何门禁；硬上限诚实提示；派生结构失败只丢弃派生层。
- 下游质量由融合触发时的来源核验承担（正确时间、正确对象）；内容好坏由用户自己判断；离线调优是开发手段，不是运行时功能。

**Why:** 质量检查的三个原始理由全部被更近源头的机制吸收——结构合法性由"正文唯一事实源+派生层容错丢弃"覆盖；内容质量由用户判断；下游污染由融合时来源核验承担。

**Consequences:** GitHub #38（规划、质量检查与有界修复）需按"质量检查退役"重写为只做契约安全解析与有界修复，不做内容质量评分；生成路径上不引入完整切片输出作为必经环节。
