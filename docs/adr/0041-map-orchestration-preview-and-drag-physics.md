# 研究地图的临时编排预览与拖动邻域物理

2026-08-22 用户确认。用户反馈研究地图（/map）节点与连线在密集时会显得混乱，提出"围绕选中节点动态调整位置"（例如选中融合节点后支撑节点均匀围成圆形）并参考 neo4j/karpathy 式有机图谱，同时希望拖动节点时周边节点产生物理响应。此前 ADR-0026 与迭代文档将"选中/专注"锁定为"只改变强调状态、绝不重排、坐标稳定"。

## 决策

- **临时编排预览**：专注（选中）某节点时，其直接支撑/来源节点以约 300ms 动画聚拢到围绕该节点的环形位置，形成清晰的支撑视图；取消选中、切换焦点或刷新后动画复原。预览坐标只存在于渲染层，不写入 Map Scene 持久坐标，退出后已保存的图谱坐标保持原样。reduced-motion 用户直接跳转。
- **拖动邻域物理**：按住任意节点可拖动，一跳邻域节点产生弹簧与碰撞式物理响应（跟随、推开、回弹），松手后有界步数内带阻尼稳定。拖动与被带动节点的最终位置写入当前 history entry 的 Map Scene（沿用现有 replaceState 保存链路），刷新/后退恢复后保持；键盘焦点节点可用 Shift+方向键微调（同样触发邻域响应），Esc 取消本次拖动。
- 非交互路径（切筛选、开关关系、切换专注）仍不重排既有持久坐标——"持久坐标稳定"的验收口径只对非交互路径保留，交互路径（拖动/键盘移动）成为持久坐标的合法来源。
- 本决策取代 ADR-0026"专注不重新布局"与迭代文档"悬停和选中只改变强调状态"条款中关于"绝不重排"的部分，其余（不强制居中、不改变缩放平移）不变。

## Why

融合节点大量存在时，全部直线连线加固定坐标使支撑关系难以辨认；用户主动拖动并希望看到结构反馈是自然的交互预期。临时预览在不破坏持久坐标的前提下提供即时可读性；拖动物理把用户的手动整理纳入持久坐标，同时保持非交互路径的确定性。

## Consequences

- 新增纯函数交互模块 `apps/web/src/features/navigation/mapInteractions.ts`（环形目标位、缓动插值、邻域弹簧/碰撞物理），可单元测试。
- `GlobalResearchMap` 新增三层坐标：持久层（布局 + positionOverrides）、交互层（拖动进行时）、编排层（选中预览）；序列化只写持久层，预览与进行时拖动不进 Map Scene。
- 物理限定邻域（一跳邻居）+ 有界结算，不做整图重算；松手后 settle 有步数上限，避免阻尼残差无限循环。
- 现有"选择前后坐标不变"组件测试改为"非交互路径坐标不变 + 预览态临时坐标 + 退出复原 + 拖动/键盘持久化"；#65 e2e 改为断言持久坐标稳定。
- 未实施：连线曲线化/标签防叠等纯视觉修复、"显式重新布局"按钮；超大图下的拖动物理表现留待 #79 规模测量票验证。
