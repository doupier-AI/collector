# 全站 UI 重构：Manus 式双主题工作台、双层级侧栏与彩虹签名按钮

2026-08-09 全站 UI 重构需求确认（用户对既有"安静画布"视觉不满意，追求更多动效、更高级配色、有呼吸感的布局与更直观的交互）。

**决策：**
- **双主题跟随系统**：`tokens.css` 新增 `@media (prefers-color-scheme: dark)` 深色令牌块，覆盖全部颜色/阴影/环/选区/网格边/难度色；浅色为默认不变。用户零配置，现有浅色测试与习惯不受影响。**正文阅读区（消息列表/切片卡片）在深色主题下保持浅色阅读面**（`--color-reading-*` 专用令牌 + 局部 `color-scheme: light`），长文阅读舒适、对比度稳定。
- **签名按钮点缀**：「开始研究」主按钮用彩虹渐变流动 + 点击弹性（纯 CSS 实现 21st.dev rainbow-button 同款效果，`AiRainbowButton` 组件，`ChatComposer rainbow` prop 开关）。不引入 Tailwind/shadcn/WebGL——项目为纯 CSS + BEM（global.css 约 4100 行），引入需全量迁移样式体系，收益远低于成本；其余按钮保持朴素，强调"把勇气花在一个地方"。
- **双层级侧栏**：左侧栏重构为窄图标栏（rail，64px：最近研究/AI 模型/融合/运行记录/回收站/折叠）+ 详情栏（detail，默认 320px 可折叠，弹性过渡 + 折叠态持久化）。顶部五入口瘦身——「开始 Chat」成主按钮，设置类入口收进详情栏底部「设置」菜单，回收站并入会话管理区（rail 图标）。保留全部既有 aria 标签/文案/类名（`内容导航` nav、`名称 (N)` 计数、`${title} 的菜单`、menuitem、`＋ 新建项目`、`重命名` textbox、`.drawer__*`），e2e 兼容。
- **会话批量操作**：侧栏「选择」模式（行勾选框 + 项目组选整组 + 底部 sticky 批量栏：已选 N 项 / 移动到… / 删除 / 取消），操作后自动退出；回收站页同款「选择」模式（批量恢复 / 批量彻底删除，带确认）。**复用现有单对象 API 并发执行，不新增后端端点**（数据一致性由既有单对象事务保证；失败保留选择可重试）。
- **章节导航与固定侧栏的共存**：`.slice-rail` 原以负 margin 悬停在正文左缘外侧（悬停带 32px），固定侧栏展开时与侧栏重叠导致交互拦截。新增 `.app-shell:has(.drawer--fixed)` 规则：固定侧栏存在时 rail 收进正文左缘内侧（正文左 padding 让位 2.75rem），侧栏收起/窄屏时恢复悬停设计。
- **固定侧栏 z-index** 保持原值 1（不高于章节导航 15）；重叠问题由上述 rail 让位方案解决，而非提升层叠。

**Why:** 用户明确不满既有视觉（"凑合用""整体效果不是我真正喜欢的"），诉求为更多动效、更高级配色、有呼吸感布局、更简单直观交互；批量删除/移动缺失是原始需求（会话增多后逐条操作不可管理）。

**Consequences:** 深色主题下需重拍全部像素基线（7 张，含 7 处 maskColor 改主题无关白）；`.page--start` logo 内联 SVG `#fff` 改 `--color-on-ai` 令牌；新增相对时间展示（`formatRelativeTime`，`.drawer__session-time` 类名保留）；新增 `--ease-spring` 动效令牌与 `--color-reading-*` 阅读面令牌；会话管理能力表证据更新；像素基线仍以 win32 + Chromium 为准。
