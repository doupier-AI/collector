# 专项：文档导入与阅读

## 范围

覆盖 TXT、Markdown、DOCX 和文本型 PDF 的导入、状态反馈、内部阅读、选区、来源返回、刷新与服务重启恢复。

## 重点路径

1. 从开始页选择或拖入受支持文件，确认预检、上传、解析和打开状态连续可见；
2. TXT／Markdown 检查标题、段落、列表、代码块和可选择性；
3. DOCX 检查常见标题、段落、列表、表格降级和阅读顺序；
4. 文本型 PDF 检查页码、文本顺序、选区和返回位置，不把文本快照误称为原始版式；
5. 在阅读页提问、引用、标记和生长节点，再返回文档位置；
6. 刷新、关闭页面、服务重启后继续读取已保存快照；
7. 扫描、加密、损坏或解析质量不足的文件显示真实原因和可继续方案。

## 增量选择

只改一种解析器时重点测该格式，并用 TXT 或 Markdown 做一条共享阅读器冒烟。公共阅读器、锚点或上传状态变化时，至少覆盖一种消息选区和一种文档选区的跨区路径。

## 共同检查

- 使用预制非私人样本，记录文件大小与结构；
- 接近体积上限的性能只在版本目标包含性能时执行；
- 窄屏、长文滚动、键盘选择和刷新恢复；
- 上传失败、网络结果不确定、重复提交和残留会话；
- 控制台解析警告与用户可见结果分开判断。

## 完成证据

记录格式、大小、结构、解析耗时、阅读截图、选区与返回证据、恢复结果。Chrome DevTools MCP 无法访问测试文件时，明确标为环境限制，不用自动化结果冒充人工上传。
