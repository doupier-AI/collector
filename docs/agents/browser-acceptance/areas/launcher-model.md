# 专项：启动器与模型配置

## 范围

覆盖双击启动、动态端口、本机配对、重复启动、持久化模型恢复、模型设置、任务模型分配和无模型失败状态。

## 重点路径

1. 从普通启动器进入本地 WebUI，确认地址没有令牌或配对码；
2. 同一版本重复启动时复用正确实例，不打开混合版本界面；
3. 已保存并启用模型时，首次进入后直接发送第一条 Chat，不执行人工模型切换；
4. 设置页新建、测试、保存、启停、发现模型和按任务类型分配；
5. 刷新与服务重启后配置状态一致，Key 不回显到页面、URL、控制台或网络响应；
6. 全新数据目录下提交问题，看到明确的未配置状态与恢复入口；
7. 范围包含版本替换时，验证旧服务安全关闭、进程退出、数据目录独占和异常锁释放。

## 增量选择

只选择与本次变化有关的路径。例如只修改模型发现时，不重复完整验证旧服务替换；修改启动恢复、凭证或任务路由时，必须增加“重启后首次 Chat”跨区冒烟。

## 共同检查

- 宽屏与窄屏设置页；
- 纯键盘完成主要表单操作；
- 密钥字段、控制台、请求和本机轨迹的敏感信息边界；
- 失败原因是否具体，重试是否保留用户输入；
- 实际模型与界面显示、任务路由和模型调用轨迹是否一致。

## 完成证据

记录启动方式、实例／版本指纹、受测模型状态、首次调用结果、关键页面截图、控制台与网络异常。不要记录 API Key。
