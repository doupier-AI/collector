# 专项：节点生长、上下文与导航

## 范围

覆盖节点创建、多层父子关系、来源线、节点内追问、父链上下文、弱标记生长、节点命名和当前版本的导航形态。

## 重点路径

1. 从根节点创建并列子节点，再从子节点创建孙节点，关系符合实际来源；
2. 子节点返回到直接来源节点，不错误跳回根节点；
3. 在此追问留在当前节点，节点生长产生新结构；
4. 深层回答理解祖先主题且不过度重复，刷新和重试不改变父链身份；
5. 弱标记低打扰、悬停预览只生成一次、点击或 Enter / Space 复用内容创建节点；失败时手动选区路径仍可用；
6. AI 节点名稳定显示，生成失败时使用确定性回退；
7. 按 `t` 打开父子树，验证当前路径、父子层级、兄弟节点、键盘导航、Escape 关闭和焦点回归；
8. 按 `g` 打开关系导航：桌面端验证网状画布，窄屏验证同源关系列表；
9. 按现行实现验证父子、`semantic-related` 旧实现边、融合来源三类边的文字 / 形状 / 线型冗余提示及筛选；筛选后键盘只遍历相关节点，全空筛选保留当前节点；
10. 画布验证逐层展开、收缩、平移、缩放、打开节点、打开父节点和返回当前页面；
11. 按现行实现验证 F1 提议的三条路径：保留关系只新增 `semantic-related` 旧实现边，融合为节点创建可回溯融合结果，暂不处理不创建关系；自动融合设置默认关闭，开启后只按现行规则处理新提议。

## 当前与未来边界

`t` 父子树、`g` 桌面网状画布 / 窄屏关系列表、三类实现边筛选、相似性提议以及 #31/#32 的确认式 / 自动融合都是当前已实现能力。目标节点系统仍未实施：全局跨会话地图、A/B 面、临时融合节点、稳定节点地址、完整连通专注与非连通区域置灰不得写入当前版本验收步骤。执行时既不能把目标能力误写为现状，也不能把仍在运行的 `semantic-related`、现役树或网状画布误判为已经退役。

## 增量选择

只测本版本实际启用的节点能力。父链、弱标记、命名和导航可以分别专项；共享节点关系或迁移变化时增加三层关系与刷新恢复冒烟。

## 共同检查

- 多层、并列、孤立或旧数据节点；
- 键盘导航、屏幕阅读语义和非颜色关系提示；
- 节点数量增加后的可读性、性能与视口；
- 任务失败、重试、刷新和服务重启；
- 来源关系与显示标签不会因模型失败丢失。

## 完成证据

记录受测导航形态、节点关系样本、父链深度、生成／命名状态、键盘路径和关键截图。未来 Issue 中的功能在进入当前版本前不纳入通过结论。
