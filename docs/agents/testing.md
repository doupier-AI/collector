# 验证执行细节（Testing）

根 `AGENTS.md`「分级验证」定义验证等级的选择原则与升级规则；本文件承载各等级的具体执行要求。凡涉及构建、测试或合并 `master` 的任务，开工前先读本文件。

> 本文件多条规则由 #86/#93/#94 复盘沉淀，其中门禁批次化与前置冒烟经 2026-08-18 用户逐项确认；文中「条件性必须 / 默认」强度标注同日经用户逐项确认。事故经过由 Git 与对应 Issue 追溯（另见 `docs/process-optimization-plan.md`），此处只保留长期有效规则。

## 实现前全链冒烟，错误发现时点前置

**条件性必须**：进入实际实施、写第一行业务代码前触发（纯文档、纯元数据等不进入业务实现的任务不触发）。触发后必须按任务类型跑约 5 分钟前置冒烟——服务端票：迁移重放 + 受影响单测 + 一条最短 e2e；UI 票：构建 + 受影响组件测试 + 一条最短 e2e；真实验收票：夹具自检（触发阈值/模型配置/端口）+ 直连探针。冒烟失败先修前提再实现；冒烟结果随最终验证记录写入提交说明。

## 全量 Playwright 门禁（防测试债务积累）

任何合并进 `master` 的提交、任何跨分支共享的测试基础设施改动（harness、helpers、playwright.config、e2e 基础库），必须先跑一次**完整**三项目全量（chromium + chromium-nomodel + chromium-autofusion）并全绿。日常功能切片仍按分级验证只跑受影响子集；但「视觉基线组（z-*.spec.ts）+ 共享库配置测试（settings-ai-model 等）」对测试顺序与共享库状态最敏感，全量门禁能一次性暴露「前序测试污染后序基线」这类跨测试依赖，避免其在仓库中无声积累到下一次强制全量时才爆发。

### 门禁按批次收税，不按票据收税（默认做法）

同一迭代/同一批待合票据先合并到集成分支，在集成分支上跑一次全量门禁全绿后再合 `master`，不为每笔合并各付一次门禁与构建。纯注释/纯文档/元数据改动（diff 无代码行变化，如 `git diff --stat` 不含代码语句变化）豁免全量门禁，只跑受影响子集，提交说明标注豁免理由。

### 门禁启动前确认最新构建

src 改动后必须先重建（根 `npm run build`）再启动全量门禁，防整轮门禁跑在旧构建上。

## 迁移重放与 schema 版本断言

- **条件性必须**：新增或修改 SQLite 迁移时，必须执行迁移重放测试（sqlite-store、session-management-store 等），并 grep 全仓 schema 版本断言、同步更新受影响项——不同步断言会使全量测试直接失败。
- **默认**：迁移重放安排在进入全量验证之前完成，让迁移类错误尽早暴露；有明确理由时可调整顺序。

## 快速失败约定（防"动辄数小时"挂起）

端到端与验收脚本禁止无限重试到整测超时的失败方式。点击/填写等动作必须设有限 actionTimeout（动作不可达即报错并留取证快照）；等待真实生成或落库的轮询必须带停滞判死——超过约定静默窗口（覆盖非流式调用超时与重试退避）没有任何落库或模型调用进展，即抛出带"最后在做什么"诊断的错误；页面跳转后先等目标页面就绪信号再操作，不把动作打进正在卸载的旧页面。

## 失败重跑粒度

**默认**：修复端到端或验收失败后，先用 `--last-failed` 或 `--grep` 只重跑失败场景确认修复成立，再按所在级别决定是否回到完整套件；不每改一点就跑全量。有明确理由时可直接运行更大范围测试。

## 后台测试命令落全量日志与显式退出码

后台运行测试/构建时输出重定向到日志文件并在末尾 `echo EXIT=$?`，日志不截断；管道（如 `| tail`）会掩盖退出码。

## 基础设施失败与功能失败分类报告

Playwright 全量失败时，区分「环境/基础设施类失败」（配对码过期、限流、服务器未就绪、超时于非断言步骤）与「断言类失败」（UI 行为、契约、视觉基线失配）；基础设施类失败应标注根因并单独处理，不与功能回归混为一谈。修复基础设施后须以最小复现验证（只跑配对/受影响的单测），再进全量门禁，而非每改一点就跑全量。

## 无图环境的视觉验证

**条件性必须**：任务本身要求视觉验证、但当前环境无法直接渲染图片时，不允许仅记录环境原因后豁免视觉验证，必须使用可验证的替代方式完成，结论写入验证记录。默认方法是逐像素程序化审图（逐桶 diff + 结构探测，差异必须全部落在预期区域）；允许使用能提供等价或更强证据的替代方法。不反复尝试格式转换。

## 确定性假模型响应清单

`apps/web/e2e/helpers.ts` 顶部维护确定性假模型响应形态清单（长文无完成词、普通回答三段式、完成信号用 aria-live 播报等）；编写新 spec 先读该清单，假模型行为变化时同步更新，避免反向读 harness 源码。
