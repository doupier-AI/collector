# Issue Tracker: Local Markdown

本仓库的 PRD 和实施 Issues 使用 `.scratch/` 下的本地 Markdown 文件管理。该约定采用 `setup-matt-pocock-skills` 提供的本地 Tracker 模板，并供本地版本的 `to-issues`、`triage`、`qa` 等 Skill 使用。

## 目录约定

```text
.scratch/<feature-slug>/
├── PRD.md
└── issues/
    ├── 01-<slug>.md
    ├── 02-<slug>.md
    └── ...
```

- 一个功能或里程碑使用一个目录；
- 父 PRD 固定命名为 `PRD.md`；
- 实施任务位于 `issues/`，从 `01` 开始按依赖顺序编号；
- Issue 文件头部使用 `Status:` 记录 Triage 状态；
- Issue 文件头部使用 `Category:` 记录 `bug` 或 `enhancement`；
- Issue 文件头部使用 `Type:` 区分 `AFK` 和 `HITL`；
- Issue 文件头部使用 `Resolution:` 记录 `open`、`completed` 或 `cancelled`，不得占用 Triage 状态表达完成情况；
- 评论和处理历史追加到文件末尾的 `## Comments`，不得覆盖原始需求。

## Skill 术语映射

- “publish to the issue tracker”：在对应 `.scratch/<feature-slug>/` 下创建 Markdown 文件；
- “fetch the relevant ticket”：读取用户给出的 Issue 路径或编号对应文件；
- “apply a triage label”：更新文件头部的 `Status:`；
- “comment on an issue”：追加到 `## Comments`；
- “close an issue”：保持最后一次 Triage `Status:`，把 `Resolution:` 改为 `completed` 或 `cancelled`，并在评论中记录依据；
- 由 `triage` Skill 追加的评论必须以 `> *This was generated by AI during triage.*` 开头。

除非用户明确要求切回远程 Tracker，不调用 GitHub Issues API，也不在 GitHub 创建镜像 Issue。

`.scratch/` 在本仓库中是正式的本地 Issue 数据目录，应纳入版本控制，不应被清理脚本当作临时构建输出删除。
