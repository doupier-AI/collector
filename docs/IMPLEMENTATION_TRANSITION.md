# Collector 实现迁移清单

日期：2026-06-13

状态：临时工程文档。迁移全部完成并通过验收后删除。

## 目的

本文件承接 PRD 2.0 与当前实现之间的差距。产品需求只描述目标体验，不记录历史模块的处置过程。

详细模块处置与实施切片见 `IMPLEMENTATION_GAP_AUDIT.md`；AI 任务状态和输入输出见 `WORKFLOW_CONTRACTS.md`。

## 可继续保留的能力

- Chromium 扩展与桌面采集协议；
- SQLite、本地文件存储和来源定位；
- 文本、Markdown、文本 PDF 和网页解析；
- 模型 Provider、结构化输出校验和 Fake Provider；
- `safeStorage`、本地 API 鉴权和扩展配对；
- token、成本、延迟和失败记录；
- Electron 安全设置与 GUI smoke 基础设施。

## 需要迁移的交互架构

- 将采集、工作台、设置三个 `BrowserWindow` 合并为一个应用壳；
- 用内部视图或路由切换“快速采集、近期收集、专题、全部材料、设置”；
- 全局快捷键切换同一窗口的紧凑采集模式；
- 托盘动作改为导航，不再创建独立窗口；
- 扩展 GUI smoke，覆盖页面切换、紧凑模式和上下文恢复。

## 需要替换的产品主流程

以下模块可以在迁移期保留兼容读取，但不得继续扩展为产品主能力：

- 逐条 Capture 的完整知识抽取；
- `KnowledgeItem` 用户管理界面；
- `RelationSuggestion`、`ReviewProposal` 和 Relation 审核；
- 六类永久语义关系；
- 以 Fragment、AgentRun、证据等级为主的信息架构。

目标闭环为：

```text
原始材料
→ 近期批量分组
→ 用户固化专题
→ 专题整理文档
→ 集中核验与版本更新
```

## 数据迁移原则

- 迁移前保留旧表和历史数据，不执行破坏性删除；
- 新流程使用新的领域表和明确迁移版本；
- 旧知识项和关系只作为历史兼容数据，不自动转成事实；
- 新闭环稳定且数据迁移验证完成后，删除旧界面、写入路径和无用表；
- 原始材料、Artifact、Fragment、AgentRun 和用户设置不得因产品模型变化丢失。

## 完成条件

满足以下条件后删除本文件，并让 PRD 与架构文档成为唯一长期基线：

1. 单窗口应用壳通过 GUI 验收；
2. 原始材料 CRUD 与回收站完成；
3. 近期收集批量工作流完成；
4. 专题创建、材料确认和主文档版本完成；
5. 生成时集中核验与成本监控完成；
6. 旧关系审核界面和写入路径移除；
7. 旧数据迁移、回滚和回归测试通过；
8. `PROGRAM_PLAN.md`、`ARCHITECTURE.md` 与实际行为一致。
