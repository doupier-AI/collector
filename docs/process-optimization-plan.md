## P1 门禁按批次收税，不按票据收税（改 AGENTS.md「全量 Playwright 门禁」条目）

- **现状**：任何合并进 master 的提交先跑一次全量门禁。本次两票 + 一处注释改动共跑 3 次门禁（每票分支各一次 + 注释改动后 master 一次），叠加 3 次构建。
- **改动**：待合票据先在同一集成分支合并 → 集成分支上跑一次全量门禁全绿 → 合 master；纯注释/纯文档/元数据改动（不改变构建产物）豁免门禁，只跑受影响子集并在提交说明标注豁免理由。
- **预期节省**：每次集成少 1–2 次门禁 + 1–2 次构建（约 15–25 分钟）。
- **风险**：豁免粒度需要「改动是否改变构建产物」的判断；建议以 `git diff --stat` 是否含 src/ 与测试文件为界。

## P2 实现前全链冒烟，错误发现时点前置（改 AGENTS.md「分级验证」新增条目）

- **现状**：夹具正文低于阈值空转至判死、迁移断言全量才爆、假模型形态首跑 7 例全挂——三类错误都在实现完成、验证链尾部才暴露。探针先行只覆盖提示词风险，不覆盖夹具与共享资产风险。
- **改动**：任务启动、写第一行业务代码之前，按任务类型跑「5 分钟前置冒烟」：
  - 服务端票：迁移重放 + 受影响单测 + 一条最短 e2e；
  - UI 票：构建 + 受影响组件测试 + 一条最短 e2e；
  - 真实验收票：夹具自检（触发阈值/模型配置/端口）+ 直连探针；
  - 冒烟失败先修前提再实现，冒烟结果随最终验证记录写入提交说明。
- **预期节省**：把「跑 15 分钟才发现前提不成立」变成「开头 5 分钟报错」，每票省 15–40 分钟返工。

## P3 同迭代共享上下文包，消灭并行发现税（新增机制，父会话分派时执行）

- **现状**：并行工作区的代理各自重复发现环境前提（worktree 数据目录、图片不可渲染、假模型形态），T04 未继承 T03 的任何经验。
- **改动**：同一父 Issue 的子票据分派时，父会话生成一份 `<迭代>-agents-context.md`（放 docs/agents/，随迭代归档）：环境前提清单（worktree 数据目录覆盖变量、图片渲染限制、并行端口分配）、假模型响应清单引用、已读 ADR/契约摘要、共享契约包的改动边界（最小增量原则）。分派简报中要求代理「先读共享上下文包，补充自己发现的新前提回写后再开工」。
- **预期节省**：每票省 10–20 分钟环境发现税，且知识随迭代累积而非随会话蒸发。

## P4 机械环节与决策环节分档（分派简报约定，不改 AGENTS.md 规则）

- **现状**：整条任务同一模型档位，机械环节（跑已知命令、等待轮询、grep、迁移重放）与疑难诊断同价烧 token。
- **改动**：父会话分派时按环节拆分或代理内部自判——机械/验证环节用低档（sonnet 或低 effort），设计/决策/疑难诊断（契约设计、焦点类调试、审查）用高档。机械环节占本次 4.3 小时的大头。
- **预期节省**：估计 20–30% token 消耗，不降质量。
- **注意**：门槛是「环节已知与否」——未知行为验证（首次失败诊断）必须高档，不能为省 token 把诊断降档。
