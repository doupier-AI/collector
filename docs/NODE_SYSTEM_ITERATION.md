# 节点系统迭代：产品设计基线

> 状态：讨论中。本文只收录已经确认的产品共识、当前实现差距与明确待确认事项；不代表相关功能已经实现。
>
> 讨论基点：`ui/refresh@30d0c23`，工作分支 `codex/node-system-iteration`。

## 文档目的

本专题重新定义 Collector 的节点系统、研究地图的全局模式、专注模式、跨会话关联与融合。它要解决的不是某一版画布如何排版，而是先固定未来不应随布局反复变化的产品语义：节点是什么、全局范围是什么、搜索返回什么、专注查询包含什么、关系何时成为事实、融合如何追溯，以及删除来源后如何保持诚实。

本文是后续讨论与任务拆分的专题入口。领域词义以 `CONTEXT.md` 为准，难以逆转的决定以 ADR-0022 为准，当前实现状态以 `docs/PROJECT.md` 为准。三者不应把候选方案写成已实现能力。

## 用户问题与产品目标

当前节点系统和现有“专注模式”没有充分表达用户的长期知识结构：地图依赖当前会话，跨会话内容难以同时出现，用户也很难感受到“过去学过的东西正在与现在的新知识汇合”。如果只把更多节点和连线塞进同一张大图，又会迅速产生视觉负担。

目标体验是：

1. 用户通过研究地图的全局模式看见自己了解过的全部内容，而不是只看当前会话。
2. 用户可以搜索任意节点，并准确知道节点内哪一段内容命中了查询。
3. 用户可以从任意节点进入真正的专注模式，回看由该节点生长出的完整思维脉络。
4. AI 主动发现跨时间、跨会话的知识关联，让旧知识在学习新内容时自然重现。
5. 只有有新增认识的关联才升级为融合；融合结果必须能追溯到来源节点和具体内容。
6. 节点、查询、地址和关系语义保持稳定；布局、聚类、视觉编码和动画可以持续替换。

## 领域模型

### 会话与研究节点

- `会话`是管理与生命周期容器，从一个根研究节点开始，可以包含用户显式生长出的多个研究节点。
- `研究节点`是研究地图中的稳定关系对象，也是一个可容纳多轮对话的思路单元。普通追问、改写、总结和话题漂移不会自动拆节点。
- 只有明确的生长动作才创建父子节点。父子关系表达用户的思路如何展开，不要求每个节点保持概念纯净。
- 会话不是知识关系边界。语义关联、关联提示和融合可以跨越不同会话；跨会话是它们的主要使用场景之一。
- 节点的稳定性来自其身份、来源和生长路径，不来自“整个节点只能描述一个概念”。

### 概念、内容定位与卡片

- `语义实体`负责表达稳定的概念身份，并处理同名异义、别名和跨上下文核验。
- `语义范围`负责定位正文中的具体内容，是检索命中、上下文选择和融合证据引用的精确单位。
- `语义卡片`只是正文的可替换呈现结构，不是内容事实源，也不决定搜索、实体识别或融合边界。
- 一个卡片可以包含多个语义范围；一个语义范围也可以跨越卡片呈现边界。布局变化不得改变节点、实体或来源关系。
- 图谱层回答“哪些来源节点支撑了融合”；内容层通过语义范围回答“具体哪段内容支撑了哪条判断”。

### 三种稳定关系与一种候选

| 名称 | 含义 | 是否属于永久图谱 |
| --- | --- | --- |
| 父子关系 | 用户显式生长形成的思路血统 | 是 |
| 语义关联 | 用户明确保留的稳定概念关系 | 是 |
| 融合来源 | 来源节点实际参与形成融合节点的有向事实关系 | 是 |
| 关联提示 | AI 动态发现、尚未被用户保留的候选关系 | 否 |

关联提示可以因模型、索引和上下文变化而重新排序或消失，不能伪装成已经确认的知识事实。用户选择“保留关联”后才形成语义关联；用户确认融合后才创建融合节点及融合来源关系。

## 全局模式

### 数据范围

- 所有未进入回收站的现存研究节点都属于研究地图的全局数据范围与全局搜索范围，包括从未生长过子节点的根节点。
- 归档内容仍属于用户知识范围；是否默认弱化、折叠或由筛选控制属于后续呈现设计。永久删除后的节点不再属于范围。
- “属于全局数据范围”不等于任何缩放层级都必须同时画出所有节点。渲染器可以聚类、裁剪或按需加载，但不能把未呈现误写成不存在。
- 全局查询不以会话作为边界。会话可以作为筛选和来源信息，但不能限制跨会话关系的发现、保存或读取。

这项决定修订 ADR-0002 中“只有显式生长出结构的对话才进入研究地图”的范围约束：显式生长仍是创建父子关系的唯一方式，但不再是节点进入全局模式的资格门槛。

### 稳定关系与候选叠加

全局模式默认以稳定节点和永久关系为事实底层。AI 关联提示属于可叠加的候选层，应与永久关系使用不同的状态和视觉语义；忽略候选不会污染研究地图。

候选何时出现、一次出现多少条、如何排序以及是否随缩放显示仍待设计。这些规则不能反向改变永久关系的含义。

## 专注模式

### 普通节点

以节点 X 进入专注模式时：

- X 及其完整后代生长树构成主体范围。
- X 的祖先路径只用于说明用户如何来到这里，不与后代树争夺主视觉。
- 语义关联、关联提示和融合邻居默认不混入生长树，需要时另行展开。
- 专注模式不是把全局图简单放大，而是一个具有明确范围的节点查询。

### 融合节点

融合节点进入专注模式时，仍以该融合节点及其后代生长树为主体，但其直接来源默认同时可见：

- 直接来源位于独立的`来源层`，不冒充父节点，也不改变生长血统。
- 默认只展示这次融合实际使用的直接来源。
- 用户可以继续展开`来源链`，递归查看更早融合成果背后的原始来源。
- 来源节点自己的整棵生长树不会自动带入，避免专注视图再次膨胀。

服务端或领域查询应分别表达“生长树”“祖先路径”“直接来源”和“可选邻居”。具体画在左侧、外围、背景层还是其他布局中，是可替换的视觉决定。

## 全局搜索

全局搜索采用“节点归并、范围定位”的模型：

- 搜索结果的基本单位始终是研究节点，同一个节点只出现一次。
- 节点内部的多个命中语义范围归并在该结果之下，用于解释为什么命中并提供内容预览。
- 用户可以从某个命中范围打开同一个稳定节点，并定位到对应内容。
- 搜索跨越全部会话，同时覆盖普通节点与融合节点。
- 排序算法、摘要样式和结果布局可以替换，但不能把一个节点拆成大量互不相干的图谱对象。

这解决了两个相反问题：纯片段搜索会重新制造视觉碎片；只返回节点标题又会失去概念级精度。

## 稳定内部节点定位

每个研究节点需要全局唯一、稳定的内部定位，不依赖它当前属于哪个会话，也不依赖图谱布局、坐标、缩放或主题。它支持搜索跳转、来源返回、关联提示、浏览器前进后退和刷新恢复。

节点定位与专注意图分开：

- “打开节点”只定位同一个节点。
- “以该节点专注”额外表达焦点节点和专注查询。
- 具体 URL 形式尚未确定，现阶段不锁定路径语法。
- 本次设计不包含把节点公开分享给其他人的功能，也不引入公开页面、协作权限或外部访问模型。

## 关联与融合

### 从重新发现到形成新知识

AI 需要提供“过去学过的内容与现在的新知识汇合”的记忆强化体验，但发现相似性不等于完成融合：

1. AI 跨会话发现可能相关的节点，形成关联提示。
2. 用户可以忽略提示、保留为语义关联，或继续查看融合提议。
3. 融合提议必须围绕一条自洽的新认识，而不是围绕固定的一对节点。
4. 一项融合可以使用两个或更多来源节点；同一组来源也可能形成多条互不相同的融合提议。
5. 没有新增综合价值时，只保留语义关联，不创建融合节点。
6. 用户确认后，融合结果成为独立节点，并用融合来源关系连接所有直接来源。

AI 自动发现和准备候选不等于自动写入永久图谱。现有默认关闭的自动融合能力是否作为“用户预先授予的高级自动化权限”继续保留，需要在实施规格形成前再次核对；本专题不把候选扫描本身视为永久授权。

### 融合节点的归属

融合节点不是任一来源节点的子节点，也不应因来源节点 ID 顺序而被塞入某个来源会话。确认融合后：

- 融合节点成为新的独立会话根节点，拥有自己的多轮对话、标题、生长树和生命周期。
- 所有来源关系通过有向融合来源边表达，方向为“来源节点 → 融合节点”。
- 来源节点可以位于任意会话；来源会话不会因此获得融合结果的所有权。

### 直接来源与来源链

若 A、B 形成融合 C，之后 C 与 D 形成融合 E：

```text
A ─┐
   ├─→ C ─┐
B ─┘      ├─→ E
D ────────┘
```

- E 的直接来源是 C、D，默认只直接连接 C、D。
- A、B 是 E 的更早来源，可通过展开 C 的来源链看见。
- 不把 A、B、C、D 全部扁平直连 E，因为那会抹掉“先形成 C、再形成 E”的思维演进，并造成连线爆炸。

### 图谱中的来源可见性

融合来源是不可被布局降级掉的产品语义：

- 融合节点必须具有可辨认的视觉身份。
- 直接来源节点与融合来源边必须能与普通语义关联明确区分，不能仅依赖颜色表达。
- 用户必须能识别融合节点由哪些直接来源支撑；选中融合节点后必须展开或高亮全部直接来源。远距离缩放是否允许聚合仍属于待确认的视觉呈现。
- 选中融合节点时，融合节点、直接来源和融合来源边共同高亮，其余图谱弱化；分散在不同区域的来源必须可定位。
- 点击具体融合判断后，应能返回一个或多个来源语义范围；图上的整节点连线不能替代内容级证据。

## 来源删除与证据完整性

当 A、B 形成融合 C，之后 A 被永久删除：

- C 继续存在，因为它是用户确认的独立成果，可能已有自己的对话和后代。
- A 的原文、标题和其他应删除内容不会为了追溯而暗中保留。
- C 的来源链保留不含原文的“来源已删除”标记。
- 依赖 A 的融合判断标记为“来源不完整”，不能继续表现为完全可追溯。
- 系统不自动改写 C，也不因删除 A 连锁删除 C。
- 如果用户希望清除派生成果，需要明确选择包含相关融合成果的清除范围；不能通过普通来源删除静默执行。

回收站阶段如何呈现暂时不可见的来源、恢复后如何解除标记，以及彻底清除派生成果的交互仍待实施规格确认。

## 稳定契约与可替换呈现

| 必须稳定 | 可以替换 |
| --- | --- |
| 节点身份、会话归属与生命周期 | 力导向、分层、时间轴或其他布局算法 |
| 全局模式的数据范围 | 聚类、裁剪、按需加载与缩放细节 |
| 父子、语义关联、融合来源的语义 | 节点形状、尺寸、颜色、线型与动画 |
| 关联提示与永久关系的状态差异 | 候选提示的位置、数量与出现时机 |
| 搜索按节点归并、按语义范围定位 | 搜索排序、摘要文案与结果样式 |
| 专注查询的生长树、祖先、来源与邻居分层 | 专注视图的空间排布和控件形式 |
| 节点内部定位与专注意图分离 | 最终 URL 文本和路由组织方式 |
| 融合的直接来源、来源链与证据缺失状态 | 来源高亮、展开和聚合的具体视觉方案 |

## 关键用户场景

### 场景一：从未生长的旧会话被重新发现

用户两年前单独学习过“词向量”，没有从该根节点生长任何子节点。今天学习“向量数据库”时，旧节点仍属于全局索引；AI 可以给出关联提示。用户忽略提示不会产生永久连线，选择保留才形成语义关联。

### 场景二：节点内存在话题漂移

一个节点先讨论缓存，后来漂移到一致性协议。搜索“一致性协议”只返回该研究节点一次，同时列出命中的语义范围。用户打开结果后直接定位到相关段落，不把每轮对话拆成图谱节点。

### 场景三：跨会话多来源融合

三个不同时期、不同会话的节点共同支持一条新认识。融合提议围绕这条认识组织三个来源，而不是先拆成三个节点对。用户确认后得到新的独立融合会话根节点，全局模式以三条融合来源边连接它们。

### 场景四：专注融合成果

用户以融合节点进入专注模式。主体显示该融合节点和其后续生长树，直接来源默认显示在独立来源层；更早的来源链由用户展开，来源节点自己的后代不自动挤入视图。

### 场景五：删除一个来源

用户永久删除某个来源会话。其他来源和融合成果不被连锁删除；融合节点显示来源缺失和证据不完整。若用户希望连派生成果一并清除，必须再次明确范围。

## 当前实现与目标差距

以下是 `ui/refresh@30d0c23` 的当前实现约束，不是目标产品规则：

| 当前实现 | 已确认目标 |
| --- | --- |
| 融合候选扫描只读取当前节点所在会话的节点 | 候选发现跨越全部会话 |
| 图投影通过 `sessionId` 读取并过滤掉跨会话端点和边 | 全局查询覆盖全部未进入回收站的现存节点和跨会话关系 |
| 融合提议由规范化节点对唯一确定 | 提议围绕一条新综合，可有两个以上来源；同一来源集合可产生多条提议 |
| 融合节点归入节点 ID 排序后某个来源的会话 | 融合节点成为独立会话根节点 |
| 彻底删除来源会话会删除触及其节点的边和提议，并可能删除被归属其中的融合节点 | 保留独立融合成果，删除来源内容并标记来源与证据不完整 |
| 节点页面地址同时依赖 `sessionId` 与 `nodeId` | 节点具有不依赖会话与布局的稳定内部定位 |
| 当前研究地图与候选扫描以会话内入口和投影为核心 | 全局模式与专注查询使用稳定的全局节点语义 |

现有关系存储本身以节点 ID 连接边，没有“必须同会话”的关系约束；限制主要来自候选扫描、图查询、提议模型、融合归属和删除生命周期。实施时需要按完整纵向切片同时调整共享契约、持久化、查询、任务恢复和 WebUI，不能只换一张画布。

## 明确不做

- 不把节点拆成单轮消息或卡片级图谱对象。
- 不要求节点内容围绕单一纯净概念。
- 不让语义卡片成为事实源、实体边界或融合边界。
- 不把会话作为语义关联或融合的边界。
- 不让 AI 候选未经相应用户授权就伪装成稳定事实。
- 不把来源节点扁平复制为融合节点的父子树。
- 不因删除任一来源而静默级联删除独立融合成果。
- 不在本专题加入对外分享、多人协作或公开访问。
- 不提前锁定图谱布局、聚类算法、节点造型和动画。
- 不为开发期研究数据增加兼容分支；数据兼容仍遵守 ADR-0007，除非用户另行明确批准。

## 待确认事项

以下问题尚未形成共同理解，不得当作实现规格：

1. 融合提议在用户确认前必须展示到什么程度：只展示新认识摘要，还是必须同时生成可审查正文、差异、冲突和逐条证据映射。
2. 用户是否可以在创建融合节点前修改提议的结论、来源和证据范围，以及修改后如何重新核验。
3. 确认融合时是否还要额外创建来源节点之间的普通语义关联边，还是只保存融合来源关系。
4. 现有“自动融合”开关在新模型中是保留为高级预授权、改为自动准备草稿，还是退役。
5. AI 关联提示的触发时机、排序、数量上限、过期与冷却规则。
6. 全局模式默认如何聚类、抽稀、加载和筛选；这些决定只能影响呈现，不能改变全局数据范围。
7. 稳定内部节点定位和专注定位最终采用什么路由形式。
