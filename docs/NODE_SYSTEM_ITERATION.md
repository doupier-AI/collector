## 用户问题与产品目标

当前节点系统和现有“专注模式”没有充分表达用户的长期知识结构：地图依赖当前会话，跨会话内容难以同时出现，用户也很难感受到“过去学过的东西正在与现在的新知识汇合”。如果只把更多节点和连线塞进同一张大图，又会迅速产生视觉负担。

研究地图的核心目的不是尽量少画节点，也不是展示技术上的关系数据，而是让用户从不同角度清楚观察节点当前处于什么状态、彼此如何联系，以及思路和融合结果如何形成。全局、专注、搜索、筛选和关系类型都是观察同一套节点事实的方式；它们不能各自生成互相矛盾的节点范围或关系解释。

目标体验是：

1. 用户通过研究地图的全局模式看见自己了解过的全部内容，而不是只看当前会话。
2. 用户可以搜索任意节点，并准确知道节点内哪一段内容命中了查询。
3. 用户可以点选任意节点进入专注模式：完整连通脉络保持正常色彩，其他图谱统一置灰，并通过父子方向回看生长路径与生长树。
4. AI 主动发现跨时间、跨会话的知识关联，让旧知识在学习新内容时自然重现。
5. AI 发现的普通关联保持为临时提示；AI 在内容稳定后独立发现具体新增认识时，才在研究地图 B 面创建临时融合节点，结果必须能追溯到来源节点和具体内容。
6. 节点、查询、地址和关系语义保持稳定；布局、聚类、视觉编码和动画可以持续替换。

## 统一观察系统

全局、专注、搜索和关系筛选不维护彼此独立的图谱。它们以不同观察条件读取同一套节点与关系事实：

- `观察中心`回答当前围绕哪个节点理解脉络；未指定中心时观察全局。
- `观察范围`由项目、时间、归档状态、搜索条件等共同限定。
- `关系角度`由父子、融合来源等一种或多种永久关系表达；关联提示只作为临时候选层叠加。
- `连通脉络`包含从观察中心沿所选关系类型能够到达的全部节点，不设置用户可见的层数或距离上限。
- `状态叠加`表达归档、候选、来源暂不可用或来源不完整等状态，不生成另一套节点事实。

专注模式仍是稳定的产品能力，但它是一套明确的观察规则，而不是另一套数据和画布。一个统一的观察查询应共同计算范围、关系类型与连通脉络，再把自洽的节点和连线结果交给画布、窄屏列表、搜索定位与键盘导航；呈现层不能各自重新解释哪些节点属于当前观察结果。

## 领域模型

### 会话与研究节点

- `会话`是管理与生命周期容器，从一个根研究节点开始，可以包含用户显式生长出的多个研究节点。
- `研究节点`是研究地图中的稳定关系对象，也是一个可容纳多轮对话的思路单元。普通追问、改写、总结和话题漂移不会自动拆节点。
- 只有明确的生长动作才创建父子节点。父子关系表达用户的思路如何展开，不要求每个节点保持概念纯净。
- 会话不是知识关系边界。关联提示和融合可以跨越不同会话；跨会话是它们的主要使用场景之一。
- 项目也不是知识关系边界。项目只整理和筛选会话；跨项目关联提示、融合来源以及会话移动项目前已经存在的来源关系继续有效，不能因分类变化而删除或改写。
- 节点的稳定性来自其身份、来源和生长路径，不来自“整个节点只能描述一个概念”。

### 概念、内容定位与卡片

- `语义实体`负责表达稳定的概念身份，并处理同名异义、别名和跨上下文核验。
- `语义范围`负责定位正文中的具体内容，是检索命中、上下文选择和融合证据引用的精确单位。
- `语义卡片`只是正文的可替换呈现结构，不是内容事实源，也不决定搜索、实体识别或融合边界。
- 一个卡片可以包含多个语义范围；一个语义范围也可以跨越卡片呈现边界。布局变化不得改变节点、实体或来源关系。
- 图谱层回答“哪些来源节点支撑了融合”；内容层通过语义范围回答“具体哪段内容支撑了哪条判断”。

### 与 AI 弱标记的依赖边界

- AI 弱标记是用户发现短概念并发起生长的一种可选入口，不是节点进入研究地图、全局搜索、专注模式、关联提示或融合的资格条件。
- 弱标记、手动选区和深入研究一旦成功创建子节点，节点系统只读取已经保存的节点身份与父子关系；三种入口形成的父子关系在图谱中使用同一种语义和视觉表达。
- 全局搜索、关联提示和融合使用正文版本与语义范围。弱标记识别为空、识别错误或功能暂不可用时，这些主路径仍应独立工作；失败只减少弱标记自身提供的预览与生长机会。
- 当前旧融合候选实现会在概念信号为空时调用词法弱标记检测作为回退信号，这只属于待迁移的实现耦合，不是目标依赖。实施收口必须移除该产品级依赖，并用“弱标记返回空或失败”的回归场景证明节点系统主路径可用。

### 两种稳定关系与一种候选

| 名称 | 含义 | 是否属于永久图谱 |
| --- | --- | --- |
| 父子关系 | 用户显式生长形成的思路血统 | 是 |
| 融合来源 | 来源节点实际参与形成融合节点的有向事实关系 | 是 |
| 关联提示 | AI 动态发现、帮助重新找到旧内容的候选 | 否 |

关联提示可以因模型、索引和上下文变化而重新排序或消失，不能伪装成已经确认的知识事实。用户可以打开相关节点或片段、忽略提示；关联提示本身不触发融合。AI 只有在内容稳定后独立发现具体新增认识，并满足至少两个正式来源实际参与和关键证据可定位时，才另行创建 B 面临时融合节点。用户没有点击或暂时离开只表示候选尚未处理；明确忽略会抑制同一候选，不按固定冷却时间自动恢复，只有新的实质证据明显改变关联理由时才可作为新候选重新出现。

关联提示继续展示“为什么有关”的具体说明，以及两端实际相关的一个或多个语义范围；用户可以从提示返回相关原文。提示不生成永久节点级连线，也不能为了展示内容级依据而把语义范围绘制成独立图谱节点。

关联候选层是动态候选池，不是要求用户清零的永久待办箱。未处理候选在仍有价值时可以继续保留和参与排序；来源内容变化、来源删除、证据失效、价值跌破门槛或更高价值候选替代时可以自动过期。当前不提供把普通关联候选转为永久关系的入口；永久语义关联只有在真实使用证明存在独立价值后才重新审查。

## 全局模式

### 数据范围

- 所有未进入回收站的现存研究节点都属于研究地图的全局数据范围与全局搜索范围，包括从未生长过子节点的根节点。
- 归档内容仍属于用户知识范围，在全局图中默认保留节点与永久关系，但使用较低视觉强度；选中归档节点后恢复正常可读强度并明确显示“已归档”。状态筛选支持“活跃”“已归档”同时多选，也可以只观察其中一种。永久删除后的节点不再属于范围。
- “属于全局数据范围”不等于任何缩放层级都必须同时画出所有节点。渲染器可以聚类、裁剪或按需加载，但不能把未呈现误写成不存在。
- 全局查询不以会话作为边界。会话可以作为筛选和来源信息，但不能限制跨会话关系的发现、保存或读取。

这项决定修订 ADR-0002 中“只有显式生长出结构的对话才进入研究地图”的范围约束：显式生长仍是创建父子关系的唯一方式，但不再是节点进入全局模式的资格门槛。

### Obsidian 视觉参考与规模验证

Obsidian 只作为图谱视觉与动效的参考，不替 Collector 决定数据范围、搜索、筛选、关系类型、融合或加载策略：

- 目标视觉采用由关系自然拉扯形成的有机力导向分布，不沿用当前按深度固定分圈的同心圆画法。
- 节点以轻量圆点为主；标签随缩放弱化，并在靠近、悬停或选中时恢复清晰。
- 悬停节点时临时突出直接关系邻域；选中节点时突出沿启用永久关系可达的完整连通脉络，其余图谱降低明度与饱和度并统一置灰。画布外围控件和说明不争夺主视觉。
- 悬停和选中不强制把目标节点拉到画布中心；已有节点位置在非交互路径下保持稳定。ADR-0042 起，专注触发的直接支撑节点通过显示层力场自然聚拢（退出约 300ms 复原、不写入持久坐标）；用户拖动节点时默认带动最多 180 个三跳内关系节点并按规模自动收窄，同时从 128 世界单位范围动态纳入最多 60 个与当前关系子图无直接边的被动碰撞体（它们在其他关系簇中有边也可参与），总量不超过 240。当前子图因预算被截掉的直接邻居不会被错误降级；被动节点只受斥力、惯性和阻尼，不建立关系弹簧。松手后统一逐帧回弹稳定，Shift+方向键使用同一模型同步结算——这些主动交互是持久坐标的合法来源，但物理接触绝不创建关系，其余路径仍不重排。首次挂载和新增节点只在显示层从持久位置附近柔性展开，永久关系以稳定微曲线呈现，两者均不改变 Map Scene 坐标。
- 只有搜索、来源返回等明确跳转到当前视口外目标时，画布才平滑移动到该节点。新增或删除关系可以让受影响区域局部重新稳定，但已有区域尽量保持位置；整体重新计算布局必须由用户明确触发“重新布局”。
- Collector 的父子关系和融合来源保留不同产品含义，但不要求在默认画布上同时使用两套抢眼的线型和颜色；临时关联提示只在候选观察层出现。
- 有方向的父子关系与融合来源不使用箭头端点。全局图未选择节点时所有永久连线静止；选中节点后，仅当前强调脉络中的父子关系与融合来源线沿“来源 → 结果”方向缓慢流动，悬停具体连线时方向进一步清晰。临时关联提示不使用永久关系的方向语法。
- 用户启用“减少动态效果”时，方向线改用起点较淡、向终点逐渐清晰的静态渐变；悬停或选中说明仍明确写出关系起点和终点，方向不能只依赖动画感知。
- 普通节点使用轻量实心圆点；融合节点保持相同视觉尺度，只使用空心圆环或圆点外的一圈细环作为常驻标识，不增加醒目颜色、动画或额外尺寸。选中后才显示“融合结果”说明并突出直接来源。
- 当前没有数百或数千节点的性能基线，也没有证据证明未来全局模式打开时必然变慢。视觉聚合、渐进加载或其他规模优化只有在代表性数据测量证明需要后才能决定，不能由未经验证的性能假设反推产品行为。

### 信息分层

节点信息不能全部塞入选中后的详情面板。画布、悬停和面板分别承担不同层次：

- `画布扫读层`使用有限的形状、颜色、透明度、角标和动效，让用户不打开面板也能观察高频状态；每种视觉通道只承担一种稳定含义，避免同一个颜色同时表示项目、节点类型和证据状态。
- `悬停与键盘焦点层`把视觉编码解码成准确文字，并临时补充项目、状态、关系起止点等信息；颜色、形状和动画都不能成为理解含义的唯一方式。
- `选中信息层`只承载确实需要阅读的内容、当前节点特有的解释和明确动作，不复制画布已经能表达的所有状态，也不变成缩小版节点详情页。

当前采用以下完整但可替换的视觉语法：

| 信息 | 主要视觉资源 | 精确解码位置 |
| --- | --- | --- |
| 所属项目 | 节点色相；创建项目时从产品项目色板自动分配稳定颜色，未分类使用中性色。产品方向允许后续修改，但 T05/#64 不提供手动改色入口或接口，该能力仍未交付 | 悬停/键盘焦点显示项目名称 |
| 普通或融合节点 | 普通节点为轻量实心圆点；融合节点为同尺度空心圆环或圆点外细环 | 悬停/选中明确写“普通节点”或“融合结果” |
| 活跃或归档 | 归档节点保留项目色相但降低饱和度；不使用透明度，避免与当前观察范围弱化混淆 | 悬停/选中明确写“已归档” |
| 当前观察主次 | 选中节点使用克制的外部光晕，当前连通脉络保持正常色彩与明度，未连通内容降低明度和饱和度并统一置灰 | 选中状态、范围归属说明 |
| 是否存在关联候选 | 节点旁的单个微型卫星点；零候选不显示，默认不常驻数字，远距离缩放时可以随标签一起收起 | 悬停/选中显示准确候选数量；点击卫星点进入该节点的候选观察 |
| 融合证据健康 | 融合圆环连续表示完整；局部虚化表示来源暂不可用；明确缺口表示来源不完整 | 悬停/选中说明受影响来源与判断 |
| 关系方向 | 默认线条静止；选中脉络中的父子和融合来源线按语义方向缓慢流动 | 悬停/选中显示关系类型、起点与终点 |
| 键盘焦点 | 使用独立的产品焦点环，不借用项目颜色、融合圆环或证据缺口 | 屏幕阅读器名称与关系说明 |

悬停与键盘焦点信息只负责精确解码，不承载完整正文。点选节点已经进入专注，不再提供重复的“进入专注”动作；选中信息卡只显示节点标题、最多两行内容预览、当前必须处理的异常说明和“打开节点”。关系类型、项目、归档、候选数量和常规证据状态已经由画布与悬停表达，不在卡片中重复铺成字段列表。

以上是当前视觉设计，不属于不可替换的领域契约。视觉资源可以根据真实使用反馈重新分配，但项目归属、节点角色、归档、候选和证据健康等事实不能随样式改变。项目色板实施前必须先在产品取色板与主题令牌中登记浅色/深色配对，不在画布代码中临时生成散落颜色；自动分配优先使用当前最少占用的项目色，项目改名不改变颜色。

### 筛选范围与跨范围关系

项目、时间和归档状态等筛选定义当前主要观察范围，但不能把跨范围永久关系伪装成不存在或截断真实连通路径：

- 当前范围内的节点正常呈现，范围外节点默认不完整铺开；跨出范围的永久关系以边界提示保留。
- 用户选中范围内节点后，完整连通脉络可以经过一个或多个范围外桥接节点，再连接到范围内的其他节点。桥接节点与路径继续显示，但必须弱化并明确标记其项目或其他范围归属。
- 例如只观察项目一时，若 A（项目一）— B（项目二）— C（项目一），选中 A 后仍保留 A—B—C：A、C 正常突出，B 作为跨项目桥接节点弱化显示。
- 临时展开不会取消筛选，也不会改变节点的项目、会话或其他归属。
- 选中融合节点且“融合来源”关系启用时，全部直接来源必须进入连通脉络；范围筛选不能截断这些来源。用户关闭“融合来源”后，直接来源按未命中关系处理并置灰。
- 普通全局搜索仍可返回范围外结果，但范围内结果正常突出，范围外结果单独分组或弱化。

### 稳定关系与候选叠加

全局模式默认以稳定节点和父子、融合来源两类永久关系为事实底层。关联提示属于可叠加的动态候选层，应与永久关系使用不同的状态和视觉语义；暂未处理的有效候选仍可在关联候选层查看，明确忽略的候选进入抑制状态，两者都不会污染研究地图。

- 默认图谱不绘制候选节点与候选连线，工具区只提示当前观察范围内的候选数量。
- 用户主动开启“候选”观察角度后，候选节点与连线进入强调层，永久节点与关系保留但整体弱化。
- 每条候选必须明确标记“临时提示”，并提供查看理由、打开相关节点或片段和忽略；不提供进入融合或主动建边的入口。
- 关闭候选观察后立即恢复永久关系视角；候选的出现与消失不改变任何永久关系事实。

关联提示在当前回答完成、内容稳定后再评估，不打断正文生成和阅读。当前学习过程一次最多突出一条最有价值且理由可回溯的候选，其余有效发现留在关联候选层。排序优先考虑候选能否帮助重新找到旧内容，或补充、纠正、对比和扩展当前认识，而不是只按字面或语义相似度排列；具体评分公式和价值门槛可以迭代，但不能把候选表现成永久关系。

### 节点选择与关系类型筛选

- 全局图尚未选择节点时，显示全部永久关系，但统一使用极细、低透明度的中性单线，不通过常驻颜色、线型或粗细同时编码关系类型。
- 用户选择一个节点后，系统立即突出从该节点沿全部永久关系类型可以到达的完整连通脉络，不要求用户先选择关系类型，也不要求用户设置观察层数。
- 当前选中节点最突出，连通脉络保持可读；与它不连通的其他区域弱化。用户可以悬停连线查看关系说明，或继续选择下一个节点循线观察。
- 产品不提供关系层数或距离设置。若代表性规模测量证明需要分批加载、聚合或裁剪，这些属于内部呈现与性能策略，不能改变“全部可达节点属于当前连通脉络”的产品语义。
- “父子关系”“融合来源”两个永久关系筛选项默认全部选中，并支持同时选择一个或多个类型；关联提示由独立的候选观察角度控制，不混入永久关系筛选。
- 用户改变筛选后，统一观察查询沿所选关系类型重新计算当前关系路径；多种已选关系可以共同组成混合路径，不要求整条路径只能使用同一种类型。
- 父子关系与融合来源的方向负责解释关系含义，不限制浏览方向。连通判断允许从关系两端进入：用户可以从来源看到结果，也可以从结果沿同一条线回看来源；线条流动方向始终保持原语义。
- 符合所选关系路径的节点和连线增强，未命中的永久节点和关系只弱化而不隐藏；关系类型筛选不能制造“未选关系已经不存在”的错觉。重新全选后恢复完整关系邻域的同等强度。
- 同一对节点即使同时存在多种关系，画布也始终只画一条连接线，不使用平行线、双线或混合线型叠加。悬停或选中连接线时再展示它包含的关系类型。
- 悬停或选中有方向的连接线时，关系说明同时明确写出起点与终点；流动动画负责快速感知方向，文字负责准确解释关系。
- 关系筛选命中这条连接所包含的任一类型时，连接线进入当前强调路径；它包含的类型全部未被选择时仍保留为弱化背景。数据层始终分别保留每条关系事实。
- 筛选只是当前观察方式，不删除或改写关系事实，也不改变节点的父子血统、来源或会话归属。

### 沿线探索

- 悬停节点只临时增强它直接连接的线与邻居标签，帮助用户判断下一步往哪里看，不改变当前观察中心。
- 单击节点把它设为新的观察中心，地图保持同一画布实例打开，并沿用当前关系类型、范围和状态筛选；请求期间继续显示当前现场，只呈现局部更新状态，不切换整页骨架或重播入场动画。
- 双击节点、按 Enter 或使用明确的“打开节点”动作才进入节点正文，避免沿线查看时意外离开地图。
- 当前一次地图打开期间保留临时观察历史，用户可以从 A → B → C 逐步返回先前观察节点；关闭地图后无需把这条浏览路径保存为知识关系或长期历史。

### 图谱与节点页导航

图谱负责观察关系，节点页负责完整阅读和对话。打开节点后进入完整节点页，不长期保留“图谱 + 完整正文”的并排布局；这避免压缩阅读空间，也避免让一张选中信息卡膨胀成第二套节点页。

- `/map` 是全局图谱观察入口。
- `/map/focus/:nodeId` 明确表示“以这个节点进入专注模式”。
- `/nodes/:nodeId` 是不依赖会话归属的稳定节点正文入口。移动会话、移动项目或跨会话融合不会改变节点地址。
- 从图谱打开节点时，导航层保存本次图谱观察快照；浏览器返回或节点页的“返回图谱”恢复打开前的节点位置、缩放和平移、观察中心、范围与关系筛选、状态叠加以及本次临时观察历史。
- 图谱现场属于当前浏览过程的临时状态，不编码成冗长 URL，也不写成节点或关系事实。直接打开或刷新稳定节点地址仍能独立读取节点；没有来源快照时，“在图谱中查看”以该节点进入专注模式。
- 页面、搜索、来源返回和画布只调用统一导航意图，不自行拼接会话编号、路由或快照。现有依赖 `sessionId` 的节点地址在迁移期只负责转向稳定节点地址。

“返回时恢复现场”适用于同一浏览标签页中的当前导航记录；它不承诺跨设备、跨浏览器或清除本地状态后恢复像素级布局。节点与专注意图稳定，临时画布位置不是需要长期同步的知识数据。

## 专注模式

专注模式是同一张全局地图的视觉聚焦状态，不是独立树形画布。以节点 X 进入专注时：

- X 最突出；从 X 出发，沿当前启用的父子关系与融合来源能够到达的全部节点和连线保持正常色彩与明度。
- 连通判断允许从关系两端进入，也允许两种关系共同组成混合路径；产品不提供层数或距离设置。
- 与 X 不连通的节点和连线继续留在原位置并保持可交互，但统一降低明度和饱和度，成为灰色背景。
- 点选任意灰色节点会把它设为新的观察中心；进入、切换和退出专注均不强制移动视口，也不持久改变节点位置（专注触发的支撑节点聚拢为 ADR-0042 显示层力导向预览，退出即复原）。
- 父子关系仍以“父 → 子”的结构、方向流动和路径强调表现生长路径与生长树；生长树不再决定画布排版。
- 关系筛选改变后重新计算完整连通脉络，但保持布局、缩放和平移。所有永久关系都关闭时，只有 X 保持突出，其余图谱置灰。
- 选中融合节点且启用“融合来源”时，全部直接来源进入正常连通脉络；关闭该关系后，来源节点仍在画布上但按未命中内容置灰。更早来源链通过继续沿融合来源关系观察，不建立独立来源层。
- 置灰只表示“当前不在专注脉络”，归档、融合身份、来源暂不可用、来源不完整和键盘焦点继续通过形状、标识、文字、读屏名称与焦点环表达。

服务端统一观察查询应直接返回焦点、完整连通脉络和未连通背景的自洽结果。画布、窄屏列表、搜索定位与键盘导航不得各自重新计算专注范围。

## 全局搜索

全局搜索采用“节点归并、范围定位”的模型：

- 搜索结果的基本单位始终是研究节点，同一个节点只出现一次。
- 节点内部的多个命中语义范围归并在该结果之下，用于解释为什么命中并提供内容预览。
- 用户可以从某个命中范围打开同一个稳定节点，并定位到对应内容。
- 搜索跨越全部会话，同时覆盖普通节点与融合节点。
- 当前图谱筛选范围是搜索的主要结果范围，范围内结果正常突出；范围外结果仍可返回，但必须单独分组或视觉弱化，不能与范围内结果混为同等优先级。
- 排序算法、摘要样式和结果布局可以替换，但不能把一个节点拆成大量互不相干的图谱对象。

这解决了两个相反问题：纯片段搜索会重新制造视觉碎片；只返回节点标题又会失去概念级精度。

## 稳定内部节点定位

每个研究节点需要全局唯一、稳定的内部定位，不依赖它当前属于哪个会话，也不依赖图谱布局、坐标、缩放或主题。它支持搜索跳转、来源返回、关联提示、浏览器前进后退和刷新恢复。

节点定位与专注意图分开：

- “打开节点”使用 `/nodes/:nodeId`，只定位同一个节点并进入完整正文。
- “以该节点专注”使用 `/map/focus/:nodeId`，额外表达焦点节点和专注查询；全局观察入口为 `/map`。
- 路由只表达稳定导航意图，图谱位置、缩放、筛选和临时观察历史由导航层的观察快照恢复，不成为节点身份的一部分。
- 本次设计不包含把节点公开分享给其他人的功能，也不引入公开页面、协作权限或外部访问模型。

## 关联与融合

### 从重新发现到形成新知识

AI 需要提供“过去学过的内容与现在的新知识汇合”的记忆强化体验，但发现相似性不等于完成融合：

1. 当前回答完成且内容稳定后，AI 自主检查跨时间、跨会话的正式知识；用户搜索、询问、对比、打开旧节点或明确要求“融合”都不触发该流程。
2. 只发现内容相关时形成关联提示；没有具体新认识或关键证据不可定位时不创建节点。
3. 当至少两个正式来源共同形成一条具体、自洽且有可定位证据的新认识时，AI 自动创建 B 面临时融合节点。一项融合可以使用两个或更多来源，同一组来源也可以形成多条不同候选认识。
4. 临时融合节点保存可审查的完整内容：核心认识、来源、差异或冲突，以及判断与证据的对应关系；创建过程不打断当前学习。
5. 用户可以在临时融合节点内继续普通对话、查看证据和明确修改；询问与讨论不自动改写当前内容。
6. 用户确认一个已核验的具体版本后，同一个节点从 B 面原位进入 A 面；确认只改变状态，该版本、实际采用的来源和证据范围原样成为固定的正式融合成果，核验通过的候选来源连接转为正式融合来源。

AI 自动发现和准备候选不等于自动写入永久知识结构。产品不提供用户主动触发融合的入口，也不提供 AI 直接创建 A 面永久融合节点的预授权模式；达到门槛的候选由 AI 自动进入 B 面，只有用户确认后才进入 A 面。

### 临时融合节点与研究地图 B 面

研究地图以 A 面正式知识为底图，以 B 面临时融合为透明覆盖层；两者共享同一画布与空间位置，不维护两套互相独立的图谱：

- A 面包含普通研究节点、正式融合节点和永久关系；临时融合节点不在 A 面绘制，只通过 B 面入口和总数提示其存在。
- B 面显示临时融合节点和候选来源连接，A 面来源节点保留为只读背景。打开或关闭 B 面不重新排列 A 面节点，不改变位置、缩放、观察中心和筛选现场。
- 临时融合节点具有稳定身份、完整正文和普通对话；允许原地查看证据或返回来源原文，不能生长子节点、不能作为其他融合来源、不属于项目、没有归档状态。
- 候选来源连接只存在于 B 面，连接实际参与草拟的 A 面来源及具体语义范围，不进入永久连通脉络。删除临时节点时一并删除；确认时只有最终采用且核验通过的连接转为正式融合来源。
- B 面开启时，A 面搜索、筛选、节点选择、观察中心切换、沿线探索和专注入口全部关闭。B 面复用 A 面相同的图谱搜索体验，但搜索临时融合节点；集中列表负责浏览、定位、单独和批量删除，不另建列表搜索。
- 原地展开来源证据仍停留在 B 面；打开来源正文则退出 B 面进入 A 面正式节点，返回后恢复原临时节点、视口、搜索条件和列表位置。
- AI 自动创建临时节点时不插入消息、不弹窗、不自动切换 B 面，只更新入口中的临时节点总数；数量不区分已读、未读、待审或搁置。
- 临时节点不会按时间或系统判断自动删除。用户单独或批量删除时，不进入回收站，只删除临时节点和候选来源连接，不影响 A 面来源。
- 批量选择以当前完整列表结果为范围：存在搜索条件时，“全选”只选择全部搜索结果；搜索条件为空时才选择全部临时融合节点。选择范围不受当前滚动位置、分页或界面是否已经渲染对应条目影响，界面必须明确显示实际选中数量。
- 批量删除确认前允许用户从所选节点标题原地打开只读内容预览，查看该节点的完整最新草案、来源和证据状态；关闭预览后返回同一删除确认现场，保留原搜索范围和选择状态。临时预览不退出 B 面，不触发编辑、确认融合或其他节点状态变化。
- 普通批量删除经过一次内容与范围复核即可执行；只有搜索条件为空且选中 B 面全部临时融合节点时，视为清空整个 B 面，用户必须额外输入“删除全部”才能执行。不按固定节点数量设置另一套高风险门槛。
- 系统阻止重试和刷新导致的确定性重复，并尽力识别高置信语义重复；无法根本避免重新发现同一概念。不确定时允许候选并存，不自动合并、覆盖或改写，集中列表与批量删除承担最终整理。

### 融合草案、对话修改与确认

融合草案由 B 面临时融合节点承载，不是生成最终内容之前的一段预告。用户在确认前已经看到并审查最终会成为固定正式成果的内容：

- 草案包含核心认识、参与来源、来源之间的一致、差异或冲突，以及关键判断与一个或多个语义范围的证据对应。
- 用户确认一个具体草案版本后，系统只把同一个临时融合节点从 B 面提升到 A 面；确认时不重新生成、不自动扩写，也不改变措辞侧重点。
- 正式融合节点的固定正文与被确认版本一致。临时节点身份、地址和位置保持不变；确认后的普通追问保留在该节点的后续对话中，显式生长仍可创建子节点，但任何行为都不反向改写已确认的融合正文、直接来源或证据对应。
- 草案修改由 AI 通过对话完成。框选内容后给出意见表示范围明确的定向修改；直接在对话框给出意见表示基于整份草案与上下文的普通对话式修改。
- 只有“改写这段”“删除来源 B”等明确修改意图才产生新草案版本；询问、讨论或意图不明的消息只回答或追问，不擅自改变草案。
- B 面只突出最新草案版本，同时提供轻量的变化查看与撤销能力；最终确认记录绑定被确认的具体草案版本。
- 只改变语气、排版或不改变含义的措辞时，核验状态保持。改变核心判断、增删来源或调整证据时，只重新核验受影响判断；核验完成前可以继续讨论和修改，但不能确认融合。
- 来源暂不可用、来源被删除或关键证据不足时，临时节点仍可查看和对话，但不能确认；系统不为促成转正而自动删除有问题的判断或来源。

### 确认后的融合固定

正式融合节点表达用户在一个具体时点确认的独立研究成果，不是跟随来源持续变化的实时汇总视图：

- 确认后的融合正文、直接来源集合以及判断与证据范围的对应永久固定，不再产生“当前版本”或确认后的修订版本。
- 来源节点后来新增内容、产生新正文版本或继续生长时，不自动扩展、替换、重新核验或改变既有融合成果，也不提示该成果吸收新证据。既有证据继续绑定确认时实际采用的来源正文版本和语义范围。
- 来源进入回收站或被彻底删除时，只按既有来源可用性规则改变追溯状态；融合正文不随之改写。彻底删除后的原文不得为维持证据而暗中保留。
- 正式融合节点仍保留普通多轮对话、显式生长、项目归属、归档和删除等独立会话能力，但这些状态与后续内容不改写被确认的融合成果。
- 后来出现补充、纠正或替代性综合时，系统创建新的 B 面临时融合节点；既有正式融合节点可以作为新综合的来源。用户若不再认可旧成果，使用其独立生命周期明确归档或删除，而不是原地覆盖。

这项固定边界把知识演化表达为多个可追溯成果之间的继续融合，而不是在同一个成果内部反复改写历史。

### 矛盾成果不建立专门管理系统

同一问题上的临时或正式融合成果可以独立并存。当前 MVP 不引入专门的矛盾状态、矛盾关系、冲突标签、自动消解流程或专用比较界面：

- 系统不自动选择胜者，不合并、覆盖、降级或改写任何既有正式融合成果。
- 仅仅检测到两个成果表达不同或相反结论，不触发新融合，也不生成新的永久关系或待办状态。
- 后来确实形成一项能够解释、取舍或调和矛盾的具体新认识，并满足普通融合的多来源与可定位证据门槛时，才创建新的 B 面临时融合节点；既有正式融合成果可以作为其来源。
- 用户仍通过普通搜索、来源查看以及各成果自身的归档或删除能力处理不再需要的内容，不增加另一套矛盾管理入口。

这项收缩保留现实知识可以并存甚至冲突的事实，同时避免融合系统再次承担判断真理、维护冲突状态和同步旧成果的责任。

### 融合节点的归属

融合节点不是任一来源节点的子节点，也不应因来源节点 ID 顺序而被塞入某个来源会话。确认融合后：

- 融合节点成为新的独立会话根节点，拥有自己的多轮对话、标题、生长树和生命周期。
- 所有来源关系通过有向融合来源边表达，方向为“来源节点 → 融合节点”。
- 来源节点可以位于任意会话；来源会话不会因此获得融合结果的所有权。
- 全部直接来源属于同一项目（包括全部未分类）时，融合会话默认沿用该项目；直接来源跨越多个项目或同时包含项目内与未分类来源时，默认进入“未分类”。确认融合时显示该默认归属并允许用户修改；之后移动融合会话也不改变来源边或证据关系。
- 多个来源共同形成融合节点，只证明它们分别参与支撑这条新综合，不证明来源节点彼此之间存在另一条适用于整个节点的永久关系；确认融合只创建来源节点指向融合节点的融合来源边。

### 直接来源与来源链

若 A、B 形成融合 C，之后 C 与 D 形成融合 E：

```text
A ─┐
   ├─→ C ─┐
B ─┘      ├─→ E
D ────────┘
```

- E 的直接来源是 C、D，默认只直接连接 C、D。
- A、B 是 E 的更早来源，可通过展开 C 的来源链看见。
- 不把 A、B、C、D 全部扁平直连 E，因为那会抹掉“先形成 C、再形成 E”的思维演进，并造成连线爆炸。

### 图谱中的来源可见性

融合来源是不可被布局降级掉的产品语义：

- 融合节点必须具有可辨认但低负担的视觉身份：与普通节点保持相同尺度，以空心圆环或圆点外细环区分；不依赖醒目颜色、动画或放大尺寸。
- 直接来源节点与融合来源边必须能与父子关系及临时关联提示明确区分，不能仅依赖颜色表达。
- 用户必须能识别融合节点由哪些直接来源支撑；选中融合节点后必须展开或高亮全部直接来源。远距离缩放是否采用聚合由代表性规模测量决定，但聚合不能使直接来源无法定位或把来源事实表现成不存在。
- 选中融合节点时，融合节点、直接来源和融合来源边共同高亮，其余图谱弱化；分散在不同区域的来源必须可定位。
- 点击具体融合判断后，应能返回一个或多个来源语义范围；图上的整节点连线不能替代内容级证据。

## 来源删除与证据完整性

当 A、B 形成融合 C，之后 A 所在会话进入回收站：

- A 暂时离开普通全局图和搜索范围。
- C 继续存在，来源位置显示弱化的“来源在回收站”占位；依赖 A 的判断标记为“来源暂不可用”，不提前标为永久性的“来源不完整”。
- 恢复 A 所在会话后，原有来源边、来源链和证据引用自动恢复，不重新生成或重新确认融合内容。

当 A 随后被用户彻底删除或到期自动清理：

- C 继续存在，因为它是用户确认的独立成果，可能已有自己的对话和后代。
- A 的原文、标题和其他应删除内容不会为了追溯而暗中保留。
- C 的来源链保留不含原文的“来源已删除”标记。
- 依赖 A 的融合判断标记为“来源不完整”，不能继续表现为完全可追溯。
- 系统不自动改写 C，也不因删除 A 连锁删除 C。
- 永久删除确认默认只删除当前来源，同时列出会直接变为“来源不完整”的融合节点，并提示更深来源链中受影响的数量。
- 产品不提供“一键删除全部派生成果”。如果用户希望继续清除，必须进入独立审查界面，明确选择每个待删除的融合节点；可以一次确认多个已选择项，但不能由系统替用户自动扩大范围。
- 删除某个已选择的融合节点等同于删除它的独立会话；确认前必须同时提示该会话自身的后代也会被删除。

普通来源删除不能静默扩大为派生成果删除；影响告知与派生成果审查是两个独立步骤。

## 关键用户场景

### 场景一：从未生长的旧会话被重新发现

用户两年前单独学习过“词向量”，没有从该根节点生长任何子节点。今天学习“向量数据库”时，旧节点仍属于全局索引；用户感觉熟悉时可以通过全局搜索找到旧节点及命中片段，AI 也可以主动给出关联提示。用户可从提示返回相关原文；明确忽略后，同一理由不会定时再次打扰，除非后来出现新证据。没有形成新增认识时，提示不会留下永久连线。

### 场景二：节点内存在话题漂移

一个节点先讨论缓存，后来漂移到一致性协议。搜索“一致性协议”只返回该研究节点一次，同时列出命中的语义范围。用户打开结果后直接定位到相关段落，不把每轮对话拆成图谱节点。

### 场景三：跨会话多来源融合

三个不同时期、不同会话的节点共同支持一条新认识。融合提议围绕这条认识组织三个来源，而不是先拆成三个节点对。用户确认后得到新的独立融合会话根节点，全局模式以三条融合来源边连接它们。

### 场景四：专注融合成果

用户点选融合节点进入专注模式。地图保持原位置；在“融合来源”和“父子关系”都启用时，该融合节点、全部可达来源、后续生长节点以及由两种关系共同连接的完整脉络保持正常色彩，其他区域置灰。关闭“融合来源”后，系统在原布局上重新计算范围，融合来源不再高亮但仍作为灰色背景可见。

### 场景五：来源进入回收站后恢复或删除

用户把某个来源会话移入回收站。融合成果继续存在，来源位置显示“来源在回收站”，相关判断暂不可用；恢复会话后原关系与证据自动恢复。如果用户彻底删除该会话，融合节点改为显示来源缺失和来源不完整。删除确认告知直接与更深层影响，但默认不删除融合成果；若用户希望继续清除，必须进入独立审查并逐项选择。

## 当前实现与目标差距

以下是 `ui/refresh@30d0c23` 的当前实现约束，不是目标产品规则：

| 当前实现 | 已确认目标 |
| --- | --- |
| 项目记录只有名称和时间字段，图谱节点没有稳定项目颜色 | 项目增加可持久化的色板角色；创建时自动分配、用户可修改、改名不变，浅色与深色主题使用成对令牌 |
| 当前画布以三套高饱和颜色和线型常驻区分关系，节点状态信息主要依赖单一节点样式 | 默认关系统一为极淡中性单线，选中后用方向流动与悬停文字解码；项目、节点角色、归档、候选和证据健康分别使用不冲突的视觉资源 |
| 当前图投影不提供项目色、候选数量或融合证据健康摘要 | 统一观察结果提供画布扫读所需的最小派生摘要；完整正文和候选详情仍按需读取，不塞入图投影 |
| 当前候选记录可以“保留关系”，接受后创建只有类型和两端节点的 `semantic-related` 边 | 目标关联提示只负责重新发现和来源返回，不触发融合，也不升级为永久关系；现有边的停止写入、已有数据处理和界面收口属于后续工程迁移 |
| 服务端先按全部关系和固定深度生成投影，关系类型主要由各前端呈现器事后隐藏 | 统一观察查询共同计算观察中心、范围、关系类型、完整连通脉络与状态，所有呈现消费同一结果；用户不管理遍历深度 |
| 当前专注脉络受 `maxDepth` 限制，画布按深度分圈并在模式间切换呈现 | 专注保持全局有机布局，完整连通脉络正常着色，未连通图谱原位置灰；点选和关系筛选不触发整体重排 |
| 融合候选扫描只读取当前节点所在会话的节点 | 候选发现跨越全部会话 |
| 图投影通过 `sessionId` 读取并过滤掉跨会话端点和边 | 全局查询覆盖全部未进入回收站的现存节点和跨会话关系 |
| 融合提议由规范化节点对唯一确定 | 提议围绕一条新综合，可有两个以上来源；同一来源集合可产生多条提议 |
| 融合节点归入节点 ID 排序后某个来源的会话 | 融合节点成为独立会话根节点 |
| 彻底删除来源会话会删除触及其节点的边和提议，并可能删除被归属其中的融合节点 | 保留独立融合成果，删除来源内容并标记来源与证据不完整 |
| 节点页面地址同时依赖 `sessionId` 与 `nodeId` | 节点具有不依赖会话与布局的稳定内部定位 |
| 当前地图是页面上的临时覆盖层，进入节点会丢失地图现场 | 全局地图成为独占视口的稳定导航入口，以桌面左侧/窄屏底部边缘工具坞承载功能；打开节点进入完整正文，返回时在同一画布恢复当前标签页中的布局、视口、观察条件和临时路径 |
| 当前研究地图与候选扫描以会话内入口和投影为核心 | 全局模式与专注查询使用稳定的全局节点语义 |
| 当前旧融合候选在概念为空时复用词法弱标记检测作为回退信号 | 目标搜索、关联提示与融合只依赖正文版本、语义范围和相应核验；弱标记缺失或失败不阻断节点系统 |

现有关系存储本身以节点 ID 连接边，没有“必须同会话”的关系约束；限制主要来自候选扫描、图查询、提议模型、融合归属和删除生命周期。实施时需要按完整纵向切片同时调整共享契约、持久化、查询、任务恢复和 WebUI，不能只换一张画布。

## 明确不做

- 不把节点拆成单轮消息或卡片级图谱对象。
- 不要求节点内容围绕单一纯净概念。
- 不让语义卡片成为事实源、实体边界或融合边界。
- 不把会话作为关联发现或融合的边界。
- 不让 AI 候选未经相应用户授权就伪装成稳定事实。
- 不在缺少真实价值证据时把普通关联提示升级为永久图谱关系，也不增加用户主动建边入口。
- 不把来源节点扁平复制为融合节点的父子树。
- 不因删除任一来源而静默级联删除独立融合成果。
- 不在本专题加入对外分享、多人协作或公开访问。
- 不提前锁定图谱布局、聚类算法、节点造型和动画。
- 不为开发期研究数据增加兼容分支；数据兼容仍遵守 ADR-0007，除非用户另行明确批准。

## 产品决策框架

本轮产品决策按下列顺序完成；已经确认的内容不因换到相邻场景而重复提问。

### A. 知识对象与尺度——已完成

- 会话、研究节点、语义实体、语义范围和语义卡片的职责边界。
- 节点允许多轮对话与话题漂移，不自动拆分。
- 搜索、关联提示和融合使用语义范围，卡片只负责呈现。

### B. 永久关系的形成与维护——已通过收缩完成

- AI 发现的普通关联保持为临时提示，只用于帮助用户重新找到旧节点或片段；融合由 AI 在内容稳定后另行判断，不由关联提示引导或触发。
- 用户感觉熟悉且知道大致线索时，首要路径是全局搜索与语义搜索；当前不增加主动建立永久语义关联的入口。
- 普通关联提示不再升级为永久图谱关系。父子关系与融合来源是当前已确认的两种永久关系。
- 永久语义关联暂不进入当前产品，只保留为候选概念；只有真实使用证明用户需要长期保存并反复回看“尚未形成融合的联系”时，才重新讨论主动建立、修正、解除与同节点对多项判断。
- 当前代码中的 `semantic-related` 仍是已实现现状，尚未迁移；本次只完成产品收缩，不代表功能代码已经改变。
