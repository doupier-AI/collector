# 工程协作与验证

本文件只在实施、构建、测试、并行开发或合并时读取。产品边界见 `docs/product/`，技术依赖见 `docs/ARCHITECTURE.md`。

## 任务入口

实施前，当前任务上下文必须能独立回答：目标用户结果、明确不做项、不可破坏规则、依赖与基线、允许改动面、验收和验证命令。单会话、串行、低风险任务不补建任务文件或 GitHub Issue；只有跨会话、并行、长期阻塞、外部参与、真实缺陷、发布、安全、迁移或用户明确要求时才使用 Issue。

任何实施任务在第一次写文件、安装依赖、启动服务或运行测试前，必须先向用户给出一次简短的验证预告，包含验证等级、计划命令或覆盖范围、是否包含浏览器/完整回归，以及预计总耗时。预告用于建立时间预期，不是普通实现步骤的审批请求；范围扩大或预计耗时明显增加时，在新增验证前更新预告。

Issue 只保存一张稳定任务卡、当前真实阻塞和最终证据，不维护过程日志或未来任务树。并行任务卡还要声明占用的产品能力、接口/数据/核心模块/测试设施、计划分支和集成依赖。产品边界变化更新主责模块契约；普通实现取舍进入代码、测试和提交。决策记录仍只用于跨模块、难逆转且存在真实替代方案的决定。

## 工作区与领取

- 根工作区当前 `master` 是默认开发、验证和本地集成位置。不开新分支即可安全完成的任务直接在这里推进；开工前检查并保留用户已有改动，只暂存本任务文件，不重置、覆盖或夹带无关内容。
- 只有用户明确要求隔离、确有互不重叠的并行代码任务，或根工作区现有改动无法与任务安全共存时，才从当前本地 `master` 创建临时 worktree。不得为了同一用户结果的配套工具、测试或数据预览继续拆分分支；临时分支必须在交付前合入本地 `master`。
- Windows 工具链最低版本是 Git for Windows 2.53.0.windows.3；项目检查低于该版本时直接失败。使用 worktree 时必须在自身目录运行 `npm ci` 并拥有独立 `node_modules`，只共享 `.npm-cache/` 下载缓存。禁止从任何 worktree 通过 Junction、目录符号链接或其他重解析点连接根工作区或其他 worktree。
- 一个临时 worktree 只属于一个任务。不同任务不得共享未提交状态、数据目录或端口范围；不得切换其他任务 worktree 的分支。
- 存在并行任务时，开工前检查所有活跃 Issue、Draft PR、分支和 worktree。比较的不只是文件名，还包括用户结果、产品能力、接口、表、共享类型、页面动作和测试设施；与活跃任务语义重复时不得领取。
- 并行任务必须先全局可见。没有统一调度、无法查看其他活跃任务或待集成队列已经积压时，代码 WIP 保持一；只有两个任务的能力和改动面都独立时才允许 WIP 为二。
- 共享契约、迁移、认证、安全、锁文件、构建配置、测试基础设施、同一产品契约、同一核心组合文件和同一产品能力串行。共享边界先集成，再释放依赖它的任务。
- 确定性 Playwright 使用互不重叠的完整 `E2E_PORT_BASE` 范围；真实模型验收隔离 `E2E_API_PORT` 与 worker 范围。模型配置只能通过 `COLLECTOR_REAL_MODEL_DATABASE` 只读指向主目录配置库，运行数据仍放在任务专属目录。

存在并行分支时，任务首次提交后、准备修改共享测试或视觉基线前、合入本地 `master` 前，都重新比较各活跃分支相对共同基线的完整差异。固定声明与真实改动不一致时先收窄范围或停止其中一条任务，不能等到最终合并才处理重复实现。

退役 worktree 前先确认任务结果已经提交或明确放弃、工作树无已跟踪或未跟踪改动，再从另一个工作区执行 `npm run worktree:remove -- --path <绝对路径>`。安全清理会拒绝旧版 Git 和脏工作树、先把重解析点作为叶节点解除，再使用非强制 `git worktree remove`，并确认外部目标仍存在。禁止直接调用 `git worktree remove`、`Remove-Item -Recurse`、`rm -rf` 或等价递归删除处理 worktree。

创建、验证和退役临时 worktree 前后都记录根工作区 `git status --porcelain`；任何意外新增、删除或修改都视为生命周期故障并立即停止。`npm run check` 必须拒绝缺失的已跟踪文件、共享 `node_modules` 和解析到其他 worktree 的内部 workspace 包。

## 开工与开发验证

- 检查基线、工作树、用户已有改动，以及目标模块的代码入口、调用方和测试；不要从 Issue 或旧文档推断已经实现什么。
- 默认从最低验证等级开始；现有证据已覆盖的检查不重复运行。纯文档、规则和元数据只检查差异，不安装依赖、不构建、不运行产品测试。
- 普通代码开发只运行受影响的单元、集成、API、持久化、组件或单个 Playwright 文件；没有界面行为变化时不运行浏览器测试。不得因为改到 `apps/api`、`apps/web`、`packages`、前后端同时变化或影响范围较宽，就自动升级完整 gate。
- `npm.cmd run gate:fast` 用于普通 PR 的远端必选检查，也可在具体风险无法被定向测试充分覆盖时本地运行；它不是每次开发和每次提交前的固定步骤。
- `npm.cmd run gate` 与完整 Playwright 只用于夜间回归、发布候选、用户明确要求，或存在下表列出的具体高风险行为。要求升级的一方必须说明可能破坏的用户结果，不能使用“影响未知”或“保险起见”作为理由。
- 提示词、token 预算或模型参数变化先运行适用的 `scripts/probe-*.mjs`。API Key 只从本机安全配置读取，不进入命令输出、截图、文档或对话。

E2E 跨异步边界时使用业务语义，不使用页面瞬时外观代替后端事实：

- 触发 POST/PUT 前先注册动作响应等待；响应返回 task 时同时锁定 task id 与 `generationAttempt`，再等待同一尝试的持久化终态和 UI 对齐。task id 会在重试、重新生成和重新编辑中复用，不能单独代表一次执行。
- UI 动作后核对 SQLite/API 派生事实时使用 `waitForPersistedState`；只有已经等待同一 HTTP 事务成功返回时才可直接读取。编辑器关闭、按钮复现、旧错误文案仍可见等只证明界面状态，不证明写入完成。
- 选区动作只能从当前可访问的“选区操作”工具栏定位；不得用 test id 直接点击淡出中的浮动胶囊副本。固定 `waitForTimeout` 只用于验证明确的持续时长、去抖或动画期限，并在相邻注释写明产品时间边界。
- 完整 E2E 前先运行 `npm.cmd run test:e2e:sentinel` 覆盖近期高风险签名。哨兵首轮失败后可以只重跑失败测试来分类 `flaky` / `persistent`，但最终退出码必须保留首轮失败，trace、截图与两轮结果分别保存。

| 验证等级 | 适用范围 | 默认验证 |
| --- | --- | --- |
| 0：差异检查 | 文档、规则、文案、Issue/PR 元数据 | 链接、格式、`git diff --check`、提交范围；不运行产品测试 |
| 1：定向验证 | 默认日常代码开发 | 受影响测试；需要时增加类型/构建、单个 API 或单个 Playwright 文件 |
| 2：快速门 | 普通远端 PR/master，或定向测试不足以覆盖组合风险 | `npm.cmd run gate:fast`；不安装 Chromium、不运行完整 E2E |
| 3：完整回归 | 夜间、发布、用户明确要求，或下列具体高风险变更 | `npm.cmd run gate` 或 GitHub `full-gate` |

只有以下变更可以自动建议等级 3：数据库迁移或 schema 版本、认证/凭据/权限边界、永久删除/恢复/覆盖、既有持久化数据兼容、CI/Playwright harness、发布与安装流程。共享类型、普通 API、常用目录、跨端实现和改动文件较多仍默认等级 1 或 2；先用调用链和定向测试确定风险。

迁移修改必须同步迁移版本、`LATEST_SCHEMA_VERSION` 和迁移重放测试。开发期研究数据可以重建，不增加历史兼容分支；供应商配置、密钥、模型路由和设置必须保留。

## 失败归属与公共缺陷

发现测试、构建或视觉失败时，先最小复现；准备修改测试、夹具、阈值或视觉基线前，必须再在不含当前任务改动的干净主干基线上复现。没有证明失败由当前任务引入，就不得顺手修改共享测试设施。

| 复现位置 | 归属与动作 |
| --- | --- |
| 只在当前任务改动下失败 | 当前任务回归，由当前任务修复 |
| 不含当前任务改动的主干基线同样失败 | 公共主干缺陷，暂停交付并创建或复用唯一缺陷任务 |
| 并行改动单独通过、组合后失败 | 集成冲突，由唯一任务处理 |
| 与代码差异无关且不稳定 | 测试基础设施缺陷，由唯一基础设施任务处理 |
| 测试与代码代表两种合理产品行为 | 保持待确认，带产品契约、代码和测试冲突询问用户 |

公共缺陷以测试名、稳定错误类别、相关资源和基线 SHA 形成问题指纹。统一调度者先查重再指定唯一负责人；其他任务只记录继承失败，不得复制补丁、重拍基线、降低阈值或跳过测试。主干恢复绿色后，受影响任务重做必要验证。

视觉快照和 Playwright 基础设施按共享资源处理。只有本任务明确批准的界面变化才能更新对应基线，且必须逐图审查；多个任务会改变同一快照时必须串行，或由集成任务在最终候选 SHA 上统一生成。无图环境使用 `npm.cmd run visual:diff -- ...` 或更强证据，不能以“测试过时”代替原因判定。

## 主线与门禁

GitHub 必选 `gate` 是日常快速门：纯文档类变更只运行差异检查，产品代码变更运行 `npm.cmd run gate:fast`，不安装 Chromium、不运行完整 E2E。合入 `master` 后执行同样的快速门，不重复 PR 的完整浏览器回归。

GitHub `full-gate` 是退出日常关键路径的完整 E2E：香港时间每日 02:00 自动运行，也可以手动触发；PR 只有明确添加 `full-gate` 标签时才运行。远端完整 E2E 设置 `E2E_TRACK_CONCURRENCY=1`，避免单个 Windows Runner 资源饥饿。发布前必须取得当前发布候选 SHA 的完整回归结果；普通 Issue 的完成和关闭不等待夜间回归。

`npm.cmd run gate` 仍是需要完整本地回归时的统一入口，覆盖项目检查、构建、单元/集成测试及全部功能、隔离和视觉 Playwright 轨道，但不再是普通开发、普通 PR 或合并后的固定步骤。

- 本地 `master` 是默认集成主线；不为普通任务创建临时集成 worktree。确有多个并行分支时按依赖顺序逐个合入本地 `master`，每次合入后检查完整差异和调用方。
- 临时功能分支只用于已明确的隔离或并行需求，提供用户结果、局部验证、已知风险和未完成项。仅存在于分支、Draft PR 或 Ready PR 都不表示已经交付；交付前必须进入本地 `master`。
- 共享契约、迁移、跨端、认证、安全或数据风险在进入候选前，由没有参与实现的只读上下文根据任务卡、完整差异、产品契约和相关调用方复核；复核者只报告问题，任务负责人修复，集成者裁定是否具备候选资格。纯文档和低风险局部改动不为形式上的“独立”重复启动完整审查。
- 存在并行分支时，按依赖顺序组合兼容的小批次，检查完整差异和调用方后形成最终候选 SHA。分支上的旧 gate 只证明旧文件树，不能替代合入本地 `master` 后的候选验证。
- 最终候选在本地 `master` 提交后，按上表运行差异、定向或快速验证；只有等级 3 才要求完整回归。同一候选的独立阶段必须验证同一 SHA，修补产生新 SHA 后旧证据失效。若工作区仍有用户未提交改动，必须说明它们是否参与验证，不能把工作树结果误报为纯候选 SHA 结果。
- 所需验证通过后不得再改变受版本控制的文件。推送前重新获取远端状态；`origin/master` 已前进时重新组装并重做受影响验证，未前进时只推送已验证候选。随后核对远端 `master` 的祖先链确实包含完成提交。
- GitHub 的 `master` 必须启用分支保护并要求快速 `gate` 状态检查通过；`full-gate` 默认不是普通 PR 的必选检查。紧急修复同样先形成可审计候选并通过与风险匹配的检查。
- 集成失败保留候选分支和证据，不把半成品推入主干。长时间命令使用 `npm.cmd run run:logged -- <命令>` 保存完整输出和真实退出码。

## 状态、关闭与记录

普通变更的本地生命周期是：开发中 → 已验证 → 已进入本地 `master`。需要远端集成的任务继续经过 PR / gate → 已进入远端 `master` → 关闭 Issue；代码只存在于临时分支、局部测试通过、分支推送或 PR Ready 都不能称为完整交付。使用原生 PR 状态表达远端待集成，不再维护 PROJECT、进度文档或重复状态文件。

明确不合入主干的研究、原型和 Issue-only 决策是例外：按任务规定的证据、用户裁决和处置方式完成后可以关闭，但必须写明“仅证据”“未实施”或等价边界，不能宣称形成生产能力。

提交前检查完整差异、未跟踪文件、相关调用方和测试退出码。一个可验证、可审查、可独立回滚的用户结果形成一次提交；提交、PR 和 Issue 只记录实际变化、验证、偏差、风险与未完成项，不复制产品规格。没有活跃 Issue 的普通任务不补票，没有跨模块难逆决定的任务不补决策记录。
