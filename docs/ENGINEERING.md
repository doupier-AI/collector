# 工程协作与验证

本文件只保留 Collector 日常开发必须遵守的工程规则。产品含义见 `docs/product/`，技术边界见 `docs/ARCHITECTURE.md`。

## 默认工作方式

- 规则优先级为：当前用户明确要求 > 当前活跃任务的验收标准 > 本文件默认规则。历史任务、旧 PR 和旧门禁记录不自动继承。
- 开工前确认目标结果、范围、不可破坏项和验收方式，并检查工作树、相关代码、调用方和测试；保留用户已有改动。
- 默认直接在根工作区当前 `master` 开发和本地集成，不为普通任务创建 Issue、分支、worktree、计划文件或进度文档。
- 只修改当前任务需要的内容。范围外缺陷先确认归属，不顺手修复、不夹带提交。
- 提示词、token 预算或模型参数变化时运行适用的 `scripts/probe-*.mjs`；凭证不得进入日志、截图、文档或对话。

## 验证

默认从最低等级开始，只运行足以证明本次改动的检查。

| 等级 | 适用范围 | 默认验证 |
| --- | --- | --- |
| 0：差异检查 | 文档、规则、文案和元数据 | 链接、格式、`git diff --check` 和提交范围 |
| 1：定向验证 | 日常代码开发 | 受影响的单元、集成、API、组件或单个 Playwright 测试；需要时增加类型检查或构建 |
| 2：快速门 | 普通远端 PR，或定向测试不足以覆盖组合风险 | `npm.cmd run gate:fast` |
| 3：完整回归 | 夜间、发布、用户明确要求或明确高风险变更 | `npm.cmd run gate` 或 GitHub `full-gate` |

- 不得因修改常用目录、跨前后端、共享类型或文件较多而自动运行完整门禁。
- 数据库 schema、认证或凭据、永久删除或覆盖、既有持久化兼容、CI/Playwright 基础设施、发布或安装流程可以升级为完整回归。
- 数据库迁移必须同步迁移版本、`LATEST_SCHEMA_VERSION` 和迁移重放测试。
- E2E 跨异步边界时等待同一 HTTP 事务、task id、`generationAttempt` 和持久化终态；页面瞬时外观不能代替后端事实，固定等待只用于明确的产品时间边界。
- 只在本任务明确批准界面变化并逐图审查后更新视觉基线。

## 并行与 worktree

- 默认一次只推进一个代码任务；确认用户结果、产品能力和改动面互不重叠时最多并行两个。
- 共享契约、迁移、认证、安全、锁文件、构建配置、测试基础设施和同一产品能力必须串行。
- 只有用户明确要求隔离、确有独立并行任务，或根工作区改动无法安全共存时才创建 worktree。
- 每个 worktree 独立运行 `npm.cmd run worktree:prepare`，使用自己的 `node_modules`、数据目录和端口；禁止用 Junction 或符号链接共享依赖。
- 退役 worktree 前确认结果已保留且工作树无改动，再从另一个工作区运行 `npm run worktree:remove -- --path <绝对路径>`；不得直接递归删除或调用 `git worktree remove`。

## 失败归属

- 测试、构建或视觉失败先最小复现；修改共享测试、夹具、阈值或基线前，必须确认失败只由当前改动引入。
- 主干基线同样失败时作为公共缺陷单独处理；并行改动组合后才失败时由唯一集成任务处理；不稳定且与代码差异无关时作为测试基础设施缺陷处理。
- 测试与代码代表两种合理产品行为时保持待确认，不通过降低阈值、跳过测试或重拍基线强行消除冲突。

## 提交与交付

- 一个可验证、可审查、可独立回滚的用户结果形成一次提交。提交前检查完整差异、未跟踪文件、暂存范围和测试退出码。
- 普通交付必须进入本地 `master`；需要远端集成时再经过 PR、必选快速门和远端 `master` 祖先链确认。远端集成不自动要求完整 E2E。
- 验证证据必须对应最终候选 SHA；修补产生新 SHA 后，旧证据不能证明新候选。
- 所需验证完成后不得再修改受版本控制文件。长时间命令使用 `npm.cmd run run:logged -- <命令>` 保存完整输出和退出码。
- Issue、提交和交付说明只记录实际变化、验证、偏差、风险与未完成项，不复制产品规格或维护过程日志。
