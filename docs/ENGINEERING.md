# 工程协作与验证

本文件只在实施、构建、测试、并行开发或合并时读取。产品边界见 `docs/product/`，技术依赖见 `docs/ARCHITECTURE.md`。

## 任务边界

实施前确保任务上下文能够独立回答：

- 模块与目标用户结果；
- 明确不做什么；
- 不可破坏的产品、安全和数据规则；
- 依赖、固定基线和允许修改的文件；
- 成功条件与验证命令。

单会话、单分支、低风险任务不创建任务文件或 GitHub Issue。只有跨会话、并行、长期阻塞、外部参与、真实缺陷、发布、安全、迁移或用户明确要求时，才使用 Issue。Issue 只保留上述最小任务卡、当前阻塞和最终证据，不维护过程日志或未来任务树。

决策记录同样是例外：必须同时满足跨产品模块、难逆转、存在真实替代方案、需要长期保留理由。普通实现取舍进入代码、测试和提交；产品边界变化直接更新对应模块契约。

## 开工检查

- 检查当前提交、工作树和用户已有改动。
- 读取目标模块契约及涉及的技术入口、调用方和测试。
- 写第一行业务代码前做约五分钟的最短前置冒烟：后端检查迁移/受影响测试/一条最短端到端；前端检查构建或类型/受影响组件/一条最短端到端；真实模型改动先检查夹具、配置、端口和直连探针。
- 纯文档、元数据或不进入业务实现的任务不触发业务冒烟。

## 并行开发

- 每条并行轨道明确基线、依赖、文件所有权、数据目录和完整端口范围。
- 多个任务不得同时编辑同一产品契约、共享契约、迁移、锁文件、构建配置或核心组合文件。
- 共享边界先串行确定和集成，再释放下游实现；环境前提尽量固化到脚本和夹具，不创建持续增长的共享上下文文档。
- 确定性 Playwright 端口由 `E2E_PORT_BASE` 控制；真实模型验收端口由 `E2E_API_PORT` 与 worker 范围控制。并行时避开整个范围。
- worktree 中需要读取主目录模型配置时，只用 `COLLECTOR_REAL_MODEL_DATABASE` 指向配置库；运行数据仍使用隔离目录。

## 风险与验证

| 风险 | 最小验证 |
| --- | --- |
| 纯文档、文案、元数据 | 链接、引用、格式、`git diff --check`、提交范围 |
| 局部前端 | 构建或类型检查、受影响组件测试；用户交互变化增加相关 Playwright |
| 局部后端 | 构建或类型检查、受影响单元/集成/API/持久化/恢复测试 |
| 共享契约、迁移、跨端、构建或发布 | `npm.cmd run gate` |
| 认证、安全、数据丢失、影响未知 | 至少提升一级，必要时直接全量门禁 |

合并进 `master` 或修改跨分支共享的测试基础设施前，必须运行 `npm.cmd run gate`。同一批切片可以在集成分支只支付一次全量门禁；普通开发先运行受影响子集。

迁移修改必须同步迁移版本、`LATEST_SCHEMA_VERSION` 和迁移重放测试。开发期研究数据可以重建，不增加历史兼容分支；供应商配置、密钥、模型路由和设置必须保留。

失败后先用最小范围复现和重跑，再决定是否扩大。区分环境/基础设施失败与断言/功能失败。长时间命令使用 `npm.cmd run run:logged -- <命令>` 保存完整输出和真实退出码。视觉变化只更新已经确认改变的基线，并逐张审查差异；无图环境使用 `npm.cmd run visual:diff -- ...` 或更强的等价证据。

提示词、token 预算、模型参数等真实模型行为变化先运行适用的 `scripts/probe-*.mjs`。API Key 只从本机安全配置读取，不进入命令输出、截图、文档或对话。

## 完成与提交

- 检查完整差异、未跟踪文件、相关调用方和测试退出码。
- 产品契约不随功能进度更新；只有用户确认产品含义变化时才修改。
- 一个可验证、可审查、可独立回滚的用户结果形成一次提交；安全、迁移和构建变化可按审查边界独立提交。
- 提交和 Issue 只记录实际用户结果、接口或数据变化、验证、偏差、风险与未完成项，不复制产品规格。
- 对应活跃 Issue 被完整交付时及时关闭；研究、原型或被治理方式取代的 Issue 必须明确写“未实施”或“仅证据”，不能以关闭冒充完成。
- 没有活跃 Issue 的普通任务不补建 Issue。没有跨模块难逆决策的任务不补建决策记录。
