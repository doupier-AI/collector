# Collector 开发起点

日期：2026-07-17

状态：当前开发基线

## 1. 开发目标

本阶段把现有本地服务能力接入新的本地 WebUI，并按真实用户路径完成可持续扩展的纵向切片。

产品入口是双击启动器后在默认浏览器打开的 Collector 工作区。WebUI 和 API 由同一地址提供，页面通过 HTTP 与流式连接使用本机服务。

## 2. 开发依据

开始任务时按以下顺序读取：

1. 根目录 `AGENTS.md`：长期沟通与文档规则；
2. 根目录 `CONTEXT.md`：统一领域术语；
3. `docs/PRODUCT_REFOUNDATION.md`：产品定义、范围与待确认事项；
4. `docs/PRODUCT_FUNCTION_FLOW.md`：完整用户流程和 AI 依赖；
5. `docs/INTERACTION_DESIGN.md` 与 `docs/INTERFACE_DIRECTIONS.md`：交互和布局；
6. `docs/ARCHITECTURE.md`：技术边界；
7. `docs/HUMAN_ACCEPTANCE_STANDARD.md`：人工验收要求。

源码、自动化测试和实际界面共同证明实现状态。产品目标与当前实现分别描述。

## 3. 已确定的工程起点

- WebUI 工作区：`apps/web`；
- 前端：React、TypeScript 与 Vite；
- 浏览器自动化：Playwright；
- 服务端：现有 `apps/api` Node 服务；
- 数据：现有 SQLite 与文件存储能力，在全新 WebUI 数据空间中建立当前领域模型；
- 通信：同源 HTTP；生成内容与任务进度使用 SSE、流式 `fetch` 或等价的渐进交付方式；
- 安全：loopback 监听、本地会话、Host/Origin 校验、输入大小限制和凭证隔离；
- 联网搜索：独立搜索适配层，优先接入 SearXNG 兼容接口；
- 观测：界面事件、领域任务、模型调用和搜索调用共享关联 ID。

## 4. 可复用代码

| 现有区域 | 当前用途 |
| --- | --- |
| `apps/api` | HTTP 服务、领域服务、任务调度和 SQLite 访问基础 |
| `packages/capture-contracts` | 跨边界数据契约与运行时校验基础 |
| `packages/model-gateway` | 外部模型供应商注册、协议适配、用量与错误语义 |
| 文件解析与来源定位代码 | 文档导入、内容快照、引用和来源返回基础 |
| `apps/browser-extension` | 浏览器来源采集的迁移参考 |

复用以当前产品流程和 API 边界为准。新的界面行为进入 WebUI。

## 5. 首个纵向切片

首个切片交付“启动并恢复一场研究会话”：

1. 启动本机服务并由同一地址提供 WebUI 静态资源；
2. 浏览器显示最近研究会话、Chat 输入、文件导入入口和当前内容主画布；
3. 用户提交文字后，服务先保存输入与任务，再渐进显示生成内容；
4. 固定字段立即出现，AI 字段显示稳定的加载占位；
5. 页面刷新后恢复会话、输入、已生成内容和任务状态；
6. 自动化测试覆盖真实浏览器操作、API 状态和 SQLite 结果；
7. 人工验收覆盖启动、提交、加载、流式显示、错误恢复与刷新恢复。

该切片建立前端工程、同源交付、会话持久化、流式连接和浏览器测试五项基础。后续切片依次接入选区智能窗口、深入研究二选一、稍后再学、来源返回、搜索和观测查看。

## 6. 数据切换

新 WebUI 使用独立的数据空间。首次切换流程识别现有产品数据目录，执行一次性清理，创建当前数据库结构，并记录切换完成标记。自动化测试使用隔离数据目录验证清理、重复启动和失败恢复。

## 7. 完成标准

每个纵向切片同时满足：

- 用户可以从 WebUI 完成整条路径；
- 数据与任务状态真实保存；
- 页面刷新和服务重启后恢复到一致状态；
- 加载、空状态、失败、重试和取消具有可见反馈；
- 凭证与本地会话令牌保持在安全边界内；
- 构建、单元测试、服务测试和浏览器测试通过；
- 当前产品文档、架构文档与人工验收标准同步更新。

## 8. 当前待确认

选区智能窗口的字段顺序和默认展开层级由后续字段清单确认。该事项影响选区切片的呈现顺序，不影响 WebUI 基础与首个纵向切片开发。
