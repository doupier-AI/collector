## 1. 本轮结论

- 文件导入后端达到 `frontend-ready`：KIMI 3 可以直接调用真实 API 实现文件选择、拖放、处理进度、失败恢复和进入同一研究会话的阅读路径；
- 当前 MVP 后端接受 TXT、Markdown、DOCX 和文本型 PDF，单文件上限 20 MiB，原文件和解析快照在服务重启后保留；
- 导入具有稳定附件 ID、任务 ID、内容快照 ID、结构 block ID、会话内上传幂等、持久事件、取消、失败、重试和重启恢复语义；
- 浏览器响应只包含稳定 ID 和安全元数据，不包含本地文件路径或内部对象键；Host、Origin、配对令牌、HttpOnly Cookie 与启动器控制凭据边界保持不变；
- 当前 WebUI 仍显示附件占位提示，尚未提供用户可见的选择/拖放/进度/阅读界面；该部分由 KIMI 3 接入，不把后端完成描述为端到端界面完成。

## 2. 范围

### 已完成

- `@collector/capture-contracts` 增加附件、导入任务、进度、稳定错误、内容快照、结构锚点、导入事件和运行时文件元数据校验；
- 新增 SQLite migration v16，保存研究会话附件、导入任务、内容快照和可重放事件，保留 v14/v15 既有会话；
- 新增研究会话导入服务，使用临时文件和原子重命名保存原件，SQLite 事务保存会话关联，并在启动时清理无数据库引用的遗留对象；
- 支持 TXT 行号、Markdown 行号/标题/块类型、DOCX 段落序号/标题/块类型、PDF 页码锚点；
- 新增真实上传、状态查询、SSE、失败、取消、重试和内容快照读取接口；
- 完成会话内上传幂等：同键同文件返回首次记录，同键不同文件返回 `409 idempotency_conflict`；并发和重启后重试不重复创建附件；

- 增加确定性 TXT、Markdown、DOCX 和多页 PDF 测试，不调用真实云模型。

## 4. 契约、数据和行为变化

- 共享类型：新增 `ResearchAttachmentRecord`、`ResearchImportTaskRecord`、`ResearchContentSnapshotRecord`、结构锚点、导入事件、稳定 MIME/大小常量和错误码；`ResearchSessionView` 新增向后兼容的 `attachments` 与 `importTasks`；
- HTTP/SSE：新增 `POST /v1/research-sessions/:sessionId/imports`、`GET /v1/research-imports/:taskId`、`GET /v1/research-imports/:taskId/events`、`POST .../cancel`、`POST .../retry`、`GET /v1/research-content/:contentSnapshotId`；SSE 支持 `Last-Event-ID`/`after`；
- SQLite/迁移：v15 → v16；新增 `research_attachments`、`research_import_tasks`、`research_content_snapshots`、`research_import_task_events` 及索引；不改写旧会话、消息、聊天任务和旧 artifacts；
- 路由和组件状态：后端路由已就绪；WebUI 路由和组件未改，附件按钮仍为占位；
- 幂等、重试和恢复：上传键作用域为单个研究会话，与创建会话/消息键独立；queued 重启后继续，running 重启后转 `failed/service_restarted` 且可重试；取消终态为 `cancelled`；
- 安全与隐私：新公开 DTO 不含 `objectPath`、`object_key`、`storageKey` 或绝对路径；原文件使用不透明对象名，启动时对账清理孤立 `.bin`/`.tmp`；DOCX 在解析前限制 ZIP 条目数、单条目解压大小、总解压量和压缩比；既有认证与本地来源校验覆盖所有新路由；
- 与上一基线的差异：`FRONTEND-BASELINE 1.5.0` → `1.6.0`，变化集中在第 10.3、10.4 及后续小节编号；SQLite v15 → v16。
