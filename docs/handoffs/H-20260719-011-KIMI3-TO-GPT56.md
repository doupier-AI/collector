## 2. 范围

### 已完成

- 前端 API 客户端接入六个接口：上传（原始 File body、编码 `X-File-Name`、浏览器 MIME 或扩展名回退 MIME、会话内独立 `Idempotency-Key`）、任务查询、导入 SSE、取消、重试、内容快照读取；
- 新增导入 SSE 连接模块 `import-events.ts`：按事件 ID 去重、`?after=` 续传、终态后关闭并 GET 确认、断线退避、重试耗尽回退 GET 轮询、401 停止并上报；
- 会话页接入真实文件选择与整页拖放：前端白名单 TXT/Markdown/DOCX/PDF、显示 20 MiB 上限、空文件拦截，仍以服务端校验为最终事实；

- 上传恢复：网络不确定时先按幂等键查询服务端，已受理则直接恢复展示，未受理则保留同一文件与键提供“重试上传”；`409 idempotency_conflict` 时刷新服务端视图，不创建前端伪记录；
- 阅读视图 `/research/:sessionId/reading/:contentSnapshotId`：按锚点联合类型渲染内容块（TXT 行号、Markdown 标题/段落/列表/代码、DOCX 段落序号与块类型、PDF 页码），纯文本渲染，不保存 DOM 路径；

## 6. 已知问题与风险

1. 上传接近 20 MiB 的浏览器端性能未实测：现象为大文件上传与解析时页面响应未知；影响是性能目标仍未量化；临时绕行为服务端 20 MiB 上限保持稳定；建议责任角色为 GPT-5.6 在后续切片决定是否设定目标；
2. 阅读视图对 Markdown 列表块按原始文本行渲染（保留 `-` 标记），不猜测列表语义：影响是版式朴素但内容完整；建议责任角色为 GPT-5.6 在选区/引用切片统一决定结构渲染策略；
3. 网络不确定时保留的文件与键只在内存中：刷新页面后“重试上传”入口消失，但服务端已受理的记录会从会话视图恢复，未受理时用户需重新选择文件（新键）；影响限于极小时间窗；建议维持现状。
