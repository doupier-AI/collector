## 1. 本轮结论

- 用户可以双击根目录 `Collector.cmd`，或运行 `npm.cmd run launch`，启动或复用 Collector 本机服务；
- 正式启动器使用系统分配的动态端口，并通过实例 ID 健康检查确认重复启动复用的是同一进程和端口；
- 首次浏览器进入不需要用户手动输入 6 位码。启动器通过短时一次性回环入口下发 HttpOnly、SameSite=Strict Cookie，随后立即关闭入口；
- 配对码和会话令牌不进入 URL、浏览器 storage、实例文件或日志；普通已配对客户端也不能调用启动器控制入口；
- 已配对浏览器扩展保留 `43110` 本机适配入口，与动态 WebUI 共享同一认证和领域服务；
- 全量构建、Node 测试、WebUI 测试和 13 项真实 Chromium 场景通过，无真实云模型调用。

## 6. 已知问题与风险

1. **默认浏览器窗口未由 GPT-5.6 实际弹出并连接 DevTools**：操作系统打开器使用标准 Windows `cmd.exe start`，注入的浏览器打开器与真实 Chromium 页面分别有自动化覆盖；接收方仍需双击 `Collector.cmd` 补一次可见验收。
2. **扩展适配端口被占用时不阻断 WebUI**：服务会在日志中记录适配入口不可用，动态 WebUI 继续运行；浏览器扩展暂时无法采集，需释放或改写 `COLLECTOR_EXTENSION_PORT`。
3. **Windows 文件模式不等于 POSIX ACL**：代码以 `0600` 创建控制凭据和实例文件；Windows 上最终访问边界依赖当前用户数据目录 ACL。当前 MVP 为单用户本机运行，打包时应将数据根放在当前用户私有目录。
4. **强制终止留下的实例记录是可恢复元数据**：下次启动的健康检查失败后会替换它，不删除 SQLite、用户文件或已保存任务。
