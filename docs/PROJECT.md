# Collector 项目现状

本文件是 Collector 的唯一现行事实入口。历史决策见 `docs/adr/`，领域术语见 `CONTEXT.md`，代理规则见 `AGENTS.md`，技术边界见 `docs/ARCHITECTURE.md`。节点系统迭代以 `docs/NODE_SYSTEM_ITERATION.md` 为产品专题入口，以 `docs/NODE_SYSTEM_IMPLEMENTATION_PLAN.md` 为分阶段实施入口，现行产品边界由 ADR-0022 至 ADR-0026 固定；这不表示目标功能已经实现。

## 怎么使用本文件

- **想开始实施**：对本项目代理说"读 `docs/PROJECT.md`，开始下一张任务"。它会从"Issue 状态与阻塞"找到当前主线和依赖顺序。
- **想查看进度**：看下方"四态能力表"——`已实现并验证 / 部分实现 / 未实现 / 待产品决定`，或直接问代理"项目现在做到哪了"。
- **想做个模糊的新决定**：先用 `/grill-with-docs` 聊清楚，决策写进 ADR，能力变化回写本文件。
- **怀疑文档与现实不符**：说"对照当前代码，核对一遍 `docs/PROJECT.md` 有没有漂移"。本文件必须与代码保持一致；功能改动或决策作出后，在同一任务内回写本文件或新增 ADR，不允许拖延。

## 产品定义与核心用户路径

Collector 是具备自然普通对话能力的研究与学习工作空间（不是通用 Agent）。用户打开即进入一个统一对话空间；研究节点保留多轮思路，用户的显式生长动作形成父子脉络，全部未进入回收站的现存节点共同构成研究地图的全局数据范围，归档不改变归属。

核心用户路径：

```text
统一对话空间提问/粘贴/导入文档 → 连续正文阅读（流式弱标记随行显示）
→ 悬停弱标记看预览 / 点击生长子节点，或手动选区引用后追问、深入研究、标记笔记
→ 节点保留来源关系 → 研究地图（专注/全局模式）回看学习路径与跨节点关联
→ 多来源节点经核验后融合为独立增量节点
```

多轮对话始终在同一节点；只有显式生长动作（深入研究、选区生长、弱标记生长）才创建子节点。
