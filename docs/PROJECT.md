# Collector 项目现状

本文件是 Collector 的唯一现行事实入口。历史决策见 `docs/adr/`，领域术语见 `CONTEXT.md`，代理规则见 `AGENTS.md`，技术边界见 `docs/ARCHITECTURE.md`。

## 怎么使用本文件

- **想开始实施**：对本项目代理说"读 `docs/PROJECT.md`，开始下一张任务"。它会从"唯一活动父 Issue"找到当前主线和依赖顺序。
- **想查看进度**：看下方"四态能力表"——`已实现并验证 / 部分实现 / 未实现 / 待产品决定`，或直接问代理"项目现在做到哪了"。
- **想做个模糊的新决定**：先用 `/grill-with-docs` 聊清楚，决策写进 ADR，能力变化回写本文件。
- **怀疑文档与现实不符**：说"对照当前代码，核对一遍 `docs/PROJECT.md` 有没有漂移"。本文件必须与代码保持一致；功能改动或决策作出后，在同一任务内回写本文件或新增 ADR，不允许拖延。

## 产品定义与核心用户路径

Collector 是具备自然普通对话能力的研究与学习工作空间（不是通用 Agent）。用户打开即进入一个统一对话空间；对话中被显式生长出的结构构成研究地图。

核心用户路径：

```text
统一对话空间提问/粘贴/导入文档 → 连续正文阅读（流式弱标记随行显示）
→ 悬停弱标记看预览 / 点击生长子节点，或手动选区引用后追问、深入研究、标记笔记
→ 节点保留来源关系 → 研究地图（专注/关联模式）回看学习路径与跨节点关联
→ 多来源节点经核验后融合为独立增量节点
```

多轮对话始终在同一节点；只有显式生长动作（深入研究、选区生长、弱标记生长）才创建子节点。

当前限制：
- 弱标记由后置词法检测产生，可能拆分多词概念；中文多字术语、中英混排误标记待修订。
