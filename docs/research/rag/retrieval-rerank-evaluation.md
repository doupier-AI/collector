# 可追溯 RAG：检索、重排与评估研究

**对应议题：** [研究可追溯 RAG 的切分、混合检索、重排与评估](https://github.com/doupier-AI/collector/issues/123)
**结论性质：** 研究输入，不是产品、存储引擎或数据模式的决定。本文不选择正式向量数据库，也不引入知识图谱作为本轮的前提。

## 一句话结论

把「可找回正确证据」和「能把证据准确交给回答」拆开评估：先以带稳定定位的文档元素为事实源，比较多种检索与重排组合；再由回答侧在有限预算内选择证据。任何只返回扁平文本、却不能回到页码/区域/表格单元或图片的方案，都不能满足 Collector 的可追溯目标。

## 可借鉴的实践，以及不能照搬的部分

| 项目/来源 | 已证实的做法 | 对 Collector 的启发 | 本轮不作的推断 |
| --- | --- | --- | --- |
| [RAGFlow](https://github.com/infiniflow/ragflow) | 提供可配置的分块、文本与向量召回融合、重排，以及可查看的切片和可追溯引用。 | 「人可以检查切分结果和引用」是研究学习产品应保留的验收维度。 | 它需要 Docker、多个服务和较高本地资源；不因此成为 Collector 的运行时依赖。 |
| [LightRAG](https://github.com/HKUDS/LightRAG) | 并列提供传统文本块 `naive` 与本地/全局/混合检索；其维护脚本从权威文本块重建向量存储。 | 原文块应是重建索引的权威输入；索引和缓存可丢弃、可重算。 | 不把图谱检索当作当前 RAG 的必要条件。 |
| [RAG-Anything](https://github.com/HKUDS/RAG-Anything) | 将文本、图片、表格、公式分通道处理，同时保留层级与元素关系；支持给插入内容带文件标识。 | 表、图、公式不能在解析时退化为一段无定位的说明文字；证据候选需要元素类型和来源定位。 | 它的多模态知识图谱和 Python 管线是候选参考，非本轮承诺。 |
| [FlagEmbedding / BGE](https://github.com/FlagOpen/FlagEmbedding) | 同一生态包含稠密、稀疏、多向量检索与 cross-encoder 重排；BGE-M3 的论文报告支持多语言、多功能、多粒度。 | 中文与英文研究材料的基准应比较「召回模型」与「重排器」的组合，不能只测一个向量模型。 | 不预先锁定 BGE 或任何模型大小。 |
| [Qdrant 官方混合检索文档](https://qdrant.tech/documentation/search/hybrid-queries/) | 以 RRF 或 DBSF 融合稠密、稀疏等多个召回列表；官方明确指出两者没有普适赢家，应由评估集选择。 | 混合检索应以可重复基准裁决，不能凭主观权重或直接相加不同量纲的原始分数。 | 此处说明的是检索形态，不是选用 Qdrant。 |
| [Ragas 指标文档](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/) / [EvalScope](https://github.com/modelscope/evalscope) | Ragas 列出 Context Recall、Response Relevancy、Faithfulness 与多模态指标；EvalScope 声明支持 RAG、重排器和多模态 RAG 评估。 | 离线排序指标与端到端回答质量需要同时保留；自动判分要与人工金标准对照。 | 不把任一框架的分数视为产品真相。 |

原始研究也支持这种拆分：[RAG](https://arxiv.org/abs/2005.11401) 将生成与可检索的非参数记忆结合，但将可更新、可提供来源的知识视为开放问题；[BGE-M3](https://arxiv.org/abs/2402.03216) 报告同一模型可提供稠密、稀疏与多向量三类检索信号；[RAG-Anything 技术报告](https://arxiv.org/abs/2510.12323) 讨论混合内容的 RAG。它们是候选技术依据，不替代针对 Collector 资料的实测。

## 建议比较的证据块形态

所有候选都必须保留 `document version → page → region/原始元素 → 展示文本或媒体` 的稳定链路；块只引用该链路，不能成为第二份正文事实。

| 形态 | 适合回答的问题 | 主要风险 | 基准中的对照方式 |
| --- | --- | --- | --- |
| **元素块**：段落、表格、图片、公式、脚注各自独立 | 找精确陈述、某个数值、图表或公式 | 片段太短，失去章节语义；表格会缺表头 | 元素原文 vs. 元素加父标题/邻近说明 |
| **标题/章节块**：标题与其下较完整内容 | 概述、比较整节论证、学习总结 | 命中位置粗，生成上下文过大 | 标题块作为召回表示，回传精确子元素作引用 |
| **父子块**：子块用于检索，父块或相邻上下文用于阅读 | 既要细粒度命中又要解释上下文 | 父子映射和预算控制会变复杂 | 同一问题比较「子块直送」与「子块命中后扩展父块」 |

对于表格和图片，最小可检索单元应保留结构化载荷：表格的标题、表头、单元格/行列范围，图片的图题、页内区域、可用的原图或缩略图引用。仅用模型生成的文字描述可以作为辅助检索字段，但不能取代原始元素或其定位。

## 检索与重排候选矩阵

1. **全文/稀疏基线**：适合术语、公式符号、论文编号、专有名词和精确短语；应作为所有实验的最低对照。
2. **稠密基线**：适合语义改写、跨中英表述和学习者自然语言问题；以相同块形态对照全文检索。
3. **混合召回**：并行取稠密与稀疏候选，再用 RRF（无可靠调参集时的稳健起点）或 DBSF/加权 RRF（只在验证集调参）融合。不要把未归一化的 BM25 与余弦分数直接线性相加；Qdrant 官方文档说明二者量纲会随查询变化。
4. **两阶段重排**：先宽召回（例如每路 top-*k*），再以 cross-encoder 或 late-interaction 重排一个小候选集。官方 BGE 仓库将 reranker 定位为对 embedding 召回的 top-*k* 文档重排；这样才能把昂贵判断放在少量候选上。重排需同时记录增益与 P50/P95 延迟，不能只报质量。
5. **多表示召回（待验证）**：标题、摘要、正文子块分别建表示并在文档级分组。Qdrant 的官方示例同样把标题、摘要、正文块视为不同信号；这是一条实验假设，而非数据库决定。

LightRAG 与 RAG-Anything 值得作为「文本块以外还有结构/多模态候选」的对照，但本轮基线应先证明无图谱的元素/标题/父子块能可靠地回跳来源。否则先加图谱会混淆解析、检索与生成三类失败。

## 最小且可复现的评估设计

### 1. 固定语料与金标准

沿用解析基准的中英论文、教材、技术报告、扫描页、表格、公式、图片与损坏文件。每道问题至少人工标注：

- 可接受的证据元素集合（允许一问多证据）；
- 支持该回答所需的最小页面/区域；
- 问题类别（精确查找、解释、跨段比较、表格/图片/公式、跨文档）；
- 参考回答与「必须引用 / 不应声称」的边界。

划分开发集、验证集、冻结测试集；模型、chunk 参数、融合权重、重排 top-*k* 只能在前两者调，冻结集只在候选定型时报告。私有内容只使用匿名合成或有明确授权的材料。

### 2. 检索与引用指标

| 指标 | 定义 | 为什么需要 |
| --- | --- | --- |
| **Hit@k / Recall@k** | 若前 *k* 个候选中至少有一个 / 覆盖全部标注相关证据，则该查询命中；分别报告「至少一个」与「全部证据覆盖」。 | 判断召回阶段是否漏掉回答所需材料。 |
| **MRR** | 第一个相关证据排名的倒数的平均值。 | 判断正确证据是否足够靠前，影响后续上下文预算。 |
| **nDCG@k** | 用位置折损累积增益衡量排序，并允许多级相关性（直接支持、仅背景、无关）。 | 一问多证据、不同支持强度时比 MRR 更合适。 |
| **引用定位命中率** | 回答中每个引用能否回跳到金标准允许的文档版本、页码及元素/区域；另报元素类型正确率。 | 防止「文字相似但页码、表格或图片错位」。 |
| **上下文预算** | 每题送入回答侧的 token、元素数、图片数与重复率。 | 高 Recall 不能靠无限塞材料取得。 |

所有结果按问题类别、语言、文件类型和元素类型分层报告；总体均值会掩盖「表格全丢」「扫描件回跳失败」等关键问题。

### 3. 端到端质量与系统成本

将 **Faithfulness（回答主张能否由给定证据支持）**、**Context Recall（给定上下文是否包含参考回答所需信息）**、**Response/Answer Relevancy（回答是否回应问题）** 作为 Ragas 可自动辅助的维度；对小型冻结集做人工复核，以校准自动评判偏差。自动答案分数不得替代引用定位命中率。

资源与可运维性需单列：

- 冷启动、热查询的 P50/P95 端到端延迟，拆分解析、嵌入、全文、融合、重排和回答侧装配；
- 索引大小、磁盘、RAM/VRAM、首次模型下载；
- 单文档增量导入、修改一页、删除一份文档、切换嵌入模型时的重建时间与影响范围；
- 失败注入：解析失败、元素无定位、向量写入中断、重排不可用时，能否从权威文档块重建，并降级到全文/稀疏检索而不伪造引用。

## 给后续票据的明确输入

### 给「验证检索、引用回跳与上下文交接」

原型至少实现并对比：元素块、标题块、父子块 × 全文/稠密/混合 × 有无重排。其输出不是给模型的自由文本，而是**带来源的候选证据**：文档版本、元素 ID、元素类型、页码/区域、可展示载荷、检索路径/分数和可装配的上下文片段。回答侧再决定取舍和 token 预算；检索侧不写回答正文。

验收应覆盖：中文与英文、表格、公式、图片、跨文档问题；每个答案引用可点击回跳；检索或重排失败仍得到可解释的降级结果；重启后索引与原始定位一致。

### 给「决定索引重建、失败降级、隐私与证据交接契约」

待裁决项：

1. 什么是可重新生成的派生索引，什么是必须保留的权威解析结果与定位；
2. 文档更新、模型变更、写入中断时的版本策略和原子可见性；
3. 全文、稠密、混合、重排分别不可用时的用户可见降级与引用标识；
4. 候选证据向统一上下文装配层交接的字段、预算、敏感级别和审计边界；
5. 本地数据、模型服务和遥测的隐私边界，以及删除一份材料后所有派生数据的可验证清理；
6. 何时允许图片/表格以图像载荷进入模型，何时只交付结构化文本与来源。

这些决定必须在解析基准和检索原型的实测结果之后作出；不应由任一开源项目的默认实现代替。
