# 节点系统分阶段实施计划（PRD 与可执行任务包）

> 状态：产品边界已经确认，ACTIVE 父规格 #59 与 20 张子票 #60 至 #79 已发布；当前从唯一无 blocker 的 #60 开始，功能尚未按本计划实现。
>
> 本文只规定实施顺序、任务构成、测试与验收门槛，不重新定义产品。领域词义以 `CONTEXT.md` 为准，产品与架构决定以 ADR-0007、ADR-0022 至 ADR-0026 为准，当前实现状态以 `docs/PROJECT.md` 为准，完整产品规则以 `docs/NODE_SYSTEM_ITERATION.md` 为准。

## 1. PRD 摘要

### 1.1 要解决的问题

当前研究地图以单个会话为范围，图投影、路由、候选发现、融合归属和删除规则也围绕会话组织。用户无法在同一张地图上稳定观察全部研究节点，也无法在保持全局方位的同时聚焦某个节点的完整关系脉络。现有 `semantic-related` 旧实现边和自动创建永久融合节点的流程还与已确认目标冲突。

本轮交付要把研究地图变成统一的全局观察系统：全部未进入回收站的节点进入 A 面正式知识底图；点选节点后，同一布局中的完整连通脉络保持正常色彩，其余图谱原位置灰；AI 的普通发现保持为临时关联提示；形成具体新增认识时，AI 自动在 B 面创建临时融合节点，只有用户确认后才原位进入 A 面并成为固定成果。

### 1.2 用户可见结果

完成全部阶段后，用户可以：

1. 在 `/map` 查看跨会话、跨项目的全局研究地图，包括从未生长过的根节点和已归档节点；回收站内容不进入普通全局范围。
2. 在地图中搜索任意普通节点或正式融合节点；同一节点只出现一次，多个命中内容范围归并在该结果下。
3. 点选任意节点或打开 `/map/focus/:nodeId` 进入同一种专注状态；完整连通脉络保持正常色彩与明度，所有未连通节点和连线保持原位置并统一置灰。
4. 通过父子关系的结构与方向看清节点如何生长，通过融合来源看清哪些直接来源支撑融合成果；切换关系类型不会重新布局。
5. 查看并忽略临时关联提示，返回相关原文；提示不会变成永久关系，也不会触发融合。
6. 在 B 面审查 AI 自动形成的临时融合节点，查看证据、继续对话、明确修改、搜索、单独或批量删除；B 面不污染 A 面永久连通脉络。
7. 确认一个已经核验的具体草案版本，使同一节点原位进入 A 面；确认时不重新生成，确认后的正文、直接来源和证据对应固定。
8. 在来源进入回收站、恢复或永久删除后看到诚实的证据状态；删除来源不会静默删除独立融合成果。

### 1.3 交付范围

- 共享领域契约、SQLite 持久化、全局观察查询、全局搜索、任务恢复和稳定导航。
- A 面全局图谱、同图专注、关系筛选、范围筛选、跨范围桥接、观察快照和窄屏关系列表。
- 临时关联提示的跨会话发现、排序、忽略、过期和来源返回。
- B 面临时融合节点、候选来源连接、草案版本、核验、搜索、列表、来源往返、删除和原位确认。
- 正式融合的固定成果、独立会话归属、直接来源、来源链和证据健康。
- 浅色/深色主题、320/1024/1440 视口、鼠标、键盘、屏幕阅读器名称和减少动态效果。
- 确定性自动化、浏览器端到端、视觉回归、重启恢复、错误状态和代表性规模测量。

### 1.4 明确不做

- 不引入永久语义关联，不提供用户主动拉线或“保留为永久关联”的入口。
- 不把会话、单轮消息、语义卡片或语义范围画成新的图谱节点。
- 不把弱标记识别结果作为节点进入地图、全局搜索、关联提示或融合的必需输入；弱标记完善由独立任务线推进。
- 不建设公开分享、多人协作、矛盾成果专用状态、自动消解或一键级联删除全部派生成果。
- 不为开发期研究数据增加兼容分支；数据兼容遵守 ADR-0007。
- 不在规模测量前承诺聚类、抽稀、分页或某个固定布局算法；这些属于测量后的可替换呈现策略。

## 2. 视觉实施纲领

视觉呈现是本轮第一优先级，但视觉不能自行发明新的产品语义。

- **主题对象**：个人研究知识如何生长、连接并形成新的综合成果。
- **页面唯一任务**：让用户在不丢失全局方位的前提下，看清一个节点的完整关系脉络和生长方向。
- **布局**：以关系自然拉扯形成的有机全局地图为主体，控件保持安静；节点正文仍在完整节点页阅读，不把地图挤成正文旁的小组件。
- **色彩**：只消费 `CONTEXT.md` 产品取色板和登记后的项目色令牌。项目用稳定色相，归档降低饱和度；专注中的未连通区域同时降低明度与饱和度并统一置灰。任何状态都不能只靠颜色表达。
- **字体**：图谱标签和工具使用现有界面字体系；完整节点阅读继续使用既有阅读面字体层级。图谱不另造装饰性展示字体。
- **节点语法**：普通节点是轻量实心圆点，正式融合节点使用同尺度空心圆环或细外环，临时融合节点只在 B 面出现。
- **关系语法**：未选择节点时永久关系是极细、低透明度的中性单线；选中后，仅完整连通脉络中的父子与融合来源按“来源 → 结果”缓慢流动。减少动态效果时改用静态方向渐变与文字说明。
- **标志性时刻**：点选节点后，地图空间不动，完整连通脉络保留原有生命力，其余知识退成灰色背景；这是本产品区别于普通局部图的核心视觉记忆点。
- **Obsidian 参考边界**：借鉴官方图谱中的圆点、连线、悬停邻域、缩放平移、过滤和力参数，不复制其数据模型或可调深度本地图。Collector 的完整连通专注、稳定关系、A/B 面与证据规则只由本项目文档决定。参考：[Obsidian Graph view 官方说明](https://obsidian.md/help/plugins/graph)。

## 3. 任务构建标准

### 3.1 票据层级

- 节点系统父规格是 #59，完整引用本 PRD、`docs/NODE_SYSTEM_ITERATION.md` 和 ADR-0022 至 ADR-0026；只有全部子 Issue 完成且证据与 `docs/PROJECT.md` 一致后才能关闭。
- `NS-xx` 是产品阶段包；实际领取单位是下方映射的 `Txx` 原生子 Issue。每张子票都包含可验证的后端能力、前端路径、联调、测试和验收，不把“接口写完但用户不可用”作为完成结果。
- 一个阶段可以由一张或多张纵向切片票组成；只有共享契约、迁移或测试设施确实能独立验收时才单独成票，且所有切片仍共同满足所属 `NS-xx` 阶段的完成门槛。
- 任务开始前固定 base branch/commit、父 Issue、阶段 Issue、依赖、范围、验证级别和不做事项。任一项不一致就停止实施并先修正任务描述。

### 3.2 每张阶段票据的固定内容

每张票据必须让第一次接手的人不依赖历史聊天即可执行，并按以下顺序书写：

1. **用户结果**：阶段完成后，用户能看到或完成什么；没有用户可见变化时明确写“本阶段只提供可集成基础”。
2. **背景与问题**：当前行为、为什么不足、与哪项已确认决定有关。
3. **前置条件**：必须完成的阶段、需要存在的契约、测试数据和运行环境。
4. **范围**：后端、前端、数据、路由、任务恢复、文档分别做什么。
5. **不做事项**：本阶段故意不解决什么，避免相邻功能被静默带入。
6. **执行顺序**：先写哪些失败测试，再改契约/持久化/API，再接 WebUI，最后怎样清理旧路径。
7. **异常与恢复**：加载、空、失败、认证过期、对象不存在、重复提交、网络结果不确定、刷新和服务重启怎样表现。
8. **测试矩阵**：单元、契约、持久化、API、组件、Playwright、视觉和无障碍分别覆盖什么。
9. **验收步骤**：普通用户按什么动作操作、每一步肉眼应看到什么、什么情况必须停止。
10. **完成证据**：命令与结果、浏览器视口、截图基线、控制台/网络、提交、PROJECT 四态判断、未完成项和风险。

### 3.3 通用完成定义

任一阶段只有同时满足下列条件才可关闭：

- 阶段范围内的后端能力可被真实调用并持久化，不以假接口、演示数据或仅有类型定义代替。
- 前端只消费统一客户端与共享契约，不在组件内自行拼接请求、重新解释图范围或保存第二份业务事实。
- 自动化覆盖成功、失败、空态、重复请求、刷新和重启恢复；用户可见交互还覆盖相关视口、键盘、焦点、可访问名称、控制台和网络请求。
- 任何视觉变更只更新受影响截图，人工逐张检查差异；不能用“更新全部基线”让测试自证通过。
- 没有未经确认的新产品概念、状态、入口、默认行为或权限。发现新边界时必须使用“⚠️ 新概念 / 新功能 / 新边界提醒”暂停当前阶段。
- 关闭或模拟弱标记检测失败时，全局地图、搜索、专注、关联提示和融合仍能通过正文版本、语义范围、节点与永久关系独立工作。
- 本阶段的实现、测试、已知偏差和风险记录在 Issue 与提交中；长期有效约束才进入现行文档。
- 提交前回答“`docs/PROJECT.md` 四态能力表是否需要改动”。状态和证据真的变化时同提交更新，否则明确记录“不需要”。
- 一个阶段按可验证用户结果提交一次；阶段 Issue 只有在验收门槛全部满足后才关闭。

## 5. 分阶段任务包

## NS-00：建立任务、样本与证据基线

### 用户结果与目的

本阶段不改变产品界面。父规格与子票已经发布；本阶段在 T01（#60）中核对任务基线，并准备后续所有阶段共用的确定性样本、验收场景和证据格式，防止每个阶段使用不同口径。

### 后端子任务

- 盘点现有节点、边、融合提议、正文版本、语义范围、项目、归档和删除存储；列出将复用、替换和退役的读写路径。
- 准备确定性数据构造器，至少覆盖：无关系节点、跨会话父子树、多个不连通分量、父子与融合来源混合环路、跨项目桥接、归档节点、回收站来源、来源已删除、多个临时融合候选和证据失效。
- 在父子树样本中分别从弱标记、手动选区和深入研究三种入口创建子节点，并提供弱标记返回空、识别错误和检测失败样本；图谱结果不得因入口不同而改变父子语义。
- 记录当前会话图、候选扫描、融合确认、删除与重启恢复的基线行为，作为迁移前对照，不把旧行为写成目标规则。

### 前端子任务

- 固定 320、1024、1440 三个视口以及浅色、深色、减少动态效果组合。
- 为全局、专注、关系关闭、搜索定位、B 面、证据异常、加载、空和错误状态建立验收场景目录；此时不创建假界面。
- 记录当前地图打开、节点跳转、浏览器返回、键盘和焦点行为，明确哪些是必须保持的通用能力，哪些由新目标替代。

### 执行、测试与验收

1. 核对父规格 #59、T01 至 T20 子票、原生父子关系和 blocker 是否与本计划一致；发现漂移先修正票据，不进入功能实施。
2. 运行现有相关测试，记录通过项和已知失败；不在本阶段顺手修功能。
3. 验证样本可重复生成，ID、正文、关系和时间不随运行变化。
4. 输出基线清单、受影响文件地图、风险清单和各阶段验证级别。

**验证级别：** 一级用于本计划和票据；若提交确定性测试构造器，则按四级测试设施变更验证。

**退出标准：** 所有阶段 Issue 自洽、依赖明确、样本可复现、当前失败已记录，未出现需要用户决定的新产品边界。

## NS-01：建立目标契约与持久化，新路径不写 `semantic-related`

### 用户结果与目的

本阶段主要提供可集成基础。系统内部能明确区分 A 面永久事实、临时关联提示、临时融合节点和候选来源连接；旧 `semantic-related` 不再被目标契约误认为第三种永久关系。

### 后端子任务

- 将目标永久关系限定为父子关系和融合来源；为临时关联提示、临时融合节点、候选来源连接、草案版本、核验状态、正式成果固定信息和来源健康建立独立契约。
- 为项目增加稳定色板角色；颜色只存角色或稳定标识，浅色/深色实际颜色由主题令牌解释。
- 建立目标 SQLite 表/字段、索引、事务和仓储接口；按 ADR-0007 允许重建开发数据，不增加未经批准的历史兼容分支。
- 停止目标路径写入 `semantic-related`；旧代码可在迁移期间内部保留，但不能被新契约或新 UI 当成目标事实。
- 把当前自动融合开关的目标含义收缩为“允许自动准备 B 面草案”，不得再授予自动创建 A 面永久节点的权限。

### 前端子任务

- 更新统一 API 客户端和测试假对象，使 UI 能区分永久关系、临时提示、临时融合和正式融合，不使用含义模糊的“语义关联”。
- 在 `tokens.css` 登记项目色角色的浅色/深色配对，以及焦点、连通、置灰背景、临时节点、证据异常和键盘焦点所需的语义令牌；不在画布组件内散落颜色。
- 暂不开放尚未可调用的页面、开关或操作入口。

### 执行、测试与验收

1. 先写共享契约和持久化失败测试，再实施数据库与仓储，再更新 API 客户端类型。
2. 验证临时对象不能通过永久边读取接口出现，永久边也不能被候选删除操作修改。
3. 验证搜索、关联提示和融合目标契约不要求弱标记字段存在，也不把弱标记检测服务作为必需输入。
4. 验证重复写入、事务失败、进程重启、来源缺失和非法状态转换。
5. 验证新路径不会写入 `semantic-related`，旧自动融合不会从新路径直接创建永久节点。

**验证级别：** 四级，因为涉及共享契约和数据库结构。

**退出标准：** 契约、存储、客户端和测试假对象一致；目标模型不存在第三种永久关系；开发数据处理遵守 ADR-0007；普通界面没有假入口。

## NS-02：实现全局观察、范围与稳定定位

### 用户结果与目的

本阶段提供真实可调用的全局读模型和稳定节点地址，但尚不要求完成最终视觉。它消除“会话就是图谱边界”和 `maxDepth` 截断，为所有呈现提供同一份观察结果。

### 后端子任务

- 实现统一观察查询：输入观察中心、项目/时间/归档范围和启用的永久关系类型；输出范围内节点、范围外桥接节点、永久关系、焦点/连通/未连通分类、项目色角色、归档、节点角色、候选数量和融合证据健康摘要。
- 全局数据范围包含全部未进入回收站的现存节点；归档保留，回收站退出普通范围；未生长根节点不能遗漏。
- 连通计算把父子与融合来源作为可组合关系，浏览可从两端进入但保留语义方向；不接受用户可见深度参数。
- 范围筛选不得截断真实路径：A（项目一）—B（项目二）—C（项目一）时，选中 A 仍返回 B 作为弱化桥接节点。
- 建立 `/nodes/:nodeId`、`/map`、`/map/focus/:nodeId` 对应的稳定读取与不存在/回收站结果；节点读取不依赖会话 ID。

### 前端子任务

- 让导航层和 API 客户端消费统一观察结果；画布、窄屏列表、搜索定位和键盘导航不得各自重新计算连通范围。
- 建立新路由的空壳状态只在后端真实能力可调用后接入；加载、空、错误、无权限和节点不存在均使用现有状态组件。
- 保留旧会话节点地址的单向跳转能力，不在新组件继续传播会话 ID。

### 执行、测试与验收

1. 先用确定性图覆盖无边、链、分叉、环、混合关系、孤立节点和桥接节点。
2. 增加 SQLite/API 集成测试，证明跨会话、跨项目、归档、回收站和重启后的结果一致。
3. 增加客户端契约测试，证明所有呈现拿到相同分类结果。
4. 直接打开和刷新三个稳定地址，验证成功、404、回收站和认证失效。

**验证级别：** 四级，因为新增跨端共享查询和稳定路由。

**退出标准：** 新全局查询不按会话或深度截断，稳定节点地址独立可用，所有观察消费者使用同一结果。

## NS-03：交付 A 面全局地图视觉底座

### 用户结果与目的

用户第一次能在 `/map` 看到完整 A 面：由跨会话节点和永久关系组成的有机全局地图，能够缩放、平移、悬停和打开节点，视觉以知识关系为主而不是控件面板。

### 后端子任务

- 为全局首屏提供最小必要摘要，完整正文、证据详情和候选详情按需读取，避免图投影膨胀为节点详情接口。
- 为布局保存或客户端稳定种子提供不依赖主题、会话或视口的节点身份；服务端不把像素坐标变成知识事实。
- 提供项目色分配和修改能力：优先使用当前最少占用色，项目改名不改变颜色，未分类使用中性色。

### 前端子任务

- 建立可替换的图布局适配层，在确定性样本上比较候选实现，选择能支持稳定位置、局部再稳定、缩放和平移的方案；若选型形成明显锁定，另记架构 ADR。
- 画布使用轻量圆点和中性细线；标签随缩放弱化，靠近、悬停、键盘焦点或选中时恢复。
- 普通节点、正式融合节点、归档、项目色和键盘焦点使用互不冲突的视觉通道；颜色不是唯一说明。
- 悬停只增强直接邻居与相关线，不改变观察中心、不重新布局；双击、Enter 或“打开节点”才离开地图。
- 窄屏使用消费同一观察结果的关系列表，不强行缩小桌面力导向画布。

### 执行、测试与验收

1. 先用静态确定性投影完成布局适配和组件测试，再接真实全局观察接口。
2. 验证打开、关闭、缩放、平移、悬停和窗口尺寸变化不会改写任何业务事实。
3. Playwright 覆盖 1440/1024 桌面画布和 320 窄屏列表，检查加载、空、错误和节点打开路径。
4. 对浅色、深色、默认动态和减少动态效果建立受控截图；控制台错误与警告为零，网络无意外请求。

**验证级别：** 二级；若本阶段同时调整共享接口，则提升四级。

**退出标准：** A 面真实数据可见、操作可达、项目与节点状态可读，地图外围控件不争夺主视觉，任何交互都不产生整体位置跳变。

## NS-04：交付同图专注、完整连通与生长方向

### 用户结果与目的

用户点选一个节点后，不离开或重排全局地图：焦点节点最突出，沿启用永久关系可达的完整连通脉络保持正常色彩，其余节点和连线在原位置统一置灰。父子方向持续表达节点的生长路径和生长树。

### 后端子任务

- 根据观察中心和当前关系筛选返回焦点、完整连通、未连通背景以及桥接节点分类；不返回深度截断结果。
- 关系全部关闭时只保留焦点为正常状态；选中正式融合节点且启用融合来源时，直接来源不得被范围筛选截断。
- 同一节点对存在多种关系时仍分别保留关系事实，并为前端提供合并为一条视觉连接所需的数据。

### 前端子任务

- 单击节点和 `/map/focus/:nodeId` 进入同一种专注状态；切换焦点、筛选或退出都保持坐标、缩放、平移和观察中心附近的空间记忆。
- 焦点节点使用克制光晕；完整连通脉络维持项目色和可读明度；未连通区域同时降明度、降饱和度并置灰，但仍可悬停、聚焦和点选为新焦点。
- 仅在当前强调脉络中显示父子与融合来源的方向流动；默认关系静止。减少动态效果时使用静态渐变和明确起止文字。
- 归档、融合身份、证据健康和键盘焦点继续由形状、标识、文字和焦点环表达，不能被置灰语法覆盖。
- 键盘 roving 顺序和窄屏关系列表消费服务端同一分类；当前焦点提供 `aria-current` 和可理解名称。
- 迁移期保留现有“打开父节点”快捷出口；ADR-0026 已保证父节点也可在同图中直接点选，但是否在新地图稳定后删除快捷出口仍需后续体验验证，本阶段不得静默移除。

### 执行、测试与验收

1. 先写完整连通计算的契约测试，覆盖混合关系、环、孤立节点、全部关系关闭和跨范围桥接。
2. 写组件测试证明样式分类不改变布局数据，点击灰色节点只切焦点。
3. Playwright 比较选择前后所有既有节点坐标，任何非局部布局变化都失败。
4. 在浅/深主题和 320/1024/1440 视口验证焦点、连通、置灰、关系开关、键盘、读屏名称和减少动态效果。

**验证级别：** 四级，因为专注分类由共享查询提供并影响用户主路径。

**退出标准：** 场景“选中融合成果—关闭融合来源—重新开启”全程不重排；父子生长方向可感知且可由文字准确解释；灰色背景仍可交互。

## NS-05：交付全局搜索、筛选、导航与现场恢复

### 用户结果与目的

用户可以在全局地图中找到任意节点和命中内容，组合项目、时间、活跃/归档和永久关系筛选；打开正文再返回时恢复原地图现场。

### 后端子任务

- 实现跨会话全局搜索，结果按节点归并，同一节点的多个语义范围作为命中依据返回；普通节点与正式融合节点都可搜索。
- 范围内结果正常排序和突出，范围外结果单独分组或标记；回收站节点不进入普通结果。
- 提供搜索命中语义范围的稳定定位，锚点失效时返回诚实降级信息。
- 为项目、时间、活跃/归档和关系类型筛选提供确定性输入与输出；筛选不改写关系事实。

### 前端子任务

- 建立统一搜索入口、结果列表、命中范围预览和定位；A 面与后续 B 面复用同一种交互外壳，但由模式限定不同数据源。
- 单击搜索结果将地图平滑移动到视口外目标并进入专注；普通点选仍不强制居中。
- 从图谱打开节点时保存当前标签页的观察快照：位置、缩放、平移、观察中心、范围、关系筛选、状态叠加和临时观察历史。
- 浏览器返回或“返回图谱”恢复快照；没有快照时，“在图谱中查看”以该节点进入专注。
- 旧会话节点路由只做单向转向，不形成第二套地址。

### 执行、测试与验收

1. 后端测试同节点多命中、跨会话、范围内外、归档、回收站和失效锚点。
2. 前端测试筛选组合、全空关系、搜索定位、A→B→C 临时观察返回和页面刷新。
3. Playwright 记录打开节点前地图状态，返回后逐项断言视口与筛选恢复；验证没有把快照写成知识事实。
4. 检查键盘完整路径、焦点回归、可访问名称、控制台、网络和不该发生的请求。

**验证级别：** 四级，因为涉及搜索、稳定路由与跨端恢复。

**退出标准：** 用户能从一个命中范围进入稳定节点、返回同一地图现场；同一节点不会因多个命中被画成多个对象。

## NS-06：把 `semantic-related` 旧实现路径迁移为临时关联提示

### 用户结果与目的

AI 可以帮助用户重新发现旧内容，但提示明确是临时的：用户能看理由、相关内容范围、打开原文或忽略；不能将其保存为永久关系，也不会因此触发融合。

### 后端子任务

- 将普通关联发现从旧融合提议/`semantic-related` 写入路径拆开，改为跨会话、跨项目的临时提示查询与持久化抑制。
- 候选检索以正文版本、语义范围和关系核验为输入，不把弱标记作为候选发现输入；弱标记为空、错误或失败时不得阻断发现。
- 提示包含理由、两端一个或多个语义范围、价值排序和证据版本；当前回答完成且内容稳定后再评估，不阻塞正文生成。
- 当前学习过程最多主动突出一条最有价值提示，其余进入候选观察层；证据失效、价值下降或被更高价值候选替代时可过期。
- 明确忽略后，同一理由不按固定时间复活；只有新的实质证据改变理由时才可形成新提示。
- 删除或停用“保留关系”写入；测试必须证明任何提示操作都不会创建永久边或融合任务。

### 前端子任务

- A 面默认不绘制候选连线，只显示观察范围内候选总数和有候选节点的微型卫星点。
- 用户主动开启候选观察后，永久底图弱化，提示节点/连接突出并明确标注“临时提示”；提供理由、来源范围、打开和忽略。
- 不显示“融合”“保留关系”“主动建边”等动作；关闭候选观察立即恢复 A 面永久关系视角和原有布局。
- 来源返回复用稳定节点与语义范围定位，失败时说明无法精确定位但仍可打开节点。

### 执行、测试与验收

1. 先写“绝不写永久边/绝不触发融合”的负向契约测试，再实施发现、排序、过期和忽略。
2. 验证跨会话旧节点可被发现，孤立短句、无证据和低价值候选不会打扰用户。
3. Playwright 覆盖候选数量、卫星点、候选观察、理由、来源返回、忽略、刷新和关闭后恢复。
4. 数据库断言 `semantic-related` 新写入为零，融合任务数量不因提示操作变化。

**验证级别：** 四级，因为替换旧跨端语义和持久化路径。

**退出标准：** 普通发现完整可用但不留下永久图谱事实；旧 `semantic-related` 不再有新写入，界面不再把它解释为目标关系。

## NS-07：实现 B 面临时融合生成与持久化

### 用户结果与目的

当 AI 在至少两个正式来源上形成具体、可证的新认识时，系统低打扰地创建临时融合节点。当前阅读不被打断，用户只看到 B 面入口总数变化。

### 后端子任务

- 在当前回答完成且内容稳定后独立运行融合判断；搜索、询问、对比、打开旧节点、关联提示或用户说“融合”都不得直接触发。
- 融合判断以正文版本、语义范围和来源核验为必需输入，不依赖弱标记是否识别成功。
- 只有具体新增认识、两个或更多正式来源实际参与、关键证据可定位且判断自洽时创建临时融合节点；只是相关或证据不足时不创建。
- 临时节点拥有稳定身份、完整草案、普通对话、版本、核验和候选来源连接；不能生长、不能作为融合来源、不属于项目、没有归档状态。
- 将当前自动融合开关改为只控制自动准备 B 面草案；任何开关状态都不能直接创建 A 面永久成果。
- 为任务重试、刷新和服务重启提供幂等键与恢复；阻止确定性重复，允许无法确认相同含义时的候选并存。

### 前端子任务

- 在 A 面提供 B 面入口和临时节点总数；创建时不弹窗、不插入消息、不自动打开地图或切换 B 面。
- 初步建立 B 面同画布覆盖层：A 面位置保持，临时节点围绕来源出现，候选来源连接只在 B 面可见。
- 临时节点视觉明确区别于正式融合节点，但不增加未经确认的状态颜色或动画。

### 执行、测试与验收

1. 用确定性假模型覆盖零来源、一来源、两来源、多来源、相关但无新增认识、证据失效和重复任务。
2. 验证临时节点及连接在同一事务中保存，重启后恢复，任务失败不留下半成品。
3. 验证 A 面查询和永久连通脉络完全不包含临时节点与候选来源连接。
4. Playwright 证明回答完成后当前页面不跳转、不弹窗，只有 B 面总数正确变化；关闭/重开应用后数量一致。

**验证级别：** 四级，因为涉及模型任务、持久化、恢复与跨端入口。

**退出标准：** 合格新认识只进入 B 面，未达门槛不建节点，任何自动路径都不能写入永久融合成果。

## NS-08：完成 B 面审查、修改、搜索与删除

### 用户结果与目的

用户能在不污染 A 面的独立审查状态中阅读全部临时融合节点，查看来源证据、继续对话、明确修改草案、搜索定位并安全删除。

### 后端子任务

- 提供临时节点列表与按临时节点搜索、完整草案读取、对话、明确修改、版本变化、撤销、局部重新核验和确认资格查询。
- 只有明确修改意图才生成新草案版本；询问、讨论或意图不明时只回答或追问。
- 语气/排版变化不改变核验；核心判断、来源或证据变化只重新核验受影响判断，核验未完成或证据异常时禁止确认。
- 提供按当前完整搜索结果选择、单独/批量删除、只读预览和清空整个 B 面的保护契约；删除只影响所选临时节点及候选来源连接，不进回收站。
- 搜索为空且选中全部临时节点时，服务端要求额外“删除全部”确认，不能只靠前端判断。

### 前端子任务

- B 面开启后锁定 A 面搜索、筛选、选择、观察中心、沿线探索和专注；A 面仅作为只读来源背景。
- B 面搜索复用 A 面搜索样式与定位体验，数据范围只包含临时节点；集中列表支持定位、选择、全选、准确数量、单独和批量删除。
- 删除确认中可从标题打开完整最新草案、来源和证据状态的只读预览；关闭预览后保留搜索、选择和滚动现场。
- 只有清空整个 B 面时要求用户输入“删除全部”；普通批量删除经过一次内容与范围复核。
- 原地展开证据不退出 B 面；打开来源正文退出 B 面进入 A 面节点，返回后恢复临时节点、视口、搜索条件和列表位置。
- 草案对话、定向修改、版本变化、撤销和核验状态使用明确动词与结果文案，询问不伪装成已经修改。

### 执行、测试与验收

1. 后端测试搜索范围、完整结果全选、分页/未渲染条目、并发删除、重复删除、清空保护和事务回滚。
2. 组件测试 A 面控件锁定、只读预览、选择数量、确认文案、修改与询问的不同结果。
3. Playwright 覆盖 B 面打开/关闭不重排、搜索、来源往返恢复、草案修改、撤销、证据异常禁止确认、普通批量删除和清空全部。
4. 验证删除不会修改 A 面节点、永久边或项目，控制台与网络无意外请求。

**验证级别：** 四级，因为包含批量删除、跨端状态与完整用户路径。

**退出标准：** B 面可独立完成浏览、修改和整理；A 面始终只读且空间稳定；高风险清空保护由前后端共同保证。

## NS-09：完成原位确认、固定成果与来源生命周期

### 用户结果与目的

用户确认当前已核验草案后，同一节点在原位置进入 A 面并成为固定正式融合成果；随后可以正常对话、生长和管理会话，但不会改写已确认正文、直接来源或证据对应。

### 后端子任务

- 在单一事务中原位提升同一节点：固定被确认草案版本、最终采用来源和证据对应，把核验通过的候选来源连接转为正式融合来源；不重新生成、不复制节点。
- 正式融合节点成为独立会话根节点。全部直接来源同项目时默认沿用该项目，跨项目时默认未分类；确认输入允许用户修改默认项目。
- 确认后拒绝融合正文修订、来源替换和证据重绑；后续对话和显式生长写入普通后续内容，不反向改变固定成果。
- 来源进入回收站时保留可恢复占位并标记“来源暂不可用”；恢复后自动恢复；永久删除后不保留原文，改为“来源已删除/来源不完整”。
- 永久删除来源前返回直接受影响融合节点与更深来源链数量，不自动扩大删除；进一步删除融合成果必须进入独立审查并明确选择，还要提示其自身后代。
- 确认、删除和恢复都具备幂等、事务回滚和服务重启恢复测试。

### 前端子任务

- 确认前完整展示当前草案版本、实际采用来源、证据状态和默认项目；有任何未核验或不可用关键证据时禁用确认并说明原因。
- 确认成功后关闭 B 面，回到 A 面并聚焦同一节点；身份、地址、坐标、缩放和平移保持，且不自动跳到下一个候选。
- 正式融合使用圆环身份，选中后突出全部直接来源；点击具体判断能回到一个或多个来源语义范围。
- 正式融合页面不提供修改已确认成果的入口；普通对话、生长、项目、归档和删除使用已有会话能力并清楚区分于固定成果。
- 来源回收站、恢复、永久删除和来源不完整都有非颜色文字/形状说明；删除确认只默认删除当前来源。

### 执行、测试与验收

1. 先写原位提升事务测试，覆盖重复确认、并发确认、部分来源失效、项目默认和中途失败。
2. 写固定成果不变量测试：后续对话、来源新增内容、项目移动、归档和重启都不能改变已确认正文、来源集合与证据版本。
3. 写删除影响集成测试，证明来源回收站可恢复、永久删除不留原文、不级联删除融合成果。
4. Playwright 覆盖确认前核验、原位确认、A 面专注、来源返回、后续生长、来源删除告知和独立审查入口。

**验证级别：** 四级，因为涉及不可逆确认、独立会话、删除与证据完整性。

**退出标准：** 同一节点完成 B→A 原位提升且成果固定；来源生命周期诚实可见；没有自动改写、自动级联删除或第三种永久关系。

## NS-10：规模验证、全链路验收与旧路径收口

### 用户结果与目的

本阶段不再增加产品功能，而是证明整套节点系统在真实使用路径、代表性规模和异常情况下可靠，并删除会导致两套图谱或旧语义复活的迁移残留。

### 后端子任务

- 使用 NS-00 的小、中、大代表性数据集测量全局查询、搜索、连通计算、候选扫描、B 面列表、确认和删除影响分析；记录首轮基线与优化后结果。
- 根据测量决定是否需要索引、缓存、按需读取或内部裁剪；任何优化都不能改变全局范围和完整连通语义。若必须引入聚合或渐进加载产品行为，另行强提醒并形成独立决定。
- 删除不再被调用的会话图查询、`maxDepth` 用户语义、`semantic-related` 写入、旧确认式融合和直接永久自动融合路径；保留必要的单向旧路由跳转。
- 删除旧融合候选把词法弱标记检测作为必需或回退概念源的产品级耦合；弱标记只保留为独立的内联提示与生长入口。
- 检查认证、本机来源限制、凭证与日志脱敏、事务、恢复和数据删除边界。

### 前端子任务

- 删除旧地图模式切换、旧三类永久边说明、“保留关系”、直接永久自动融合和依赖会话 ID 的新代码路径。
- 完成浅/深主题、320/1024/1440、键盘、读屏名称、减少动态效果、缩放平移、搜索、A/B 切换、专注、来源返回和删除流程的最终视觉检查。
- 更新受影响的视觉回归基线并逐张检查，保证布局稳定、焦点清楚、非连通置灰不吞掉归档/证据/键盘状态。
- 生成普通用户可执行的节点系统验收手册；Chrome DevTools MCP 人类拟真测试只在用户主动说出规定触发词后执行。

### 执行、测试与验收

1. 运行全量构建、全量测试、项目检查和全部相关 Playwright；真实模型验收只使用本机已保存且可用的配置，并与确定性自动化分开记录。
2. 逐场景验证：全局旧根节点、节点内多命中、跨项目桥接、专注混合关系、全部关系关闭、提示忽略、自动创建 B 面、来源往返、批量删除、原位确认、固定成果、来源回收站/恢复/永久删除。
3. 关闭或模拟弱标记检测失败，验证全局地图、搜索、专注、关联提示、B 面融合与正式融合主路径仍然可用；再验证弱标记成功生长的子节点与其他生长入口使用相同父子关系进入全局地图。
4. 检查所有相关页面控制台错误与警告为零，网络请求方法/路径/状态正确，没有不该发生的外部请求或敏感信息泄漏。
5. 对照源码、测试和真实界面更新 `docs/PROJECT.md` 四态能力与证据；不得仅因构建通过就标为已实现。
6. 清理阶段残留、关闭全部完成的子 Issue；父规格只有在所有子 Issue 和证据一致后关闭。

**验证级别：** 四级发布门。

**退出标准：** 所有目标场景通过，旧用户可见语义和双路径已收口，PROJECT、ADR、CONTEXT、验收文档、源码、自动化与实际界面给出同一个答案。若用户尚未主动触发人类拟真测试，必须明确记录“未执行，按规则不属于单阶段完成条件”。

## 6. 测试与验收总矩阵

| 维度 | 最低覆盖 | 判定标准 |
| --- | --- | --- |
| 领域契约 | 两种永久关系、提示、临时/正式融合、候选/正式来源、固定成果 | 非法状态无法写入；提示不能变永久边；确认后不变量不可改 |
| 图算法 | 无边、链、树、环、混合关系、多分量、关系全关、桥接 | 服务端统一分类；无深度截断；方向与可达性分离 |
| 持久化 | 创建、更新、确认、删除、事务失败、重复请求、重启 | 无半成品、无重复、恢复后结果一致、删除不越界 |
| API | 成功、空、404、409、认证过期、证据失效、网络结果不确定 | 状态码与错误可行动；客户端最终查询可恢复真实结果 |
| 组件 | 所有视觉状态、操作禁用、焦点、文案和模式隔离 | 不出现假操作；颜色/动画不是唯一语义；布局不因状态样式位移 |

| 视觉回归 | A 面全局、专注、全灰背景、混合关系、B 面、证据异常 | 只更新受影响基线；逐张审阅；节点选择前后坐标稳定 |
| 控制台与网络 | 每条用户可见 Playwright 路径 | 控制台错误和警告为零；请求符合预期；无额外外部调用 |
| 安全与隐私 | 本机鉴权、模型凭证、运行记录、来源与删除 | API Key、认证头、Cookie、会话令牌不进入 UI、日志或提交 |
| 人工验收说明 | 每步一个主要动作，紧跟肉眼可见预期与停止条件 | 普通用户无需理解代码即可执行；准备、隐私、记录、清理完整 |

## 7. 每阶段人工验收脚本格式

每个用户可见阶段都要随 Issue 附一份短脚本，但默认只由开发者通过普通浏览器/Playwright验证，不等同于用户触发的 Chrome DevTools MCP 人类拟真测试。

1. **目标**：一至三句话说明本阶段要证明的用户结果。
2. **准备**：页面、样本、模型/联网要求、预计时间、会保存什么和起始界面特征。
3. **隐私**：使用预制样本；不得在记录中暴露私人正文、账号、API Key 或令牌。
4. **步骤**：每一步只做一个动作，使用界面真实名称。
5. **预期**：紧跟可见结果，包括位置、文字、明暗、可用操作和不应发生的跳转/请求。
6. **结果**：只允许“符合说明 / 与说明不一致 / 无法继续”。
7. **停止条件**：意外凭证要求、删除范围不明、界面明显不符、应用无响应或同一错误连续两次。
8. **清理**：删除测试节点/候选，恢复筛选、主题、模型和项目设置。

## 9. 计划使用方式

- **开始实施**：读取 `docs/PROJECT.md` 与父规格 #59，领取当前唯一无 blocker 的 T01（#60）；不得跳过依赖直接制作最终画布。
- **阶段交付**：按阶段完成后端、前端、自动化和验收证据，再提交、更新四态判断并关闭对应 Issue。
- **发现冲突**：先按权威顺序核对 `PROJECT.md → ADR → CONTEXT.md → 专题基线`；不能靠改标题或换词掩盖冲突。
- **发现新边界**：立即暂停，用强提醒单独请用户确认；确认前不得加入任务、实现或验收。
- **最终发布**：只有 NS-00 至 NS-10 全部完成、旧路径收口且证据一致，父规格才可关闭，节点系统总体能力才可评估为“已实现并验证”。
